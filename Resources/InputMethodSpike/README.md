# KeyHue 입력기 (실험적)

입력기는 **KeyHue.app에 포함**됩니다. KeyHue에서 설치·업데이트·제거하며 별도 입력기 ZIP은 없습니다. 두벌식 한글과 QWERTY 영문 입력, 한/영을 잘못 놓고 친 단어 고침을 실험하는 단계입니다. 한자 변환은 아직 제공하지 않습니다. 현재 결정은 [ADR 0051](../../docs/adr/0051-single-app-distribution-and-managed-input-method.md), 검증 범위는 [실험 기록](../../docs/INPUT_METHOD_SPIKE.md)을 참고하세요.

## 설치하고 사용하기

1. 조합 중인 글자를 먼저 확정하고 KeyHue를 실행합니다.
2. **설정 › 입력기**에서 **입력기 설치 및 사용…**을 누릅니다. 메뉴의 **KeyHue 입력기 ▸ 입력기 설치 및 사용…**으로도 시작할 수 있습니다. 상태 줄이 지금 상태(설치 안 됨 · 시스템 설정에서 두 모드를 추가하세요 · 사용 중 등)와 다음에 누를 버튼 하나를 보여 줍니다.
3. 모드 유지에 필요한 입력 모니터링 안내를 확인하고 권한을 허용합니다. 거부했다면 설치 후에도 권한 필요가 표시됩니다. **시스템 설정 › 개인정보 보호 및 보안 › 입력 모니터링**에서 KeyHue를 허용하세요.
4. KeyHue가 ABC로 전환하고 내장 서비스를 사용자 입력기 폴더로 복사한 뒤 서명을 확인하고 macOS에 등록합니다. 부모 입력기와 한글/영문 모드를 활성화하거나 입력 소스 목록을 편집하지 않습니다([ADR 0055](../../docs/adr/0055-users-add-input-sources-manually.md)). 두 모드가 이미 추가돼 사용 가능하면 연동과 한/영 모드 유지가 켜지고 한글 모드가 선택됩니다.
5. 그렇지 않으면 설치 완료 안내가 표시됩니다. **입력 소스 설정 열기** → 시스템 설정 › 키보드 › 텍스트 입력 › 편집 › **+**에서 한국어 아래의 **KeyHue 실험 – 두벌식**과 영어 아래의 **KeyHue 실험 – 영문**을 모두 직접 추가하세요. macOS가 새 입력기 등록에 대한 알림을 표시하면 허용해야 합니다. KeyHue는 이 시스템 허용을 대신 누를 수 없습니다. 두 mode가 실제 사용 가능 상태인 설치본에서 사용을 다시 눌러도 등록을 반복하지 않습니다. 사용 요청은 유지되며 두 mode가 켜지면 연동이 자동으로 시작됩니다. 사용 옵션을 다시 켤 필요는 없습니다. 최소 macOS 13 전체에서 이 흐름을 검증한 것은 아닙니다.

설치 위치는 `~/Library/Input Methods/KeyHueInputMethodSpike.app`입니다. 기존 등록과 호환되도록 내부 이름과 ID는 유지합니다. 관리자 권한은 필요하지 않습니다. 내장 원본은 복사한 뒤에도 남습니다. 메뉴바 입력 소스는 **가 / A**, 입력 소스 추가 화면의 입력기 항목은 카멜레온으로 구분합니다. 이전 아이콘이 캐시에 남아 있다면 로그아웃·로그인 후 확인하세요.

문제가 생기면 `~/Library/Logs/KeyHue/KeyHue.log`에서 설치·등록·모드 선택 상태를, `~/Library/Logs/KeyHue/KeyHueInputMethod.log`에서 IMK 서버와 입력 세션 상태를 확인하세요. 입력 글자와 키 코드는 기록하지 않습니다.

## 조합과 삭제

- 한글은 현재 음절만 밑줄로 표시하고 앞 음절은 확정합니다. 받침 이동과 겹모음/겹받침 분리도 반영합니다.
- 영문은 조합하지 않고 친 글자를 바로 입력합니다(밑줄 없음). 그래서 터미널에서 `ls` 뒤 Return을 한 번만 눌러도 명령이 실행됩니다(ADR 0081). 대신 macOS 자동 대문자가 문장 첫 단어에 적용됩니다. 자동 고침은 친 키로 이를 알아보지만 단축키 고침은 화면 글자를 읽으므로, 키보드 › 텍스트 입력 › 편집…에서 자동 대문자를 끄는 것을 권장합니다.
- Backspace는 현재 조합의 키를 취소합니다. 조합이 없으면 앱의 일반 삭제에 맡깁니다. 이미 확정한 앞 글자를 다시 조합하지 않습니다.
- 공백·기호·확정 요청·단축키·모드 변경 시 남은 조합을 처리하고 경계/앱 동작은 한 번 전달합니다. 실제 밑줄 모양·확정·삭제는 앱별로 확인해야 합니다.
- 키 처리 직전에 현재 시스템 입력 모드를 확인합니다. 모드 변경 콜백이 생략돼도 한글로 돌아온 첫 키부터 한글 세션으로 맞춥니다(ADR 0050).

## 단어 고침

- 한/영을 잘못 놓고 친 글자를 단축키(기본 **⌥↩**)로 고칩니다. 선택한 글자를, 선택이 없으면 커서 바로 앞 단어를 반대 배열로 바꾸고(`dkssud` → 안녕, `ㅗ디ㅣㅐ` → hello) 입력 모드도 바꿉니다. 바로 한 번 더 누르면 되돌립니다([ADR 0068](../../docs/adr/0068-fix-words-with-a-shortcut.md)).
- **설정 › 입력기 › 단어 고침**에서 끄기·단축키로·단축키와 Space에서 자동으로 중에 고르고, 단축키와 고치지 않는 앱을 정합니다. 자동은 영문으로 친 한글 단어를 판정기가 실수로 볼 때 Space에서 고치며, 바로 Delete를 누르면 되돌립니다([ADR 0064](../../docs/adr/0064-correction-modes-off-manual-automatic.md)).
- 터미널은 앱에서 글자를 바꿀 수 없어 방금 친 단어를 Delete 키로 지우고 고친 글자를 넣습니다. 이 키는 KeyHue가 보내므로 KeyHue가 실행 중이어야 하고, **시스템 설정 › 개인정보 보호 및 보안 › 손쉬운 사용**에서 KeyHue를 허용해야 합니다. 입력기 자체에는 권한이 필요 없습니다([ADR 0067](../../docs/adr/0067-bidirectional-correction-and-terminals.md), [0073](../../docs/adr/0073-utility-posts-terminal-keys-for-the-input-method.md)).
- 비밀번호 칸은 바꾸지 않습니다. 고치지 못한 앱은 설정에 표시되고 제외 목록에 넣을 수 있습니다([ADR 0065](../../docs/adr/0065-correct-all-apps-with-feedback.md)).
- 고칠 단어는 입력기 메모리에만 둡니다. 자동 고침의 **되돌린 고침 기록**(기본 꺼짐)을 켠 경우에만 되돌린 고침을 이 Mac에 최근 50개까지 저장하고, 끄면 지웁니다.

## KeyHue 유틸리티와 연동 테스트

연동이 켜져 있고 두 모드가 사용 가능하면 기본 소스의 자동/ABC와 기억한 ABC를 KeyHue 영문으로, 기본 소스나 기억에 남은 시스템 두벌식을 KeyHue 두벌식으로 해석합니다. 연동이 꺼졌거나 모드가 하나라도 없으면 기억·기본값의 KeyHue 두벌식·영문을 켜져 있는 시스템 두벌식·ABC로 읽습니다. 원래 기본값은 바꾸지 않습니다. 사용할 수 없거나 선택 실패 시 기존 소스 정책으로 돌아가며 이때 KeyHue 모드는 다시 고르지 않습니다. 다른 언어와 명시적으로 고른 다른 기본 소스는 보존합니다.

**관리 › KeyHue 한/영 모드 유지**는 입력 소스 변경을 관찰하므로 ⌘Space·Caps Lock·Control Space·Fn·메뉴 등 전환 키를 따로 설정하지 않습니다. KeyHue 모드에서 시스템 ABC나 시스템 두벌식으로 바뀌면 반대쪽 KeyHue 모드로 연결하고, 연동 중 두 소스는 회색으로 표시합니다. 메뉴에서 직접 골라도 연결될 수 있습니다. 잠금 화면이나 비밀번호 칸이 ABC를 고른 뒤에는 두 KeyHue 모드를 ABC 앞으로 되돌려 ⌘Space가 바로 오가게 하고, 해제 뒤에도 ABC가 남아 있으면 이전 KeyHue 모드(모르면 영문)로 돌립니다(ADR 0082). 다른 언어로의 전환은 유지합니다. 권한 미허용이면 모드 유지는 동작하지 않습니다. KeyHue가 종료되면 기본 입력은 남고 자동 연동은 중단됩니다.

입력 모니터링은 선택 알림보다 입력이 먼저 시작되면 대기 중인 전환을 취소하기 위한 listen-only 관찰입니다. 입력을 재전송하거나 고쳐 쓰지 않습니다. 아주 빠른 전환·첫 키와 macOS 알림 순서의 호환성은 여전히 실험 대상입니다.

잠시 멈추려면 **관리 › 연동 끄고 ABC로 전환**을 누르세요. 파일은 남고, 상태 줄 아래의 **입력기 사용 시작…**으로 다시 켤 수 있습니다. 전환 실패 시 macOS 입력 메뉴에서 사용 가능한 시스템 소스를 직접 고르세요.

| 확인할 상황 | 기대 결과 |
|---|---|
| 최초 사용 옵션 ON | 설치·등록 후 시스템 설정에서 두 모드 추가 안내, 추가하면 옵션 재조작 없이 연동·한글 선택 |
| ⌘Space/Caps Lock/Control Space/Fn/메뉴로 한↔영 | 사용 중인 방식으로 확인, 표시와 첫 입력 문자가 일치 |
| 한글 → 영문 → 한글 직후 입력 | 한글 조합, 원문·조합 유실 없음 |
| 여러 음절 / `hello world again` | 한글은 현재 음절만 밑줄, 영문은 밑줄 없음, 공백·문자 중복/유실 없음 |
| 터미널 영문 모드 `ls` + Return | Return 한 번으로 실행 |
| Backspace·Shift·기호·Return·Tab·단축키 | 조합 취소와 앱 동작 한 번, 기존 문서 유지 |
| 앱/창/필드 변경, 다른 언어 선택 | 기본값·복원 정책과 다른 언어 선택 보존 |
| 권한 OFF, 연동 OFF, ABC 복귀 | 권한 안내·자동 연결 중단, 시스템 입력 가능 |
| 업데이트/제거 중 재선택·종료 실패 | 중단·오류 안내, 이전 설치본 보존 |

TextEdit, Notes, Safari/Chrome 필드, VS Code/Electron, Terminal에서 OS·앱 버전·모드·재현 절차와 결과를 직접 기록하세요. 입력 내용은 자동 수집·로그·저장·전송하지 않습니다. 실제 앱 호환성이 확인되기 전에는 기본 입력기 안정화 완료로 표시하지 않습니다.

## 업데이트와 제거

KeyHue를 새 앱으로 교체한 뒤 설정 › 입력기(또는 메뉴의 KeyHue 입력기)에서 상태 줄 아래의 **입력기 업데이트 및 사용…** 버튼을 누르세요. 같은 버전 개발 재빌드도 내용이 달라지면 업데이트가 표시됩니다. 앱 교체만으로 실행 중인 입력기를 자동 교체하지 않습니다. 검사·정상 종료·복사·최종 검증·등록 중 실패하면 이전 설치본을 복구합니다. 종료되지 않으면 강제 종료하지 않고 재로그인 후 다시 시도하도록 안내합니다.

입력기만 제거하려면 먼저 시스템 설정 › 키보드 › 텍스트 입력 › 편집에서 KeyHue 두 모드를 제거한 뒤 설정 › 입력기의 **관리 › 입력기 제거**(또는 메뉴의 **KeyHue 입력기 ▸ 입력기 제거**)를 선택하세요. 모드가 남아 있으면 파일이 이미 없어도 모드 제거를 안내하는 오류를 보이고 파일을 유지합니다. 연동 OFF·ABC 전환 후 서비스를 정지하고 설치본만 삭제하며 입력 소스 설정은 편집하지 않습니다. macOS 26에서는 완료 후 KeyHue가 자동 재시작하며 macOS 재로그인은 필요하지 않습니다. KeyHue 앱과 설정, 다른 입력기, 내장 원본은 남습니다. 시스템 메뉴에 예전 항목이 남으면 로그아웃·로그인 후 확인하세요. KeyHue 앱까지 삭제할 때는 **입력기 제거 → KeyHue 종료 → Applications의 KeyHue.app 삭제** 순서로 진행하세요.

## 개발 빌드와 검증

```bash
scripts/build-app.sh          # 내장 입력기를 포함한 build/KeyHue.app
scripts/check-bundle.sh       # 부모/서비스 버전·메타데이터·서명·self-check
scripts/install.sh --no-build # KeyHue 설치·실행 후 앱에서 입력기 사용 선택
scripts/package.sh           # 하나의 universal KeyHue ZIP
scripts/verify.sh            # 사용자 입력 소스를 변경하지 않는 자동 검사
```

버전은 루트 `VERSION` 하나입니다. `scripts/app-config.sh`가 단일 앱의 메타데이터를 공유합니다. 별도 입력기/유틸리티 대상 인자는 제거했으며 `scripts/install.sh`는 KeyHue 앱만 설치합니다. 입력기 파일은 앱의 설치/제거 기능에서 관리하고 입력 소스 추가·제거는 사용자가 시스템 설정에서 합니다. 결정은 [ADR 0052](../../docs/adr/0052-input-method-activation-and-single-app-scripts.md)·[ADR 0055](../../docs/adr/0055-users-add-input-sources-manually.md)를 따릅니다. 코어와 IMK 어댑터는 `Tools/InputMethodSpike/`에 있고 self-check는 서버를 시작하거나 입력 소스를 선택하지 않습니다.
