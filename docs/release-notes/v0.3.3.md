### Stability: crashes and freezes fixed

- Changing the app language in Settings no longer makes KeyHue quit. Rebuilding the menu bar menu for the new language crashed.
- KeyHue and the KeyHue input method no longer quit when the other side stops waiting during a terminal word fix. If the input method quit, typing in every app was interrupted.
- Installing, updating or removing the input method no longer freezes KeyHue for several seconds. The checks it runs now happen in the background.
- A word fix in a terminal no longer pauses typing in other apps while the input method waits for KeyHue.

### Switching input sources

- **Restore Last Input Source**: when macOS restored a document's own input source right after you switched apps, KeyHue remembered that instead of what you last used there. It now restores what you used.
- Window switches are no longer delayed while a KeyHue menu or alert is open.
- **Keep KeyHue Korean/English Modes**: if you picked ABC yourself while this option was off, turning it on later no longer reorders the modes as if the lock screen had picked it.

### Word fixing (KeyHue input method)

- In a terminal, pressing Backspace while a syllable was still being composed and then the fix shortcut could leave the wrong text (for example `가rks`). The fix now matches what the terminal shows.
- If the Backspace keys of a terminal fix never arrive, the input mode goes back to the one you were typing in and KeyHue says the word was kept, instead of leaving only the mode changed.
- Automatic fixing: a Backspace right after a fix the app refused no longer marks the word as undone, so the word is still fixed the next time.
- Automatic fixing treats Shift+Space and Shift+Backspace the same way as typing does.
- Removing an entry from **Undone Fixes** while the input method records a new one no longer loses either of them.

### Settings

- If you cancel a permission request, the switch you turned on goes back to off instead of looking on.
- The Settings window stays responsive while you drag a color or the bar sliders.
- When KeyHue can't check the current input source before installing or removing the input method, it now says so, instead of asking you to switch input sources.
- Removing the input method while KeyHue Korean and English are still added in System Settings now says plainly that KeyHue can't remove those modes for you, and the alert's **Open Input Source Settings** button takes you there.
- On macOS 26, System Settings sometimes keeps a mode you removed, where neither you nor KeyHue can see or remove it, so the input method could never be removed. If System Settings no longer lists the modes, choose **Remove Anyway** in the alert: KeyHue turns off its own entries and removes the input method. If macOS kept a mode, KeyHue tells you: it does nothing without the input method, and the manual's [Removing what macOS keeps](https://sejoung.github.io/KeyHue/manual.html#remove-leftover-modes) explains how to remove it completely.
- Installing the input method again after such a removal brings back the mode macOS kept as already added. The installation notice now asks only for the mode that is still missing.
- Error alerts for the input method and Launch at Login now show what went wrong and what to do. Before, only the title appeared.
- Records saved by a newer KeyHue (failed fixes, undone fixes) are no longer erased when you go back to this version. Entries it can't read are skipped.

### Privacy and diagnostics

- The local log now records only the number of entries in any list of words in your settings, never the words.
- A failed update check now writes its reason to the local log.

### 안정성: 크래시와 멈춤 수정

- 설정에서 앱 언어를 바꿔도 KeyHue가 종료되지 않습니다. 새 언어로 메뉴바 메뉴를 다시 만들다 크래시가 났습니다.
- 터미널에서 단어를 고치는 도중 상대가 응답을 기다리지 않고 연결을 끊어도 KeyHue와 KeyHue 입력기가 종료되지 않습니다. 입력기가 종료되면 모든 앱의 입력이 끊겼습니다.
- 입력기를 설치·업데이트·제거할 때 KeyHue가 몇 초씩 멈추지 않습니다. 이때 하는 확인 작업을 백그라운드에서 합니다.
- 터미널에서 단어를 고칠 때, 입력기가 KeyHue의 응답을 기다리는 동안 다른 앱의 입력이 멈추지 않습니다.

### 입력 소스 전환

- **마지막 입력 소스로 복원**: 앱을 바꾼 직후 macOS가 문서별 입력 소스를 되살리면, KeyHue가 사용자가 그 앱에서 마지막으로 쓴 입력 소스 대신 그것을 기억했습니다. 이제 사용자가 쓴 입력 소스로 복원합니다.
- KeyHue 메뉴나 알림창이 열려 있는 동안 창 전환이 늦게 반영되지 않습니다.
- **KeyHue 한/영 모드 유지**: 이 옵션이 꺼져 있을 때 직접 ABC를 고른 것을, 나중에 옵션을 켰을 때 잠금 화면이 고른 것처럼 보고 모드 순서를 바꾸던 문제를 고쳤습니다.

### 단어 고침 (KeyHue 입력기)

- 터미널에서 음절을 조합하는 중에 Backspace를 친 뒤 고침 단축키를 누르면 엉뚱한 글자가 남을 수 있었습니다(예: `가rks`). 이제 터미널에 보이는 대로 고칩니다.
- 터미널 고침의 Backspace 키가 하나도 전달되지 않으면, 입력 모드만 바뀐 채로 남지 않고 원래 입력 모드로 돌아가며 단어를 그대로 두었다고 알립니다.
- 자동 고침: 앱이 고침을 받아들이지 않은 직후 Backspace를 쳐도 그 단어를 "되돌린 단어"로 기억하지 않습니다. 다음에도 그 단어를 고칩니다.
- 자동 고침이 Shift+Space와 Shift+Backspace를 일반 입력과 같은 규칙으로 처리합니다.
- **되돌린 고침**에서 항목을 지우는 순간 입력기가 새 항목을 기록해도, 둘 중 어느 쪽도 사라지지 않습니다.

### 설정

- 권한 요청에서 취소하면 켠 스위치가 켜진 것처럼 보이지 않고 꺼진 상태로 돌아갑니다.
- 색이나 막대 슬라이더를 끄는 동안에도 설정 창이 느려지지 않습니다.
- 입력기를 설치·제거하기 전에 현재 입력 소스를 확인하지 못하면, 입력 소스를 바꾸라고 하지 않고 확인하지 못했다고 알립니다.
- 시스템 설정에 KeyHue 두벌식·영문 모드가 남아 있는 채로 입력기를 제거하면, KeyHue가 이 모드를 직접 지울 수 없다고 분명히 알립니다. 알림의 **입력 소스 설정 열기** 버튼으로 바로 갈 수 있습니다.
- macOS 26에서 시스템 설정이 지운 모드를 남겨 두는 경우가 있습니다. 이 모드는 사용자도 KeyHue도 보거나 지울 수 없어서 입력기를 영영 제거할 수 없었습니다. 시스템 설정에 더 이상 보이지 않는데 안내가 나오면 알림에서 **그래도 제거**를 고르세요. KeyHue가 자기 항목을 끄고 입력기를 제거합니다. macOS가 모드를 남겼으면 KeyHue가 알려 줍니다. 남은 모드는 입력기가 없으면 아무 동작도 하지 않으며, 완전히 지우는 방법은 설명서의 [macOS가 남긴 항목 지우기](https://sejoung.github.io/KeyHue/manual-ko.html#remove-leftover-modes)에 있습니다.
- 이렇게 제거한 뒤 입력기를 다시 설치하면 macOS가 남긴 모드가 이미 추가된 상태로 돌아옵니다. 설치 완료 안내는 이제 아직 없는 모드만 추가하라고 알려 줍니다.
- 입력기와 로그인 시 실행의 오류 알림에 무엇이 잘못됐고 무엇을 하면 되는지가 함께 나옵니다. 이전에는 제목만 보였습니다.
- 더 새 버전의 KeyHue가 저장한 기록(고치지 못한 앱, 되돌린 고침)이 이 버전으로 돌아와도 지워지지 않습니다. 읽을 수 없는 항목만 건너뜁니다.

### 개인정보와 진단

- 로컬 로그에는 설정에 있는 단어 목록의 개수만 남기고, 단어 자체는 남기지 않습니다.
- 업데이트 확인에 실패하면 그 이유를 로컬 로그에 남깁니다.
