### KeyHue input method (experimental, off by default)

KeyHue now includes its own Korean/English input method. KeyHue.app contains it, and nothing changes until you choose to install it.

- **Two modes, one switch.** KeyHue – Korean and KeyHue – English replace 2-Set Korean and ABC. ⌘Space, Caps Lock, Control Space and Fn move between the two KeyHue modes directly. If macOS picks ABC or 2-Set Korean (for example after the lock screen or a password field), KeyHue brings you back to the matching KeyHue mode.
- **Fix a word typed in the wrong mode.** Press ⌥↩ to turn `dkssud` into 안녕 or `ㅗ디ㅣㅐ` into hello. KeyHue converts the selection, or the word before the cursor, and switches the mode. Press ⌥↩ again right away to undo. You can also have words fixed automatically at Space, change the shortcut, and choose apps that are never changed.
- **Terminals.** Return runs a command on the first press in English mode. Word fixing works in terminals too (checked in Ghostty). KeyHue sends the Delete keys, so it needs Accessibility access; the input method itself needs no permission.
- **Privacy.** The input method keeps only the current word in memory. Logs never include typed text, words or key codes.

**To start:** Settings › Input Method › **Install and Use Input Method…**, then add **KeyHue – Korean (Experimental)** and **KeyHue – English (Experimental)** in System Settings › Keyboard › Text Input › Edit › +. If the list looks empty, choose another language once and come back. **Before deleting KeyHue**, remove both modes and choose **Manage › Uninstall Input Method**. See the [manual](https://sejoung.github.io/KeyHue/manual.html#automation) for details and known limits.

### Other changes

- Notes for zsh users: Shift, Option or Ctrl+arrow keys typing `A`–`D` in a terminal, and how to fix it with zsh-shift-select or `bindkey`.
- **Allow Again** no longer removes a permission you have just granted.
- Fixes for setting up the input method from a downloaded copy of KeyHue.

### KeyHue 입력기 (실험적, 기본 꺼짐)

KeyHue에 한글/영문 입력기가 들어갔습니다. KeyHue.app에 포함돼 있고, 직접 설치하기 전에는 아무것도 바뀌지 않습니다.

- **두 모드를 한 번에 전환:** KeyHue 실험 – 두벌식과 KeyHue 실험 – 영문이 시스템 두벌식과 ABC를 대신합니다. ⌘Space·Caps Lock·Control Space·Fn으로 두 KeyHue 모드를 바로 오갑니다. 잠금 화면이나 비밀번호 칸 때문에 macOS가 ABC나 두벌식을 고르면, KeyHue가 짝이 되는 KeyHue 모드로 되돌립니다.
- **잘못 친 단어 고치기:** ⌥↩를 누르면 `dkssud`가 안녕으로, `ㅗ디ㅣㅐ`가 hello로 바뀝니다. 선택한 글자, 선택이 없으면 커서 앞 단어를 바꾸고 모드도 바꿉니다. 바로 한 번 더 누르면 되돌립니다. Space에서 자동으로 고치기, 단축키 변경, 고치지 않을 앱 선택도 할 수 있습니다.
- **터미널:** 영문 모드에서 Return 한 번으로 명령이 실행됩니다. 단어 고침도 터미널에서 됩니다(Ghostty에서 확인). Delete 키는 KeyHue가 보내므로 KeyHue에 손쉬운 사용 권한이 필요하고, 입력기에는 권한이 필요 없습니다.
- **개인정보:** 입력기는 지금 치는 단어만 메모리에 둡니다. 로그에는 입력한 글자·단어·키 코드가 남지 않습니다.

**시작하기:** 설정 › 입력기 › **입력기 설치 및 사용…**을 누른 뒤, 시스템 설정 › 키보드 › 텍스트 입력 › 편집 › +에서 **KeyHue 실험 – 두벌식**과 **KeyHue 실험 – 영문**을 추가하세요. 목록이 비어 보이면 다른 언어를 한 번 눌렀다 돌아오세요. **KeyHue를 지우기 전에는** 두 모드를 먼저 빼고 **관리 › 입력기 제거**를 선택하세요. 자세한 내용과 알려진 한계는 [설명서](https://sejoung.github.io/KeyHue/manual-ko.html#automation)를 보세요.

### 그 밖의 변경

- zsh 사용자 안내: 터미널에서 Shift·Option·Ctrl+방향키가 `A`~`D`를 입력하는 문제와 zsh-shift-select·`bindkey`로 해결하는 방법.
- **다시 허용**이 방금 허용한 권한을 지우지 않습니다.
- 내려받은 KeyHue에서 입력기를 설치할 때의 문제를 고쳤습니다.
