### KeyHue input method: notice when another app's secure input blocks it

- When another app in the background keeps secure input on (for example after a password field or a Touch ID or password prompt in Chrome), macOS doesn't let third-party input methods be used in any app, and ⌘Space only switches between ABC and the macOS 2-Set Korean. KeyHue now shows **Secure Input in 〈app〉** at the bottom of the screen and tells you how to end it: go back to that app or close its password field.
- The notice isn't shown for a password field in the app you're using, where ABC is expected, or on the lock screen. It appears once each time secure input is held, and at most once every 30 seconds.
- Once secure input ends, the next ⌘Space returns to a KeyHue mode. Before, it kept switching between ABC and 2-Set Korean until you switched apps.
- The log now records which app holds secure input (`secure input held by …`).

### Turn off word fixing for the current app from the menu

- If the fix shortcut conflicts with an app such as IntelliJ, choose **Disable Word Fixing in 〈app〉** from the menu while using that app. In excluded apps, shortcut and automatic word fixing are off, and the fix shortcut goes to the app. Choose it again to remove the exclusion.

### KeyHue 입력기: 다른 앱의 보안 입력으로 막히면 알려 줍니다

- 뒤에 있는 다른 앱이 보안 입력을 켠 채로 두면(예: Chrome의 비밀번호 칸이나 Touch ID·암호 확인 뒤), macOS는 어느 앱에서든 서드파티 입력기를 쓰지 못하게 하고 ⌘Space도 ABC와 macOS 두벌식만 오갑니다. 이제 KeyHue가 화면 아래에 **〈앱〉에서 보안 입력 중**이라고 알리고, 그 앱으로 돌아가거나 비밀번호 칸을 닫으면 풀린다고 안내합니다.
- 지금 쓰는 앱의 비밀번호 칸(ABC가 정상)과 잠금 화면에서는 알리지 않습니다. 보안 입력이 잡힐 때마다 한 번, 30초에 한 번까지만 알립니다.
- 보안 입력이 풀린 뒤 첫 ⌘Space에서 KeyHue 모드로 돌아옵니다. 이전에는 다른 앱으로 바꿀 때까지 ABC와 두벌식만 오갔습니다.
- 어느 앱이 보안 입력을 잡았는지 로그에 남깁니다(`secure input held by …`).

### 메뉴에서 지금 쓰는 앱의 단어 고침 끄기

- IntelliJ 같은 앱에서 고침 단축키가 충돌하면, 그 앱을 쓰던 상태에서 메뉴의 **〈앱〉에서 단어 고침 끄기**를 선택하세요. 제외한 앱에서는 단축키 고침과 자동 고침이 꺼지고, 고침 단축키는 앱에 그대로 전달됩니다. 다시 선택하면 제외를 해제합니다.
