# 0042. 잘못된 언어 경고를 치는 중에 한다 (영어 접두사 + 설치된 명령어 이름)

- 상태: Accepted (0041의 판정 시점을 앞당긴다. 단어 끝 판정은 못 잡은 단어를 위해 남긴다)
- 날짜: 2026-10-01

## 맥락
0041은 스페이스·리턴에서 단어 전체로 판정했다. 직접 써 보니 그 시점에는 이미 단어를 다 잘못 친 뒤였다(2026-10-01 피드백: "스페이스나 엔터 시점이면 오타가 이미 났던 경우"). 단어를 치는 중, 처음 몇 타 안에 알려야 손을 멈출 수 있다.

앞부분만으로는 "영어 사전에 있는가"를 볼 수 없어 근거가 적다. 대신 두 방향의 비대칭을 쓴다.

## 결정
- **치는 중 판정**(`MistypeDetector.judgeEarly`, `EarlyMistypeDetection.swift`): 글자 키마다 앞부분으로 판정하고, 한 단어에 한 번만 알린다.
  - 치는 중에 못 잡은 단어는 0041처럼 공백에서 단어 전체로 다시 판정한다.
  - **한글 모드 → 영어:** 다음 세 조건이 모두 맞으면 영어로 본다. 2타부터 본다.
    - 모음이 음절이 되지 못하고 **확정**됐다(he = ㅗㄷ의 ㅗ). 확정은 다음 키가 온 뒤를 뜻하며, 마지막 글자는 아직 바뀔 수 있다.
    - 키가 영어 단어의 앞부분이다. 아ㅏ 같은 오타를 거르는 조건이다.
    - ㅠㅠ 같은 낱자 반복이 아니다.
  - **영문 모드 → 한글:** 다음 조건이 모두 맞으면 한글로 본다. 3타부터 본다.
    - 이 글자로 시작하는 영어 단어나 명령어가 없다.
    - 의미 없는 Shift가 없다.
    - 확정된 음절과 마지막 음절의 초성·중성이 모두 음절이다. 마지막 음절의 받침은 다음 음절로 넘어갈 수 있어서 뺀다.
    - 그 부분의 한국어 점수(끝 경계 없이)가 −2.5 이상이다.
- **영어 접두사의 출처**(`EnglishPrefixIndex.loadWords`): 정렬한 목록에서 이분 탐색한다(모든 접두사 집합은 수백만 개라 만들지 않는다).
  - 시스템 단어 목록 `/usr/share/dict/words`(23만 단어).
  - **설치된 명령어 이름:** `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/local/bin`, `/opt/homebrew/bin` 안의 영문자로만 된 파일 이름(이 Mac에서 1,126개).
    - 사전에 없는 명령어(dirname)를 치는 중에 한글로 잘못 알리던 문제를 줄인다.
    - **단어 하나를 예외로 넣는 대신 이 방법을 골랐다.** 같은 종류의 단어가 계속 나오고, 손으로 목록을 관리하지 않아도 되며, brew로 설치한 도구도 따라간다.
    - 파일 이름만 읽는다. 기능을 켤 때 한 번만 읽는다.
  - 읽지 못하면 치는 중 판정만 끄고 단어 끝 판정은 그대로 한다.
- **메시지:** 치는 중에 알렸으면 그때까지 친 앞부분에 "…"를 붙인다(안…?, he…?). 로그에는 `(while typing)`만 덧붙이고 단어는 남기지 않는다.
- **측정 도구:** `Tests/perf/mistype-eval.sh`가 키를 하나씩 치는 것을 흉내 내 처음 알린 시점을 잰다. 앱과 같은 접두사 출처(`--prefix-words system`)를 쓴다.

## 측정
`Tests/perf/mistype-eval.sh`로 쟀다. 모델과 단어 끝 판정의 기준은 0041과 같다.
- "치는 중": 공백을 누르기 전에 알린 비율이다.
- "남은 타": 알린 뒤에 그 단어를 더 쳤을 타 수의 평균이다.

**영문 모드로 친 한글** (최소 3타, 점수 −2.5)

| 영어 접두사 | 치는 중(뉴스 / 대화체) | 몇 타째 | 남은 타 | 치는 중 오탐 /1000(영어 뉴스 / 위키 / 코드) |
|---|---|---|---|---|
| 사전만 | 88.2% / 79.7% | 3.9 / 3.7 | 4.2 / 3.5 | 0.02 / 0.01 / **1.38** |
| 사전 + 명령어 (채택) | 88.2% / 79.6% | 3.9 / 3.7 | 4.2 / 3.5 | 0.02 / 0.01 / **0.28** |

- 사전만 쓸 때 코드 오탐 24건 중 20건이 `dirname`이었다. 남은 코드 오탐은 workdir, rhs, eof 같은 변수 이름이다.
- 최소 4타로 올리면 알리는 시점이 약 1타 늦어지고, 오탐은 거의 같다.

**한글 모드로 친 영어** (최소 2타)

| | 치는 중(영어 뉴스 / 위키 / 코드) | 몇 타째 | 남은 타 | 치는 중 오탐 /1000(한국어 뉴스 / 대화체) |
|---|---|---|---|---|
| 사전 + 명령어 | 53.9% / 55.2% / 56.9% | 3.0 | 2.4–3.8 | **0.00 / 0.00** |

- 낱자 표현 목록(ㅋㅋ, ㅠㅠ, ㅎㄷㄷ 등 45개)에서는 한 번도 알리지 않았다.
- 치는 중에 못 잡는 나머지는 다음 두 종류이며, 단어 끝에서 잡는다.
  - 자음만 이어지는 단어: test = ㅅㄷㄴㅅ. 초성체와 구분해야 해서 앞부분만으로는 판단할 수 없다.
  - 한글로도 음절이 되는 짧은 단어: to = 새.
- 단어 끝까지 합친 검출과 오탐은 0041과 같다: 영문 모드 97% / 93%, 한글 모드 88%. 치는 중 판정을 더해도 오탐은 늘지 않았다.

## 결과와 한계
- 대부분의 잘못된 단어를 3–4타째에 알린다. 그 뒤에 더 칠 2–4타를 아낀다.
- 치는 중에 알리면 판정이 틀렸을 때 더 거슬린다. 남은 오탐(코드 0.28 /1000)은 사전에도 명령어에도 없는 변수 이름이다.
  - 알렸는데 고치지 않고 넘어간 단어를 예외로 기억하는 방법이 있지만, 그러려면 단어를 저장해야 한다. 개인정보 원칙(0041)과 부딪히므로 직접 써 본 뒤 정한다.
- 명령어 폴더는 고정 목록이다. 셸의 PATH(~/.cargo/bin 등)는 앱이 알 수 없어 넣지 않았다.
- 3타 안에 잡히면 1b(자동 전환)나 고쳐 쓰기의 비용(다시 칠 글자 수)도 작아진다. 다음 단계는 직접 써 본 뒤 정한다.
