# 0065. 단어 고침은 모든 앱을 대상으로 하고, 실패와 오탐은 사용자에게 보여 주고 사용자가 보고하게 한다

상태: Accepted (구현과 단위 테스트, 테스트 앱·TextEdit 실제 검사 완료)

날짜: 2026-10-04

관련: [0064](0064-correction-modes-off-manual-automatic.md), [0041](0041-wrong-language-warning.md)

## 배경

[ADR 0064](0064-correction-modes-off-manual-automatic.md)는 교체를 실제로 확인한 앱(`verifiedApps`, TextEdit)만 고쳤다. 사용자는 특정 앱이 아니라 모든 앱에서 쓰려고 입력기를 설치한다. 원하지 않는 앱은 제외하고 원하지 않으면 끈다. 허용 목록 방식은 이 기대와 맞지 않는다.

모든 앱을 대상으로 하면 두 가지가 생긴다.
- 일부 앱(웹 편집기, Electron 등)은 범위·커서를 부정확하게 알려 주거나 교체를 무시해서 고침이 실패할 수 있다.
- 판정기가 영어 단어나 이름을 한글로 바꾸는 오탐도 생긴다.

이것을 조용히 처리하면 사용자는 이유도, 되돌릴 방법도, 알릴 방법도 없다. 실패한 앱을 실행 중에 자동으로 빼는 방안도 같은 이유로 버렸다. 앱이 나아지려면 실제 오탐이 개발자에게 돌아와야 한다. 다만 오탐에는 사용자가 친 단어가 들어간다.

## 결정

### 대상
- 사용자의 "고치지 않는 앱"이 아닌 모든 앱을 고친다. 끄기면 고치지 않는다. `verifiedApps` 허용 목록은 없앤다.
- 테스트 앱의 고정 모드와 runner의 테스트 전용 값(ADR 0064)은 그대로 둔다.
- 보안 입력 중에는 고치지 않는다.
- 교체 전 확인(원문·커서·조합 상태)과 교체 후 확인은 그대로다. 앱이 범위를 알려 주지 못하면 고치지 않는다.

### 실패: 원문을 지키고, 보여 주고, 사용자가 정한다
- 교체가 거부되거나 결과가 기대와 다르면 그 한 번만 포기한다. 원문이 그대로 남은 경우는 건드리지 않고, 자동 모드의 기존 복구(ADR 0056·0057)는 유지한다. 앱을 자동으로 빼지 않는다.
- 입력기는 앱 ID와 실패 이유(`CorrectionFailure`)만 유틸리티에 알린다(distributed notification). 단어는 보내지 않는다.
- 유틸리티의 처리:
  - 그 앱에서 고치지 못했다는 짧은 메시지를 한/영 알림 자리에 보인다.
  - 같은 앱에서 연속 3번 실패하면 한 번만 "설정에서 이 앱을 제외할 수 있다"고 알린다. 그 앱의 기록을 지우기 전까지는 다시 알리지 않는다.
  - 설정의 "고치지 못한 앱" 목록에 앱, 횟수, 마지막 이유를 보인다. 버튼은 [고치지 않는 앱에 추가] / [기록 지우기(다시 시도)] / [문제 보고]다.
  - 앱 ID와 이유는 입력 내용이 아니므로 유틸리티 설정에 저장한다.

### 오탐: 바로 되돌리기가 신호다
- 고친 직후 Delete로 되돌린 단어는 입력기가 실행되는 동안 다시 고치지 않는다. 메모리에만 두며, 최근 200개까지다.
- 설정의 "되돌린 고침 기록"(기본 꺼짐)을 켜면 되돌린 항목을 이 Mac에만 저장한다. 항목은 영문 원문, 바뀐 한글, 앱, 모드, 시각이며 최근 50개까지다.
  - 입력기가 `~/Library/Application Support/KeyHue/undone-corrections.json`(권한 0600)에 쓴다.
  - 단어는 distributed notification으로 보내지 않는다. 같은 사용자의 다른 앱이 들을 수 있기 때문이다. 알림에는 "바뀌었다"만 담고, 유틸리티가 파일을 읽는다.
  - 옵션을 끄면 파일을 지운다.
- 목록의 항목마다 할 수 있는 일:
  - [이 단어는 고치지 않기]: 사용자 예외 단어(`correctionIgnoredWords`)로 저장한다. 입력기는 이 단어를 고치지 않는다.
  - [보고]
  - [삭제]
- 보고된 단어는 앱에 함께 배포하는 예외 단어 목록(`Resources/Mistype/reported-words.txt`)에 넣는다. 입력기는 이 목록의 단어를 고치지 않는다. 측정 도구는 이 목록을 "보고된 오탐" 영문 말뭉치로 읽어 기준을 바꿀 때마다 회귀를 확인한다.

### 보고
- [문제 보고]와 [보고]는 GitHub 이슈 작성 페이지를 미리 채워 연다. 자동 전송은 하지 않는다.
- 열기 전에 들어갈 내용을 보여 주고, 이슈는 공개된다고 알린다. 사용자는 브라우저에서 내용을 고친 뒤 직접 제출한다.
- 들어가는 내용:
  - 실패: 앱 ID, 이유, 횟수, KeyHue·macOS 버전
  - 오탐: 원문, 바뀐 한글, 앱 ID, 모드, 버전

## 결과
- 사용자는 모든 앱에서 고침을 쓰고, 원하지 않는 앱은 직접 제외하거나 끈다.
- 실패와 오탐이 보이고, 사용자가 다음 행동(제외·다시 시도·예외 단어·보고)을 고른다.
- 단어 저장은 사용자가 옵션을 켠 경우에만 이 Mac에서 한다. 전송은 사용자가 고른 항목만 브라우저에서 한다.
- 일관되게 틀린 값을 알려 주는 앱은 교체 후 확인으로도 실패를 알아채지 못할 수 있다. 이때는 사용자가 바로 Delete로 되돌리고 보고하는 경로가 남는다. 자주 쓰는 앱은 실제로 확인해 [호환성 기록](../INPUT_METHOD_COMPATIBILITY.md)에 남기고, 문제가 있으면 기본 제외 목록에 넣는다. (ADR 0067부터 기본 제외 목록은 비어 있고, 오탐은 배포 예외 단어로 막는다.)

## 구현 (2026-10-04)

테스트를 먼저 작성해 실패를 확인한 뒤 구현했다.

- **대상:** `CorrectionRouting`에서 허용 목록을 없앴다. 제외하지 않은 모든 앱이 사용자 모드를 따른다. `CorrectionRoutingTests`가 고정한다.
- **오탐:**
  - `CorrectionPolicy`는 되돌린 단어를 최근 200개까지 메모리에 두고 다시 고치지 않는다(`alreadyUndone`).
  - 사용자 예외 단어와 배포 예외 단어는 판정기에 묻지 않고 건너뛴다(`ignoredWord`).
  - 배포 예외 단어는 `Resources/Mistype/reported-words.txt`(앱과 입력기 번들)에 있다. 측정 도구가 비어 있지 않을 때 "reported" 영문 말뭉치로 읽는다.
- **설정:**
  - `correctionIgnoredWords`, `recordUndoneCorrections`(기본 꺼짐)를 추가했다.
  - 입력기는 같은 규칙(`InputMethodCorrection.read`, `SettingsStore.bool(from:)`)으로 읽는다.
- **실패:**
  - 자동 엔진(`CorrectionProbe.lastFailure`)은 교체 무시, 한글 전환 미적용, 결과 불일치를 남긴다.
  - 수동 연결부는 마감 시 `CorrectionResultCheck`로 판정한다. 사용자의 다음 키로 인한 취소는 실패로 세지 않는다.
  - 입력기는 앱 ID와 이유만 담은 `…correction-failed` 알림을 보낸다.
- **유틸리티:**
  - `CorrectionFeedbackStore`가 실패 기록(앱·이유, 유틸리티 defaults)과 되돌린 고침 파일을 다룬다.
  - 실패는 한/영 알림 자리의 짧은 메시지로 보인다. 세 번째 실패에서는 제외 제안을 한 번만 하고 그 뒤로는 조용하다.
  - 설정의 "단어 고침" 절에서 다음을 다룬다:
    - 고치지 않을 단어
    - 되돌린 고침 기록 옵션과 그 목록: [이 단어는 고치지 않기]/[보고]/[삭제]/[모두 삭제]
    - 고치지 못한 앱: [제외]/[다시 시도]/[보고]
  - 기록을 끄거나 마지막 항목을 지우면 파일을 삭제한다.
- **보고:** `CorrectionReport`가 GitHub 이슈 작성 주소를 만든다. 유틸리티는 공개된다는 안내와 들어갈 내용을 보여 주고, 사용자가 동의할 때만 브라우저로 연다.
- **기록 파일:** 입력기가 `~/Library/Application Support/KeyHue/undone-corrections.json`에 원자적으로 쓰고 권한을 0600으로 둔다. 폴더 권한은 0700이다. 알림에는 "바뀌었다"만 담는다.

**검사:**
- `scripts/verify.sh`가 통과했다. 테스트 수는 입력기 Core 147, Core 563, 앱 273, 스크립트 115개다.
- 실제 앱 검사 (2026-10-04):
  - 첫 실행에서 테스트 앱 자동 고침과 TextEdit 수동 고침이 실패했다. 두 검사는 되돌린 단어를 다시 쳐서 고쳐지기를 기대했다. 서버 로그의 생략 이유는 `alreadyUndone`이었다. 즉 새 동작이 맞게 작동했고, 테스트의 기대가 틀렸다. 수동 신호 실험도 같은 이유로 두 번째 전환 방법부터 고침이 생략되어 결과가 무의미했다.
  - 고친 내용:
    - 되돌리기 사례마다 다른 단어를 쓴다. 실제 모델로 수동·자동 모두 고쳐지는 단어를 골랐다: `rkatk`, `gksrmf`, `dhsmf`, `tkfkd`, `dlqfur`, `dlqfurrl`.
    - "되돌린 단어는 다시 고치지 않는다"를 실제 앱 검사 사례로 추가했다(테스트 앱 자동, TextEdit 수동). TextEdit 자동에는 이미 있었다.
  - 다시 실행한 결과 (`.artifacts/`):
    - 테스트 앱 자동: 경합·필드 이동·외부 선택을 포함한 전 사례 통과 (`input-method-e2e/20261004-141023/`)
    - 테스트 앱 수동 신호: 네 전환 방법 모두 고침. 되돌리기는 원문을 복원하고 한글 모드를 유지한다. 되돌린 단어와 대조군은 그대로다 (`input-method-e2e/20261004-141053/`)
    - TextEdit 수동: 일곱 사례 통과 (`input-method-textedit/20261004-141131/`)
    - TextEdit 자동: 통과 (`input-method-textedit/20261004-140321/`)
    - TextEdit 회귀(고침 꺼짐): 통과 (`input-method-textedit/20261004-140350/`)
  - 실패 알림, 고치지 못한 앱 목록, 되돌린 고침 파일은 단위 테스트로만 확인했다. 실제 실패를 내는 앱에서의 확인과 Notes·Safari·Chrome 확인은 남아 있다.
