# 0094. 입력기 전환 실패는 일시 중단하고 사용자의 모드 유지 설정은 보존한다

- 상태: Accepted (구현·회귀 테스트, 실제 장시간 재발 여부는 추가 관찰)
- 날짜: 2026-10-21
- 관련: [0071](0071-route-through-the-leaving-mode-and-wait-for-modifier-release.md), [0077](0077-apply-a-new-permission-without-restart.md), [0093](0093-verify-session-repair-target-and-front-client.md)

## 맥락

사용자는 ‘KeyHue 한/영 모드 유지’를 끈 적이 없는데 꺼져 있는 것을 보았다고 했다. 로그에는 10월 19일 17:49:04(Chrome)와 20일 17:50:42(Slack)에 `input method routing suspended` 직후 `routeInputMethodPair: true → false`가 있었다. 두 경우 모두 모드 선택은 성공했지만 3–15ms 뒤 ABC로 되돌아왔다. 20일의 OFF는 21일 09:34에 다시 켤 때까지 유지됐다.

반복 전환 방지 자체는 필요하다. 하지만 `AppDelegate`가 라우터의 실패 콜백에서 저장 설정을 OFF로 바꿔, 일시적인 macOS 전환 실패가 사용자의 선택을 영구 해제했다. 사용자에게 별도 안내도 없었다. 0093의 세션 복구 보완과는 별개의 경로다.

## 결정

- 라우터가 전환 실패·즉시 덮어쓰기를 감지하면 내부 실행 상태만 일시 중단한다. 앱은 이를 로그에 남기고 사용자 설정은 수정하지 않는다. 설정을 끄는 콜백 인자도 앱 시작 API에서 제거한다.
- 중단 중 소스 알림만으로 다시 선택하지 않는다. 시간이 지나도 자동 재시도하지 않는다. 전환을 반복하거나 입력 중 갑자기 언어를 바꾸지 않는다.
- 새 단축키·클릭 또는 앱·창·포커스 등의 기준선 재설정이 있으면 다음 전환을 처리할 수 있게 한다. 재개 자체는 입력 소스를 선택하지 않는다.
- ⌘Space의 Space는 시스템이 소비해 키 감시에 오지 않을 수 있다. 실제 수식 키 변경으로도 재개한다. KeyHue가 복구를 위해 합성한 키는 기존 표식 검사로 제외한다.
- 일반 글자 입력은 중단을 해제하지 않고 기다리던 선택을 취소한다. 사용자가 기능을 껐거나 권한·입력 모드가 없거나 보안 입력 중이면 재개 뒤에도 기존 제한을 따른다.
- 잠금·비밀번호 입력 뒤 우회 소스를 정리하는 선택 실패에도 같은 일시 중단을 적용한다. 이전의 사용자 설정 자동 OFF는 되살리지 않는다.
- 로그에 `temporarily paused`, `preference unchanged`와 재개 조건을 남긴다. 입력 내용은 읽거나 기록하지 않는다.

## 검증

- 실제 발생한 ABC 덮어쓰기, 양방향 모드와 시스템 두벌식 우회, 선택 실패, 알림 반복에도 유한한 선택 횟수.
- 입력 중 재개 금지, 단축키·클릭과 문맥 변경 뒤 재개, 재개만으로 선택하지 않음, 반복 실패마다 한 번만 처리.
- 사용자의 명시적 OFF·보안 입력·모드 제거 제한 유지, 우회 소스 정리 실패의 일시 중단.
- 기존 라우팅·시스템 우회 소스 정리·세션 복구 회귀 검사를 함께 실행한다. 개인 대화 입력창에서는 실패를 강제로 만들거나 문자를 보내지 않는다.
- 라우팅·일시 중단 회귀 검사 34개 통과. 전체 `scripts/verify.sh` 통과: Swift 1,247개, 스크립트 142개, 사이트 34개와 정적 검사·배포 번들·입력기 자체 검사(`.artifacts/verify/20261021-100435/`).
- 설치 앱·내장 입력기·설치 입력기는 모두 0.3.7(150)이며 검증한 실행 파일과 SHA-256이 같다. 서명 검사와 실행 상태 `needsUpdate=false ready=true`를 확인했다. 설치·재실행 전후 저장된 `routeInputMethodPair`는 계속 true다.
- 실제 IMK 검사는 전체 통과로 세지 않는다. 첫 준비(`.artifacts/input-method-e2e/20261021-100549/`)는 ABC가 한글로 되돌아와 업데이트 사전 조건에서 중단됐다. 두 번째(`100627/`)는 입력기 업데이트·반복 설치와 기본 한/영 입력에 성공했으나 조합 표시 검사에서 실패했다. 이 실패는 0093의 초기 검사에서도 나타났으며 이번 실행의 원인은 확정하지 못했다. 재실행(`100705/`)은 기본 한/영 입력에 성공한 뒤 WebStorm으로 포커스가 옮겨져 키 전송을 중단했다.
