# 0036. 문제를 나중에 확인할 수 있게 중요한 이벤트는 통합 로그(notice)와 로그 파일에 남긴다

- 상태: Accepted
- 날짜: 2026-09-30

## 맥락
"로거를 적용해서 필요한 로그를 남기고, 문제가 생겼을 때 그걸 확인할 수 있게 해야 한다"는 요청이 있었다.

창 전환 복원 문제(ADR 0033)를 찾을 때 겪은 일이다.
- 창 전환, 자동 전환 결과, 입력 소스 변경이 `debug` 레벨이었다. 통합 로그의 debug는 디스크에 남지 않아서, 문제가 난 **뒤에는** 아무것도 볼 수 없었다.
- 원인을 보려면 `log stream`을 켜 두고 사용자에게 다시 재현해 달라고 해야 했다. 그마저 파일로 받을 때는 버퍼링 때문에 몇 번 비어 있었다.
- 앱 활성화, 설정 변경, 실행 시점의 버전·권한, AX 붙기 실패는 아예 기록되지 않았다. 원인(KeyHue보다 늦게 실행된 앱)은 결국 tccd의 시스템 로그로 거꾸로 추적했다.
- 로거가 파일마다 따로 만들어져 있었다.

## 결정
- **로거를 하나로 모은다**(`Log`, 앱 레이어). subsystem은 `KeyHue` 그대로 둔다. 성능 점검 스크립트의 `log stream` 조건과 메시지 형식(`caps=… source=…`, `window switched within …`)도 유지한다.
- **레벨을 목적에 맞춘다.**
  - `notice`, `error`: 원인을 좇을 때 필요한 것. 통합 로그(디스크에 남음)와 로그 파일에 함께 쓴다.
  - `debug`: 자주 일어나는 세부 사항. 통합 로그에만 쓴다.
- **로그 파일 `~/Library/Logs/KeyHue/KeyHue.log`를 둔다**(`RotatingLogFile`, Core).
  - 통합 로그는 명령어를 알아야 볼 수 있고, 오래된 기록부터 사라진다. 파일은 사용자가 열어 보거나 문제 신고에 첨부할 수 있다. ~/Library/Logs는 콘솔 앱에도 보인다.
  - 1MB마다 돌려 쓰고 3개까지 보관한다(최대 약 3MB). 앱을 다시 실행하면 이어 쓴다.
  - 쓰기는 전용 직렬 큐에서 한다. 입력 소스 전환 흐름(메인 스레드)을 파일 I/O로 막지 않는다.
  - 설치된 앱(번들 ID `io.github.sejoung.keyhue`)으로 실행될 때만 파일에 쓴다. 테스트와 스크린샷 렌더링이 사용자 로그를 채우지 않게 하기 위해서다.
- **남기는 이벤트**
  - 실행: 버전·빌드, macOS 버전·빌드, 기본값과 다른 설정, 권한(입력 모니터링·손쉬운 사용·macOS 표시 숨김), 맨 앞 앱, 입력 소스
  - 앱 활성화(번들 ID, pid), 창 전환, 입력 소스 변경, 자동 전환 결과(`switched select(…) ok`, `retrying … (overwritten)`, `skipped …`)
  - 손쉬운 사용: 붙기 성공(구독한 알림, 메인 창을 알았는지), 준비 안 됨·재시도, 끝내 포기(`AttachRetrier`의 `onGiveUp`)
  - ESC 감지 시작·중지·시스템에 의한 비활성화, 권한 누락 안내와 사용자의 선택, 설정 변경(`이전 → 새 값`), 깨어남, 종료
- **남기지 않는 것**: 입력한 글자, ESC 외의 키, 창 제목, 텍스트 내용, 사용자가 고른 고치지 않을 단어(개수만, ADR 0083). 앱 번들 ID와 입력 소스 ID는 남는다는 점을 설명서와 README의 개인정보 절에 적는다. 로그는 어디로도 보내지 않는다.
- 메뉴에 **로그 파일 보기**를 둔다. Finder에서 파일을 선택해 보여주고, 아직 없으면 폴더를 연다.
- 성능 점검 스크립트는 테스트하는 동안 쌓인 로그 파일 부분을 결과 폴더에 `keyhue-file.log`로 남긴다(ADR 0035).

## 결과
- 단위 테스트
  - 한 줄 형식(시각·레벨·카테고리·메시지)
  - 폴더를 만들고, 다시 실행해도 이어 쓴다.
  - 크기를 넘으면 돌려 쓰고 최근 3개만 남긴다. 제한보다 긴 한 줄도 버리지 않는다.
  - 기본값과 다른 설정만, 바뀐 설정은 `이전 → 새 값`으로 적는다. 색은 hex로, 값이 없으면 `-`로 적는다.
  - 자동 전환 결과를 짧게 적는다.
  - AX 붙기는 마지막 재시도까지 실패했을 때만 포기로 알린다. 취소·대상 변경은 포기가 아니다.
- 스크립트 테스트: 테스트하는 동안의 로그만 남긴다. 돌려 쓰였으면 새 파일 전체를 남기고, 시작 위치가 없으면 복사하지 않는다.
- 실측: 설치 후 측정용 앱으로 창 전환 점검을 돌렸다.
  - 파일에 `app activated → not ready … will retry → attached → window switched ×2`가 시각과 함께 남았다.
  - `log show`(debug 옵션 없음)로도 창 전환 기록이 조회됐다.
- 실행 로그에서 `front app`이 비어 있는 경우를 확인했다. 실행 직후 KeyHue 자신이 맨 앞이어서였고(Dock 표시), 다음 앱 활성화부터 정상으로 관찰한다. 오해가 없게 로그 문구에 그 사실을 적는다.
