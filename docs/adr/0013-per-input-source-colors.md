# 0013. 한/영 고정 상태를 입력 소스별 색으로 일반화하고, "ABC"를 "기본 입력 소스"로 바꾼다

- 상태: Accepted (ADR 0004의 분류 규칙, ADR 0007의 ABC 전환 대상을 대체)
- 날짜: 2026-09-29

## 맥락
지금까지 KeyHue는 입력 소스를 한글/영문/기타 세 가지로 분류하고 색 3개(초록/파랑/회색)만 썼다. 그런데 "타이핑 전에 어떤 언어로 입력될지 모른다"는 문제는 영어 외 언어를 함께 쓰는 모든 사용자에게 있다. 일본어, 중국어, 러시아어·영어, 그리스어, 아랍어·히브리어 사용자, 그리고 German/US 배열을 섞어 쓰는 개발자도 마찬가지다. 글로벌 앱으로 가려면 판정 규칙을 늘리는 것이 아니라 모델 자체를 바꿔야 한다.

## 결정
### 상태 모델
```swift
enum InputState { case source(InputSourceInfo), capsLock, unknown }
```
- 상태는 "현재 선택된 입력 소스 자체"다. Caps Lock은 여전히 가장 우선한다.
- 입력 소스 ID가 바뀌면 상태가 바뀐다. ABC ↔ German처럼 같은 영문 계열끼리 바꿔도 구분된다.
- 일본어 입력기의 히라가나/가타카나처럼 모드가 나뉘는 경우, macOS가 모드마다 별도 입력 소스 ID로 알려주므로 모드별 색도 자연스럽게 지원된다.

### 색
- `sourceColors: [Input Source ID: 색]`에는 **사용자가 직접 지정한 색만** 둔다. 기본색과 같은 색을 고르면 항목을 지운다.
- 지정하지 않은 입력 소스는 `SourcePalette.defaultColor(for:)`를 쓴다.
  1. 영문 배열(ASCII 입력 가능한 배열, 단 CJK 입력기 제외) → 파랑 하나로 묶는다.
  2. 주요 언어 → 고정 색: 한국어 초록, 일본어 주황, 중국어 보라, 키릴 문자 청록, 그리스어 남색, 아랍어 계열 민트, 히브리어 노랑.
  3. 그 밖의 언어 → 언어 코드의 FNV-1a 해시로 팔레트에서 고른다. Swift `hashValue`는 실행마다 달라지므로 쓰지 않는다.
  4. 빨강은 Caps Lock 전용이라 기본 배정에 쓰지 않는다.
- 한국어 사용자의 첫 실행 경험(한글 초록, ABC 파랑, Caps 빨강)은 이전과 같다.

### 기본 입력 소스 (자동 전환 목표)
- `defaultSourceID: String?`를 둔다. nil이면 자동 선택이다: ABC → U.S. → 첫 영문 keylayout → 첫 영문 배열.
- 지정한 입력 소스가 꺼져 있으면 자동 선택으로 대체한다.
- "이미 목표 상태인가" 판단은 다음과 같다.
  - 자동: 현재 입력 소스가 영문 배열이면 전환하지 않는다. 기존의 "English 상태에서 앱 전환 → 그대로" 동작과 같다.
  - 직접 지정: 정확히 그 입력 소스여야 한다. German 사용자가 ABC 상태여도 German으로 바꾼다.
- 메뉴와 설정 창의 문구는 목표 이름을 넣어 "Switch to ABC on ESC"처럼 표시한다.

### HUD 글자
영문 배열은 `a`, 한국어 `가`, 일본어 `あ`(가타카나 모드는 `ア`), 중국어 `中`, 키릴 `Я`, 그리스어 `α` 등. 표에 없는 언어는 입력 소스 이름의 첫 글자를 쓴다.

## 결과
- 판정 규칙 없이 어떤 언어 조합에서도 동작한다. 색 규칙은 "사용자 지정 > 언어 기본색" 하나뿐이다.
- 앱별 입력 기억(ADR 0009)은 원래 입력 소스 ID로 저장하고 있어서 변경이 없다.
- 출시 전이라 이전 설정 키(`koreanColor`/`englishColor`)는 옮기지 않고 삭제한다.
- **알려진 한계**: 입력 소스를 바꾸지 않고 한 입력기 안에서만 모드를 바꾸는 경우(예: 일부 중국어 입력기의 Shift 중/영 전환)는 macOS가 알려주지 않아 감지할 수 없다. 설정 창에 안내 문구를 둔다.
- 입력 소스가 많아지면 색만으로 구분하기 어렵다. 패턴·두께 차이 같은 색 이외의 구분 수단은 후속 과제다.

## 검토한 대안
- **언어 그룹별 색(한국어, 일본어…)만 지정**: 같은 언어의 모드(히라가나/가타카나)나 배열(ABC/German)을 구분할 수 없다.
- **처음 본 입력 소스에 자동 배정한 색을 저장**: 사용자가 지정한 것과 자동 배정한 것이 섞여, 기본 팔레트를 개선해도 반영되지 않는다(ADR 0014와 같은 문제).
