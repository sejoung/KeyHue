# 0018. MIT 라이선스로 소스를 공개하고, 이름과 아이콘은 라이선스에서 제외한다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락
KeyHue는 입력 모니터링·손쉬운 사용 권한을 요청할 수 있는 앱이다. 사용자 입장에서는 "키보드를 들여다보는 앱"이라 "입력 내용을 기록하지 않는다"는 약속을 믿기 어렵다. 코드를 공개해 그 약속을 직접 확인할 수 있게 하는 것이 가장 강한 근거다. 비슷한 macOS 입력 유틸리티도 대부분 공개돼 있고, 글로벌 출시(ADR 0013, 0016)에서는 번역과 언어별 기본 색에 대한 외부 기여가 품질을 빠르게 올린다.

## 결정
- 소스 코드를 **MIT 라이선스**로 공개한다(`LICENSE`, Copyright (c) 2026 Beni Kim).
  - GPL은 App Store 배포와 충돌할 수 있어 제외했다.
  - Apache-2.0(특허 조항)은 1인 유틸리티에 비해 무겁다고 판단했다.
- **KeyHue라는 이름과 앱 아이콘**(`docs/icon.png`와 이를 바탕으로 생성되는 아이콘)은 MIT 대상에서 제외하고, 수정한 버전을 배포할 때는 다른 이름과 아이콘을 쓰도록 README에 명시한다. LICENSE 파일은 GitHub가 라이선스를 인식할 수 있게 MIT 원문 그대로 둔다.
- 문서 구성
  - `README.md`: 영어. 사용자용(기능, 개인정보와 권한, 설치, 한계, 개발, 릴리즈, 라이선스)
  - `README.ko.md`: 같은 내용의 한국어판. 두 파일은 함께 고친다
  - `docs/SPEC.md`: 기존 한국어 제품 명세(루트 README에서 옮김)
  - `docs/adr/`: 설계 결정 기록. 당분간 한국어로 쓴다
  - `CONTRIBUTING.md`: 영어. 기여 규칙(개인정보 원칙, Core/앱 분리, 번역 규칙, ADR)
- About 창에 저장소 링크(github.com/sejoung/KeyHue)를 표시한다.
- GitHub Actions CI(`.github/workflows/ci.yml`)가 PR과 main/태그 push마다 `scripts/verify.sh`(build + test + bundle)를 macOS 러너에서 실행한다.
- 공개 전 점검
  - git 전체 기록에서 비밀 정보 패턴(API 키, 토큰, 개인 키 등): 없음
  - 커밋 작성자 이메일: 개인 이메일 하나뿐임을 확인했다

## 결과
- 사용자가 개인정보 약속을 코드로 확인할 수 있고, 번역이나 언어 추가 기여를 받을 수 있다.
- 코드는 누구나 재배포할 수 있다. 공식 배포판의 차별점은 이름, 아이콘, Developer ID 서명·공증(ADR 0017)이다.
- 저장소 공개 전환(GitHub 설정)은 저장소 소유자가 직접 한다.
- CI는 GitHub 러너의 Xcode(Swift 6.x)에서 아직 실행해 보지 않았다. 첫 실행 결과로 툴체인 호환성을 확인해야 한다.
