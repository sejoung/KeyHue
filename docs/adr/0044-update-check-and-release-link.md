# 0044. 하루 한 번 업데이트를 확인하고 메뉴에서 알리며, 다운로드·설치는 사용자가 한다

- 상태: Accepted (ADR 0017의 업데이트 범위를 보완)
- 날짜: 2026-10-02

## 맥락
앱 안에서 새 버전을 확인할 방법이 없어 사용자가 웹사이트나 GitHub Releases를 직접 방문해야 했다. 사용자는 업데이트 안내 위치와 자동 설치를 검토한 뒤 **자동 확인 + 메뉴 안내 + 다운로드 페이지 열기**를 선택했다.

현재 배포는 GitHub Releases의 ZIP이고, 앱은 SwiftPM으로 빌드한 뒤 스크립트로 번들을 조립하며 고정 자체 서명 인증서를 사용한다(ADR 0021). Apple Developer ID·공증은 유료 Apple Developer Program에 포함된다. Sparkle은 Developer ID 없이도 도입할 수 있지만, 업데이트 아카이브의 무료 EdDSA 서명과 프레임워크·보조 프로그램 패키징·서명·Hardened Runtime 설정 검증이 추가로 필요하다.

## 결정
- **외부 의존성 없이 읽기 전용 업데이트 확인을 추가한다.** URLSession으로 `https://api.github.com/repos/sejoung/KeyHue/releases/latest`를 인증 없이 조회한다. 토큰·쿠키·분석 도구를 쓰지 않고 입력 내용·앱 활동·로그를 보내지 않는다. GitHub에는 일반적인 HTTPS 접속 정보(IP 주소 등)가 전달된다.
- **자동 확인은 기본 ON, 24시간 간격이다.** 마지막 시도 시각을 UserDefaults에 저장하므로 오류·재실행·wake에도 요청을 반복하지 않는다. 시작과 wake에서 간격을 계산해 한 번 예약하며, 자동 확인을 끄면 예약과 진행 중인 자동 요청을 무효화한다. 수동 확인은 OFF 상태에서도 가능하고 진행 중인 요청은 공유한다. 시계가 뒤로 바뀌면 새 기준으로 확인한다.
- `X.Y.Z`를 정수로 비교한다(`0.10.0 > 0.9.0`). `vX.Y.Z` 형식의 정식 태그와 업로드가 끝난 KeyHue ZIP이 있는 공개 정식 릴리즈만 안내한다. 잘못된 응답, 사전 릴리즈, HTTP 오류, 시간 초과는 실패로 처리하고 최신 버전이라고 표시하지 않는다.
- **메뉴바의 설정 바로 아래**에 `업데이트 확인…`을 둔다. 확인 중에는 비활성화하고, 새 버전이 있으면 `새 버전 vX.Y.Z 다운로드…`로 바꾼다. Dock 표시 시 KeyHue 앱 메뉴에도 같은 동작을 제공한다. 수동 확인은 일반 설정을 열어 결과를 보여준다.
- **설정 › 일반 › 업데이트**에 현재 버전, 마지막 성공 시각, 자동 확인 토글, 조회 결과, 확인 버튼과 다운로드 링크를 둔다. 이미 발견한 업데이트와 마지막 성공 시각은 로컬에 저장해 재실행·조회 실패 후에도 유지한다. 설치된 버전보다 최신이 아니면 다운로드 링크를 숨긴다.
- **알림 배너·자동 팝업·아이콘 색 변경은 추가하지 않는다.** 백그라운드 조회가 타이핑이나 다른 앱의 포커스를 방해하지 않는다. 오류도 설정에서만 표시한다.
- **다운로드는 해당 버전의 GitHub 릴리즈 페이지를 브라우저로 연다.** URL은 검증된 버전으로 앱에서 구성한다. 앱 안에서 ZIP을 받거나 앱 파일을 교체하지 않는다. 사용자는 변경 내역을 읽고 ZIP을 받은 뒤 KeyHue를 종료하고 응용 프로그램 폴더의 앱을 교체한다.
- README·제품 명세·사이트의 “네트워크 없음” 안내를 업데이트 확인 목적의 통신과 끄는 방법으로 바꾼다. 영어·한국어·일본어 UI를 함께 제공한다.

## 결과
- 유료 멤버십·서버·새 서명 키 없이 기존 릴리즈 파이프라인을 그대로 사용한다.
- GitHub의 비인증 API 한도나 오프라인 환경에서는 확인이 실패할 수 있다. 자동 재시도는 다음 24시간 주기에 하고 사용자가 수동으로 다시 확인할 수 있다.
- 자동 설치는 제공하지 않는다. 필요해지면 Sparkle 도입을 별도 ADR로 결정한다.
- 이미 배포된 앱에는 확인 코드가 없으므로 사용자는 이 기능이 포함된 버전을 처음 한 번 직접 설치해야 한다.
- 버전 비교·확인 간격은 Core 테스트로, 응답 검증·캐시·자동 확인 OFF·오류·중복 요청·메뉴 연결은 가짜 네트워크와 시간으로 검증한다. 실제 시간을 기다리거나 테스트에서 GitHub에 접속하지 않는다.

## 검토한 대안
- **Sparkle로 자동 설치**: 설치 경험은 좋아지지만 현재 빌드·서명 구조에 필요한 작업이 더 크다. 이번 사용자 선택은 안내와 링크이므로 보류한다.
- **시스템 알림만 제공**: 알림 권한과 전달 여부에 따라 놓칠 수 있고 타이핑을 방해할 수 있다. 메뉴·설정에 상태를 유지한다.
- **짧은 간격 polling**: 업데이트 빈도에 비해 요청과 전력 사용이 늘어난다. 24시간 간격의 예약을 사용한다.
