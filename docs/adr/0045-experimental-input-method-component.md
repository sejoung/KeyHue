# 0045. 실험적 입력기는 같은 제품의 별도 앱으로 만들고, 기본 입력과 자동 고침을 단계별로 검증한다

> 배포·버전·사용자 설치 흐름은 [ADR 0051](0051-single-app-distribution-and-managed-input-method.md)로 대체했다. 아래는 당시 결정이며 프로세스 경계·개인정보·단계별 검증 등 유지 범위는 0051을 따른다.

- 상태: Accepted (구조·개발 순서의 결정, 입력기 구현 전. 고침 기본값은 [0064](0064-correction-modes-off-manual-automatic.md)로 대체)
- 날짜: 2026-10-02

## 맥락
한/영 알림은 잘못 친 단어를 알려 주지만, 사용자가 지우고 입력 소스를 바꾼 뒤 다시 쳐야 한다. 사용자 피드백은 InputMethodKit으로 입력을 직접 조합하고, 단어 끝에서 자동 고침과 Backspace 되돌리기를 제공하자는 것이다.

[ADR 0040](0040-mistype-language-detection-phase0.md)의 두벌식 조합과 판정기는 출발점이 된다. 다만 11,172개 음절 왕복 테스트는 조합 알고리즘 검증이며, 입력기의 편집·확정·앱 호환성을 검증한 것은 아니다. 말뭉치의 검출률·오탐률도 실제 자동 고침의 정확도나 되돌리기 성공률과 다르다.

입력기가 소유한 조합 문자열은 직접 바꿀 수 있지만, 확정된 텍스트는 클라이언트 앱의 문서다. InputMethodKit을 도입해도 확정 후 교체, 커서 이동, 앱별 텍스트 API 차이와 입력 모드 동기화는 검증해야 한다.

## 결정

### 제품과 프로세스
- **같은 KeyHue 제품·저장소에서 별도 입력기 앱 번들과 프로세스를 만든다.** 기존 `KeyHue.app`은 표시·알림·자동 전환 유틸리티로 유지하고, 계획 중인 `KeyHueInputMethod.app`은 macOS가 실행하는 InputMethodKit 입력기다. ADR 0040에서 검토한 별도 제품 대신 같은 제품의 선택 설치 구성 요소로 구체화한다.
- 입력기는 유틸리티 실행 여부에 의존하지 않는다. KeyHue를 종료해도 기본 입력·자동 고침·되돌리기가 동작해야 한다. 입력기를 설치하지 않은 사용자의 기존 유틸리티 동작을 유지한다.
- 두벌식 한글과 QWERTY 영문 모드를 제공한다. 여기서 영문 모드는 KeyHue 입력기의 모드이며, Apple ABC 입력기를 대체·삭제하거나 그 ID를 사용하지 않는다.

### 모듈 경계
- 기존 `KeyHueCore`의 두벌식 조합·판정 모델을 공유한다.
- 계획 중인 `KeyHueInputMethodCore`는 조합 세션, 편집, 확정, 고침·되돌리기 정책을 담당하는 순수 로직이다. 기존 경고용 `MistypeWordTracker`를 입력 편집기로 사용하지 않는다.
- 계획 중인 `KeyHueInputMethodApp`은 IMK 서버·컨트롤러·클라이언트 API를 연결하고, `KeyHueInputMethod`는 진입점만 둔다. 입력기 모듈은 `KeyHueApp`에 의존하지 않는다.
- 입력 상태는 클라이언트 세션마다 분리한다. 고침은 IMK 텍스트 API로 수행하며, 합성 Backspace·키 입력·클립보드 붙여넣기·AX 문서 수정으로 구현하지 않는다.

### 실험 범위와 개발 순서
- 입력기 자체를 **선택 설치하는 실험적 구성 요소**로 시작한다. 자동 고침은 별도의 옵션이며 **기본 OFF**다. 기본 입력의 안정화와 자동 고침의 정식 전환을 따로 판단한다.
- **T: 기술 검증 → 0: 기본 두벌식·영문 입력 → 1: Space에서 영문→한글 자동 고침과 즉시 Backspace 되돌리기 → 2: 치는 중 판정** 순서로 진행한다. 각 단계의 완료 기준을 만족해야 다음 단계로 넘어간다.
- 1단계는 검증된 일반 텍스트 앱에서만 사용자가 켤 수 있다. 한글→영문 고침, Return·Tab에서 고침, 코드·터미널·보안 입력의 자동 고침은 초기 범위에서 제외한다.
- 고침을 수락하면 다음 단어의 모드도 한글로 맞추고, 즉시 되돌리면 원문과 이전 영문 모드를 복원한다. 직접 바꾼 모드가 우선한다. 모드 반영을 확인할 수 없는 상황에서는 고침하지 않는다.
- 되돌리기는 **방금 고친 단어의 위치·내용·커서가 유지된 경우에만** 제공한다. 추가 입력·이동·포커스 변경 등으로 조건이 깨지면 일반 Backspace 동작을 따른다. 임의의 이전 문서를 수정하지 않는다.
- 영문 단어 전체를 marked text로 유지할지, 먼저 확정하고 제한된 범위를 교체할지는 T단계에서 비교한다. 이 선택과 API 호출 순서는 1단계 구현 전에 후속 ADR로 확정한다.

### 기존 기능과 개인정보
- 색·HUD는 실제 입력 소스/모드 확인 결과를 따른다. 키를 눌렀다는 이유만으로 색을 바꾸지 않는다. IME 모드의 TIS 노출과 유틸리티의 자동 전환·복원을 함께 검증한다.
- KeyHue 입력기를 선택한 동안 유틸리티의 기존 한/영 경고를 중복 실행하지 않는다. 지원 입력 소스 ID를 추가하는 것만으로 연동을 끝내지 않는다.
- 입력기는 자신에게 전달된 입력과 필요한 최소 교체 범위를 메모리에서 처리한다. 단어·문서·키 이력은 파일·설정·진단 로그·네트워크에 남기지 않는다. 세션 종료 시 버퍼를 지운다. 유틸리티와 입력 내용을 주고받지 않는다.
- 초기 설정은 입력기가 소유한다. 설정·상태 연동이 필요해지면 입력 내용을 제외한 최소 계약을 별도로 정한다. 기존 `KeyHueApp` 런타임이나 전역 설정 객체를 가져오지 않는다.
- 현재 유틸리티의 업데이트 확인([ADR 0044](0044-update-check-and-release-link.md))으로 입력기를 설치·교체하지 않는다. 실험 배포는 별도 아티팩트와 명시적인 설치·복구 절차를 갖춘다.

## 결과
- 유틸리티 사용자에게 입력기 설치를 요구하지 않으면서 기존 조합·판정 자산을 재사용할 수 있다.
- 자동 고침 없이도 기본 입력기를 먼저 배포해 실제 앱 호환성 피드백을 받을 수 있다.
- 입력 유실·중복, 다른 세션 수정, 단축키 차단은 출시 차단 결함이다. 판정 숫자가 좋아도 이 기준을 통과하기 전에는 자동 고침을 배포하지 않는다.
- 두 앱 번들, 세션 편집 엔진, 설치·업데이트·복구 검증이 추가된다. “판정기에 IMK만 붙이면 완성”으로 일정이나 안정성을 판단하지 않는다.
- 서명·공증과 등록·업데이트 동작은 입력기 번들로 별도 검증한다. 기존 자체 서명 방식이 그대로 충분하다고 가정하거나 유료 Developer ID 도입을 이 결정의 선행 조건으로 삼지 않는다.

## 검토한 대안
- **유틸리티에서 외부 입력을 지우고 다시 입력**: 기존 조합 상태와 전환 경쟁에 의존하므로 채택하지 않는다.
- **기존 KeyHue 프로세스에 입력기 역할 통합**: 입력기 수명 주기와 유틸리티의 종료·설정 창·로그인 실행이 결합되므로 채택하지 않는다.
- **별도 저장소·별도 제품**: 현재는 공통 코어 재사용과 단계별 검증의 비용이 커진다. 독립 배포 구성 요소로 분리하되 제품·저장소는 함께 유지한다.
- **기본 입력과 자동 고침을 한 번에 출시**: 입력기 결함과 판정 오탐을 구별하기 어렵고 되돌릴 경로가 좁아진다.
