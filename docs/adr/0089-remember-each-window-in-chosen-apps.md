# 0089. 고른 앱만 창마다 입력 소스를 기억한다

- 상태: Accepted (구현·단위 테스트, 실제 기기 확인은 남음)
- 날짜: 2026-10-12
- 관련: [0028](0028-remember-input-per-window.md), [0029](0029-switch-behavior-per-situation.md), [0038](0038-ux-cleanup.md)

## 맥락

0029는 "같은 앱에서 창을 바꿀 때" 동작 하나를 모든 앱에 쓴다. 사용자마다 앱에 따라 원하는 것이 달랐다.

- 터미널은 창(탭)마다 다른 언어를 쓴다. 영어 명령을 치는 탭과 한글 커밋 메시지를 쓰는 탭이 섞인다. 창마다 기억해야 한다.
- 메신저는 대부분 한글로 쓴다. 채팅방(창)을 바꿔도 입력 소스가 그대로이고, 다른 앱에 갔다 오면 그 앱에서 쓰던 것으로 돌아오기를 바란다. 앱 하나로 기억해야 한다.

앱 복원 + 창 그대로 두기가 메신저 쪽, 앱 복원 + 창 복원이 터미널 쪽 동작이다. 둘 다 이미 있지만 앱마다 다르게 고를 수 없었다.

앱마다 세 동작 중 하나를 고르는 안도 검토했다. 앱 설정 3 × 창 설정 3 × 앱별 창 설정 3으로 조합이 늘고, "앱 하나로 기억"이 "창: 그대로 두기"라는 이름으로 보여 원하는 것을 찾기 어려웠다. 그래서 앱마다 고르는 것을 기억 단위(창마다 / 앱 하나로) 하나로 줄였다.

Ghostty(2026-10-12, macOS 26.6.2)를 손쉬운 사용 API로 확인했다.
- 탭은 macOS 기본 탭이라 탭마다 창 요소가 따로 있다. 새 탭은 창 생성과 메인 창 변경을, 탭 전환은 매번 메인 창 변경을 알렸다. 돌아온 탭은 같은 창 요소(CFEqual)였다. 지금의 창 감지로 탭마다 기억할 수 있다.
- 분할된 칸은 같은 창이다. 칸을 옮겨도 메인 창은 바뀌지 않아 칸끼리는 구분하지 않는다.

## 결정

- **창마다 기억하는 앱 목록**(`windowMemoryApps`, bundle ID)을 둔다. 목록의 앱은 같은 앱에서 창을 바꿀 때 "마지막 입력 소스로 복원"으로 동작한다. 목록에 없는 앱은 `onWindowSwitch`를 따른다.
- 목록은 **"앱을 바꿀 때"가 복원일 때만** 적용한다. 앱마다 고르는 것은 복원의 기억 단위이기 때문이다. "창을 바꿀 때"가 이미 복원이면 모든 앱이 창마다 기억하므로 목록은 의미가 없다. 적용되지 않는 동안에도 목록은 지우지 않는다. 다시 복원으로 바꾸면 그대로 적용된다.
- 앱을 바꿔 돌아올 때 앞 창 기록을 먼저 쓰는 것(0029)도 그 앱이 창마다 기억할 때만 한다. 메신저는 바로 앱 기록을 쓴다.
- 창 기록은 그 창의 앱과 함께 남긴다. 앱이 창마다 기억하지 않게 되면(목록에서 빠지거나 목록이 적용되지 않게 되면) 그 앱의 창 기록만 지운다. 창 기록은 원래 KeyHue 실행 중에만 있다(0028).
- 손쉬운 사용 권한은 창 옵션이 그대로 두기가 아니거나, 적용 중인 목록에 앱이 있을 때 필요하다. 권한 안내의 **끄기**는 다른 창 기능처럼 목록도 비운다. 남겨 두면 다음 실행에도 권한 안내가 다시 뜬다.
- **켜기·끄기는 메뉴바에서 바로 한다.** 앱을 바꿀 때가 복원이고 창을 바꿀 때가 복원이 아니면, 메뉴에 **"〈맨 앞 앱〉에서 창마다 기억"** 체크 항목이 보인다. 메뉴바 메뉴를 열어도 맨 앞 앱은 바뀌지 않으므로 쓰고 있던 앱이 그대로 이름으로 나온다. KeyHue 자신이 맨 앞이면 보이지 않는다. 켤 때 권한이 없으면 창 옵션과 같은 안내를 거치고, 사용자가 취소하면 추가하지 않는다.
- **설정 창**(자동 전환 탭, 창 옵션 아래)에 **"창마다 기억하는 앱 (n)"** 목록을 둔다. 앱마다 **제거** 버튼이 있고 **앱 추가…**로 여러 개를 한 번에 넣는다. 실행 중이 아니거나 지운 앱도 여기서 뺄 수 있다. 목록이 적용되지 않는 동안에는 그 이유를 보여 준다.
- 로그에는 목록의 bundle ID를 남긴다(사용자가 입력한 단어가 아니다).

### 하지 않는 것
- 앱마다 앱 전환 동작이나 세 가지 창 동작을 고르게 하지 않는다.
- 분할된 칸(같은 창 안)은 구분하지 않는다. 칸을 옮길 때 포커스 요소가 같게 보고되는 경우가 있어 믿을 수 없다.

## 검증

- 단위 테스트: 목록의 앱만 창마다 복원, 목록이 적용되지 않는 조건 두 가지, 앱 복귀 시 앞 창 기록은 창마다 기억하는 앱만, 목록에서 뺀 앱의 창 기록만 지움, 권한 끄기가 목록을 비움, 메뉴 항목의 보임·체크, 저장.
- 수동(Ghostty, 카카오톡): Ghostty 탭마다 복원과 새 탭의 기본 입력 소스, 카카오톡 채팅방 전환 시 유지, 메뉴바에서 켜고 끄기, 설정 창에서 제거.
