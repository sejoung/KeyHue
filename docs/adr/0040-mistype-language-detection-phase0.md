# 0040. 잘못된 언어로 친 단어 판정(실험적): 0단계는 판정기와 말뭉치 측정만 만든다

- 상태: Accepted (0단계: 판정기·측정. 앱 연결과 학습 말뭉치(Leipzig → 위키백과)는 ADR 0041로 갱신)
- 날짜: 2026-10-01

## 맥락
사용자 피드백: 영문으로 쳤는데 한글인 경우(또는 반대)를 알아서 바꿔 달라. 취소는 백스페이스로, 궁극적으로는 InputMethodKit 입력기로.

- 자동으로 고쳐 쓰려면 키 입력을 읽고, 지우고, 다시 쳐 넣어야 한다. 한글 조합 상태, 입력 소스 전환의 경쟁 상태, 앱마다 다른 백스페이스(Vim 등) 때문에 위험이 크다.
- InputMethodKit 입력기는 조합 중인 글자를 직접 쥐므로 깔끔하지만, 두벌식 입력기 전체를 새로 만드는 별도 제품이다.
- KeyHue는 "입력한 내용을 기록하지 않는다"고 약속한다(ADR 0008: ESC 여부만 보는 listen-only 탭). 이 기능은 단어 단위로 키를 메모리에 모아야 한다.
- 두벌식 + QWERTY 계열(ABC/U.S.)에서만 의미가 있다. 다른 언어와 배열에는 쓸 수 없다.

판정 정확도가 낮으면 이후 단계(경고, 자동 전환, 고쳐 쓰기)는 모두 의미가 없다. 그래서 먼저 판정만 만들고 숫자를 잰다.

## 결정
- **판정기는 KeyHueCore의 순수 로직이다**(`Sources/KeyHueCore/Mistype/`). 앱에는 아직 연결하지 않는다. 권한, 이벤트 탭, 설정 UI는 바뀌지 않는다.
  - 키 입력은 QWERTY 글자로 나타낸다(대문자 = Shift). macOS 키 코드는 배열과 상관없으므로 같은 입력을 영문과 두벌식으로 동시에 풀 수 있다.
  - `Dubeolsik`: macOS 두벌식과 같은 조합(겹모음, 겹받침, 받침 넘기기). 11,172개 음절 전체가 키 → 음절로 되돌아오는지 테스트한다.
  - `HangulSyllableModel`: 음절 bigram 모델(단어 경계 포함, unigram 보간). 음절당 평균 log10 확률을 "한국어다움" 점수로 쓴다.
  - `MistypeDetector`: 단어 하나(공백에서 판정)를 `keep / meantHangul / meantLatin`으로 판정한다. 영어 사전은 프로토콜이다(앱에서는 NSSpellChecker).
- **판정 규칙** (측정으로 정했다)
  - 영문 모드 → 한글: 3타 이상이다. 영어 사전에 없다. 의미 없는 Shift(Q W E R T O P 외의 대문자)가 없다. 두벌식으로 풀면 음절만 나오고 점수가 −2.75 이상이다.
    - 의미 없는 Shift 규칙은 고유명사(Gurdial → 혁야미) 오탐을 없앴다.
  - 한글 모드 → 영어: 2타 이상이다. 다음 둘 중 하나면 영어로 본다.
    - 영어 단어이고, 음절만 나왔다면 점수가 −2.5 미만이다.
    - 음절이 되지 못한 모음이 남았다(ㅔㅑㅔㄷㄹ먀ㅣ = pipefail). 명령어와 식별자를 잡는다.
  - 이때 영어 단어는 소문자, 첫 글자만 대문자, 모두 대문자 중 하나여야 한다. 가운데 대문자(wkRn = 자꾸)는 쌍자음이기 때문이다.
  - 같은 낱자 반복(ㅋㅋㅋ, ㅠㅠ)과 3타 이하 초성체(ㅎㄷㄷ = gee, ㅇㅋ)는 그대로 둔다.
- **측정은 `Tests/perf/mistype-eval.sh`로 한다**(로컬 전용). 정답 텍스트에서 "잘못된 모드로 친 입력"을 기계적으로 만들 수 있으므로, 사람이 치지 않고도 오탐과 검출을 잴 수 있다.
  - 학습: Leipzig 한국어 뉴스 100K. 측정: 한국어 위키·Tatoeba(대화체), 영어 뉴스·위키, 이 저장소의 코드.
  - 학습과 측정 말뭉치는 출처가 다르다.
  - 말뭉치는 내려받아 `.artifacts/corpora/`에만 둔다. 모델을 앱에 넣을 때는 라이선스를 따로 확인한다.
  - NSSpellChecker(en)는 로마 숫자 글자로만 된 문자열(vlxl, dmdm)을 모두 맞다고 한다. 측정 도구는 그런 문자열을 시스템 단어 목록으로 한 번 더 확인한다. 앱에 넣을 때도 같은 처리가 필요하다.

## 측정 결과 (2026-10-01)
오탐은 맞게 친 1,000단어당 잘못 판정한 횟수다. 검출은 잘못된 모드로 친 단어 중 잡아낸 비율이고, 짧아서 판정하지 않은 단어도 놓친 것으로 센다.

| 방향 | 설정 | 검출 | 오탐 /1000 |
|---|---|---|---|
| 영문 모드 → 한글 | 3타, −2.75 | 위키 96.2%, 대화체 93.1% | 뉴스 0.02, 위키 0.03, 코드 0.24 |
| 한글 모드 → 영어 | 2타, −2.5, 낱자 모음 | 뉴스 88.0%, 위키 88.8%, 코드 87.9% | 위키 0.11, 대화체 0.14 |
| (참고) 한글 모드, 3타 | 3타, −2.5, 낱자 모음 | 뉴스 77.6%, 코드 82.9% | 위키 0.08, 대화체 0.03 |

- 남은 오탐은 대부분 두벌식으로도 말이 되는 짧은 단어다(영문 thd → 송, qos → 밴 / 한글 꺼 → Rj, 앳 → dot).
- 놓친 것은 대부분 양쪽 다 말이 되는 짧은 단어다(dl → 이, rm → 그, to → 새, do → 애). 영어 사전이 약어로 받아 주는 3타(dir, sms)와 영국식 철자도 놓친다.
- 3타 이하 초성체 규칙 때문에 was(ㅈㅁㄴ)·are·get·see는 잡지 못한다(검출 약 −2%p). ㅎㄷㄷ 같은 표현을 영어로 바꾸지 않는 쪽을 택했다.

## 결과와 한계
- 공개 말뭉치로 판정 자체는 쓸 만하다는 것을 확인했다. 오탐이 1,000단어당 1회보다 훨씬 적다.
- 말뭉치로 잴 수 없는 것이 있다. 이것들은 직접 써 봐야 한다(1단계).
  - **오타:** 말뭉치에는 오타가 없다. 오타로 낱자 모음이 남으면(ㅇ나녕) "낱자 모음 → 영어" 규칙이 오탐을 낸다.
  - **섞어 쓰기:** 한 단어 안에서 언어를 바꾸는 입력(API를)과 단어 중간의 백스페이스·커서 이동.
  - **실제 입력의 단어 분포:** 채팅, 터미널 명령, 셸 기록. `--latin shell=$HOME/.zsh_history`처럼 내 말뭉치를 더해 로컬에서 잴 수 있다.
- 다음 단계(1a: 경고만, 기본 꺼짐, 한국어 두벌식과 ABC/U.S.가 둘 다 있을 때만 표시)로 가려면 다음이 필요하다.
  - 입력 모니터링 탭에서 키 코드를 글자로 바꾸고, 공백에서 판정한 뒤 버퍼를 비운다. 버퍼는 메모리에만 두고 로그에 남기지 않는다.
  - README 개인정보 표를 고친다.
  - 음절 모델을 앱 리소스로 넣는다(라이선스 확인).
