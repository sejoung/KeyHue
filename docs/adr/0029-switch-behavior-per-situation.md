# 0029. 앱·창을 바꿀 때 "그대로 / 기본 입력 소스로 전환 / 마지막 입력 소스로 복원" 중 하나를 고른다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락
앱·창 전환과 관련된 옵션이 네 개로 나뉘어 있었다.
- "앱 전환 시 ABC로 전환"(ADR 0007), "앱별 입력 소스 기억"
- "같은 앱에서 창을 바꾸면 ABC로 전환"(ADR 0027), "창별 입력 소스 기억"(ADR 0028)

같은 순간(앱이나 창을 바꿀 때)에 무엇을 할지를 여러 옵션이 나눠 정하고 있었다.
- 초기화와 기억을 둘 다 켜면 기억이 이기고, 초기화는 처음 가는 앱·창에만 적용됐다. 이 관계가 메뉴에 드러나지 않았다.
- "앱별 기억 + 창 전환 시 ABC"처럼 층이 섞인 조합은 동작을 예측하기 어려웠다.

사용자가 실제로 답하는 질문은 "앱(창)을 옮기면 입력 소스를 어떻게 할까?" 하나이고, 답은 셋이다.

## 결정
- `SwitchBehavior`: **그대로 두기(keep) / 기본 입력 소스로 전환(switchToDefault) / 마지막 입력 소스로 복원(restoreLast)**.
- 설정 두 개로 상황마다 하나씩 고른다. 기본은 둘 다 그대로 두기다.
  - `onAppSwitch`: 앱을 바꿀 때. 권한이 필요 없다.
  - `onWindowSwitch`: 같은 앱에서 창을 바꿀 때. 그대로 두기가 아니면 손쉬운 사용 권한이 필요하다.
- **복원인데 기록이 없으면 기본 입력 소스로 전환한다.** 처음 여는 앱, ⌘N으로 연 새 창이 해당한다. 단축키가 엉뚱한 언어로 입력되지 않게 한다는 앱의 목적에 맞춘다. 이 때문에 "복원하되 처음 가는 곳은 그대로 두기" 조합은 없다.
- 각 상황의 규칙은 그 상황에만 적용된다.
  - 앱을 바꿀 때는 `onAppSwitch`를 따른다. 복원이고 창도 복원이면, 돌아온 앱의 앞 창 기록 → 앱 기록 → 기본 입력 소스 순으로 고른다.
  - 창을 바꿀 때는 `onWindowSwitch`를 따른다. 같은 앱 안이므로 앱 기록은 쓰지 않는다.
  - 앱 기억은 앱이 복원일 때만, 창 기억은 창이 복원일 때만 기록한다.
- 메뉴는 "앱을 바꿀 때 ▸", "같은 앱에서 창을 바꿀 때 ▸" 하위 메뉴로 보여 준다.
  - 창 옵션에 권한이 없으면 상위 항목에 "–"를 표시하고, 아래에 "손쉬운 사용 권한 허용…"을 보인다.
  - "기억한 입력 소스 지우기"는 복원을 하나라도 골랐을 때만 보인다.
- 설정 창 자동 전환 탭은 선택 목록 두 개와 ESC 토글로 구성한다.
- 권한 안내에서 "끄기"를 고르면 창 옵션만 그대로 두기로 바꾸고, 앱 옵션은 유지한다.
- **기존 설정은 옮긴다**(키: `resetOnAppSwitch`, `resetOnWindowSwitch`, `rememberInputPerApp`, `rememberInputPerWindow`, 개발 중이던 `inputMemory`). 옮긴 뒤 옛 키는 지운다.
  - 앱: 기억이 켜져 있었으면 복원, 아니면 초기화 토글에 따라 전환 또는 그대로
  - 창: 창별 기억이 켜져 있었으면 복원, 아니면 창 초기화 토글에 따라 전환 또는 그대로

## 결과
- 옵션 네 개가 선택지 두 개가 되어, 조합이 몇 개인지와 어떤 순서로 적용되는지가 메뉴에 그대로 드러난다.
- 단위 테스트
  - 동작별 기억 여부
  - 창: 복원 / 처음 보는 창 / 전환 / 그대로
  - 앱: 앞 창 우선, 앱 → 기본 순서, 창이 복원이 아니면 창 기록을 쓰지 않음, 앱 규칙이 앱 복귀를 결정
  - 권한 "끄기", 메뉴 상태, 저장, 옛 설정 9가지 조합 이전
  - 흐름: 창별 복원, 새 창은 ABC, 앱 복원 + 창 전환 조합
- 통합 테스트: 창 선택은 권한 안내를 거치고, 앱 선택은 바로 저장된다.
- ADR 0007의 "앱 전환 시 ABC" 토글과 ADR 0027의 "창 전환 시 ABC" 토글은 이 선택지로 대체된다. 지연 전환·1회 검증과 메인 창 감지 방식은 그대로다.
