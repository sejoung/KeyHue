# 0027. 같은 앱 안에서 창을 바꾸면 기본 입력 소스로 전환한다 (메인 창 변경 기준)

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락
"터미널 창이 여러 개 떠 있을 때, 창을 옮기면 영어로 초기화하고 싶다"는 요청이 있었다.
- "앱 전환 시 전환"(ADR 0007)은 NSWorkspace의 **앱 활성화** 알림만 쓴다. 같은 앱 안에서 창을 옮기는 것은 알 수 없다.
- 창 이동을 권한 없이 알려주는 공식 알림은 없다. 주기적 확인(polling)은 원칙상 쓰지 않는다.
- 텍스트 필드 기능(ADR 0009)이 이미 손쉬운 사용 API로 활성 앱을 관찰하고 있다.

구현 전에 AX 알림을 실측했다.
- **창 전환**(테스트 앱, Finder): "포커스 창 변경"과 "메인 창 변경"이 함께 오고, 창 요소는 CFEqual로 구분된다.
- **탭 전환**(테스트 앱의 AppKit 탭): "포커스 창 변경"은 **오지 않고**, "메인 창 변경"만 온다.
- 이 환경에서는 알림으로 받은 창의 role/subrole을 읽는 호출이 실패했다(`kAXErrorInvalidUIElement`, 테스트 앱·Finder 모두). 그래서 창 종류(일반 창, 대화상자)로 거르는 방식에 기대지 않는다.

## 결정
- 옵션 **"같은 앱에서 창을 바꾸면 기본 입력 소스로 전환"**(`resetOnWindowSwitch`, 기본 꺼짐). 손쉬운 사용 권한이 필요하고, 켤 때만 설명 후 요청한다. 앱 시작 시 권한이 끊겨 있으면 알린다(ADR 0021).
- `AccessibilityFocusMonitor`(텍스트 필드 감지를 확장해 이름을 바꿈)가 활성 앱의 **`kAXMainWindowChangedNotification`**을 구독한다.
  - `WindowSwitchTracker`(Core, 테스트 대상)가 "알고 있던 **다른** 메인 창으로 바뀐 경우"에만 전환으로 센다.
  - 떠 있는 패널·대화상자·시트는 보통 메인 창이 되지 않으므로 제외된다.
  - 대화상자를 닫고 같은 창으로 돌아오면 같은 창이라 세지 않는다.
  - 앱이 바뀌면(ADR 0007의 영역) 새 앱의 현재 메인 창으로 기준을 다시 잡는다. 그래서 앱 전환이 창 전환으로 두 번 세어지지 않는다.
  - 창은 AX 요소의 CFEqual로만 구분하고, 창 제목이나 내용은 읽지 않는다.
- 전환은 앱 전환과 같이 0.1초 기다린 뒤 실행하고, 0.25초 뒤 한 번 검증한다(ADR 0007).
  - macOS의 "문서 입력 소스 자동 전환"이 창마다 입력 소스를 되살리는 것과 경쟁하지 않기 위해서다.
- 메뉴·설정 창·권한 안내·사용 설명서·명세에 추가하고, 세 언어로 번역한다.

## 결과
- 단위 테스트
  - 기준 없음 → 기준만 잡음
  - 다른 창 → 전환
  - 같은 창 → 무시
  - 창 없음 → 기준 유지
  - 앱 전환 후 기준 재설정
  - 정책(옵션 꺼짐·이미 영문), 권한 판단, 메뉴 상태, 저장
  - 0.1초 대기 후 전환
- 통합 테스트: 창 동일성 비교, 메인 창 알림 구독, 설정 창 토글.
- **아직 실제 앱에서 확인하지 않은 것**: 터미널·iTerm·VS Code 등 실제 앱에서 창과 탭 전환이 이 알림으로 잡히는지. 사용자가 권한을 허용한 뒤 확인해야 한다(`docs/TESTING.md` 체크리스트). 앱마다 탭을 구현하는 방식이 달라 탭 전환이 잡히지 않는 앱이 있을 수 있다.
- 새 창을 열거나(⌘N) 창을 닫아 다른 창이 메인이 되는 것도 "창을 바꾼 것"으로 센다.
