# 0038. Dock 표시는 기본으로 끄고, 메뉴는 자주 쓰는 것만 두며, 설정 창은 네 탭으로 나눈다

- 상태: Accepted (ADR 0020의 Dock 표시 기본값을 대체)
- 날짜: 2026-09-30

## 맥락
기본 기능을 확인한 뒤 UI·UX를 점검했다. 실측이나 이번 작업 중 실제로 겪은 것을 근거로 삼았다.

1. **창 없는 KeyHue가 포커스를 가져갔다.** "Dock에 표시"가 기본으로 켜져 있어 KeyHue가 일반 앱으로 동작했다.
   - 설치 후 실행하자 맨 앞 앱이 Slack에서 KeyHue로 바뀌었다. Dock 표시를 끄면 Ghostty가 그대로 맨 앞이었다.
   - 측정용 앱을 닫자 포커스가 KeyHue로 갔다. Dock 표시를 끄면 Ghostty로 돌아갔다.
   - 포커스를 가진 KeyHue에는 창이 없어서 바로 타이핑할 수 없고, 그동안 KeyHue는 관찰할 앱도 없다.
2. **설정 창 일반 탭이 너무 길었다.** macOS 입력 소스 표시 옵션을 더하면서 높이를 780까지 늘렸는데도 스크롤바가 보였고, 자동 전환 탭은 절반이 비어 있었다.
3. **메뉴가 길었다.** 약 20개 항목에 막대 위치·두께·불투명도·색상·디스플레이 하위 메뉴까지 있어 설정 창과 거의 겹쳤다.
4. **문구가 실제와 달랐다.** "자동 전환(앱 전환, ESC, 텍스트 필드 벗어남)"에 창 전환이 빠져 있었다. "앱은 그대로, 창은 복원" 조합에서 앱에서 돌아올 때 창의 기억을 쓰지 않는다는 점도 드러나 있지 않았다.
5. **색상 목록에 내부 ID가 보였다.** 입력 소스 이름 아래에 `com.apple.inputmethod.Korean.2SetKorean` 같은 ID가 있었다.
6. **창 전환 감지 실패가 보이지 않았다.** 앱이 AX에 끝내 답하지 않으면(ADR 0033) 사용자는 "그냥 안 된다"로만 느낀다.

## 결정
1. **Dock 표시를 기본으로 끈다**(`showDockIcon = false`).
   - ADR 0020의 이유 중 "다시 실행해도 반응이 없다"와 "노치에 가려지면 설정에 못 들어간다"는 이미 해결되어 있다. 다시 실행하면 설정 창이 열린다.
   - 남은 "⌘Tab으로 설정 창에 못 돌아간다"는 **설정 창이 열려 있는 동안만 Dock에 표시**해서 해결한다. 창을 닫으면 메뉴바 전용으로 돌아간다(`showsDockIcon(settingsWindowOpen:)`).
   - 기본값과 같은 값은 저장하지 않으므로(ADR 0014), Dock 표시를 직접 바꾼 적이 없는 기존 사용자도 업데이트 후 메뉴바 전용이 된다. 늘 Dock에 두려면 켜면 된다.
2. **설정 창을 네 탭으로 나누고 높이를 640으로 줄인다.**
   - 일반: 언어, Dock 표시, 로그인 시 실행, 로그 파일 보기
   - 모양(새 탭): 상태 바, 메뉴바 아이콘, HUD, macOS 입력 소스 표시
   - 입력 소스, 자동 전환: 그대로
   - 새 탭 이름은 안에 있는 "표시" 절과 겹치지 않게 macOS 시스템 설정의 용어(모양 / Appearance / 外観)를 따른다.
   - **탭은 SwiftUI `TabView` 대신 AppKit 분할 컨트롤로 직접 그린다.**
     - `TabView`는 내용 둘레에 테두리 상자를 그렸다. 그래서 탭이 제목 막대 구분선에 붙었고, 탭 아래에 배경색이 다른 띠가 생겼다(사용자 지적, 실제 창 캡처로 확인).
     - SwiftUI의 분할 컨트롤은 칸을 글자 길이에 맞춰 나눠 "Input Sources"가 비좁았다. 그래서 AppKit 분할 컨트롤(`fillEqually`)로 네 칸을 같은 너비로 나눈다.
     - 탭 위에 14pt 여백을 둔다. 탭과 내용은 같은 창 배경을 쓰고, 그 배경을 제목 막대 밑까지 늘려(`fullSizeContentView`, 투명 제목 막대, 구분선 없음) 한 가지 색으로 잇는다.
3. **메뉴에는 자주 바꾸는 것만 둔다.**
   - 남기는 것: 현재 입력 소스, 상태 바 표시, 앱·창 전환 동작, 기억 지우기, ESC, 기본 입력 소스, HUD, 텍스트 필드, 설정, 로그 파일 보기, 정보, 종료
   - 설정 창으로 보내는 것: 막대 위치·두께·불투명도·디스플레이, 색, Dock 표시, 로그인 시 실행
   - 메뉴에서만 쓰던 색 프리셋과 그 번역도 지운다.
4. **문구를 고친다.** 기본 입력 소스 설명에 창 전환을 넣고, 자동 전환 설명에 "다른 앱에서 돌아올 때는 '앱을 바꿀 때'를 따른다"를 덧붙인다(한·영·일).
5. **내부 ID는 이름이 겹칠 때만 보인다.** 평소에는 마우스를 올리면 보인다.
6. **창 전환 감지 실패를 알린다.**
   - AX 붙기를 끝내 포기한 앱이 지금 맨 앞이면, 메뉴의 창 전환 항목 아래와 설정 창 자동 전환 탭에 "○○의 창 전환을 감지하지 못함"을 보인다.
   - 옵션이 꺼져 있거나 권한이 없으면 그 안내가 먼저이므로 보이지 않는다.
   - 메뉴를 열 때 붙기를 한 번 더 시도하므로, 그 사이 앱이 준비됐다면 경고 없이 보인다.

## 결과
- 단위·통합 테스트
  - Dock 표시 기본값이 꺼짐이고, 설정 창이 열려 있을 때만 보인다.
  - 메뉴 상태에서 막대·색·Dock·로그인 필드를 뺐다.
  - 이름이 겹칠 때만 내부 ID를 보인다.
  - 감지 실패 안내는 창 옵션이 동작 중일 때만 보인다(메뉴와 설정 창).
  - 쓰지 않는 번역 키가 없다(번역 테스트).
- 설정 창 스크린샷 네 장을 다시 만들었다. 모두 스크롤 없이 640 높이에 들어간다.
- 설명서(한/영)의 처음 실행, 메뉴 표, 설정 절(모양 탭 추가), 문제 해결(아이콘이 가려지면 다시 실행)을 고쳤다.

## 갱신 (2026-10-01): 앱을 숨겨도 막대는 남는다
- 문제: 설정 창을 닫아 메뉴바 전용으로 돌아갈 때 포커스를 원래 앱에 돌려주려고 `NSApp.hide(nil)`을 부른다. 그런데 이것이 앱의 모든 창을 숨겨, **아무 설정도 바꾸지 않고 닫으면 하단 막대가 사라졌다**(다음 앱 전환 때까지).
  - 설정을 바꾸고 닫으면 막대를 다시 그리면서 나타나서, 바꾸지 않았을 때만 드러났다.
  - 같은 원인: Dock 아이콘이 보일 때 메뉴의 "KeyHue 가리기"(⌘H), 다른 앱의 "기타 가리기"(⌥⌘H).
- 결정: State Bar, 전환 HUD, 한/영 경고 메시지 패널은 `canHide = false`로 둔다. 앱을 숨겨도 남고, 설정 창만 숨는다.
- 검증: 통합 테스트가 패널을 띄운 뒤 `NSApp.hide`를 불러도 보이는지 확인한다(막대·HUD·메시지). 막대 테스트는 수정 전에 실패하는 것을 확인했다.
