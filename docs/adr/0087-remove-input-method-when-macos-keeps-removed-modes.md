# 0087. macOS가 지운 모드를 남겨도 확인 후 입력기를 제거한다

- 상태: Accepted (구현·단위 테스트, macOS 26.6.2 실제 재현. 다른 Mac에서의 재현은 아직 못 함)
- 날짜: 2026-10-12
- 관련: [0053](0053-verify-input-modes-and-repair-owned-source-membership.md), [0055](0055-users-add-input-sources-manually.md)

## 배경

0055는 KeyHue가 입력 소스 목록을 바꾸지 않고, 사용자가 시스템 설정에서 두 모드를 지운 뒤에만 입력기 파일을 지우게 했다. 모드가 남은 채 파일을 지우면 목록에 동작하지 않는 항목이 남기 때문이다.

macOS 26.6.2에서 이 전제가 깨지는 경우를 재현했다(2026-10-12).

- 사용자가 시스템 설정 › 키보드 › 텍스트 입력 › 편집에서 두벌식과 영문을 지웠다. 두벌식은 `com.apple.inputsources`의 `AppleEnabledThirdPartyInputSources`에서 빠졌지만 영문 항목은 남았다.
- 남은 영문은 TIS에서 enabled·selectable이었지만 시스템 설정 목록과 입력 메뉴 어디에도 보이지 않았다. 시스템 설정을 종료했다 다시 열어도 같았다.
- 시스템 설정에서 다시 추가했다 지워도 설정 파일은 바뀌지 않았다. 추가 시트에도 KeyHue가 보이지 않았고, 그 상태에서 추가를 누르면 부모와 영문 항목이 다시 생겼다.
- `TISDisableInputSource`와 `TISEnableInputSource`는 모드에 대해 성공(0)을 반환하면서 아무것도 바꾸지 않았다. 부모 항목(`…spike`)의 비활성화만 설정 파일에 반영됐다.
- 입력기 번들을 옮기면 TIS 카탈로그에서는 곧 사라졌지만 설정 파일의 항목은 남았다.

0053에서도 같은 방식으로 한글 항목이 남았다. 이 상태에서 KeyHue는 "사용자가 아직 쓰는 모드"로 읽어 제거를 계속 막았고, 사용자는 그 모드를 볼 수도 지울 수도 없었다.

## 결정

- 모드가 남아 있으면 지금처럼 제거를 막고 안내한다. 안내 창에서 **입력 소스 설정 열기**, **그래도 제거**, **나중에**를 고른다.
- 안내에 "시스템 설정에 더 이상 보이지 않는데 이 안내가 나오면 macOS가 지운 모드를 잘못 남긴 것"이라고 설명한다. 사용자가 **그래도 제거**를 고르면 모드 확인 없이 제거를 진행한다. 다른 조건(KeyHue 모드 선택 중이 아님, 검증된 설치본만 삭제, 서비스 종료)은 그대로 지킨다.
- 파일을 지우기 전에 KeyHue 자신의 항목을 TIS로 끈다(모드 다음 부모). macOS 26에서는 부모만 반영되지만, 모드 요청도 보내 두어 이를 지키는 macOS에서는 아무것도 남지 않게 한다. 사용자에게 보이지 않는 부모 항목은 일반 제거에서도 이렇게 정리한다.
- 입력기가 없어 TIS 카탈로그에 없는 항목은 "사용자가 추가한 모드"로 보지 않는다. macOS는 남은 모드가 있는 동안 지운 부모 항목도 되살렸지만(2026-10-12 13:35), 카탈로그에 없으면 아무것도 보이거나 동작하지 않는다. 그래서 제거 뒤 메뉴에 **입력기 제거**가 다시 나오거나 다음 제거가 막히지 않는다.
- 확인 후 제거한 뒤에도 macOS가 남긴 모드 항목은 로그에 ID만 남긴다. 입력기가 없으면 아무 동작도 하지 않는다. KeyHue는 `com.apple.inputsources`에 직접 쓰지 않는다(0055 유지).

0055의 "제거는 사용자가 두 모드를 먼저 지워야 진행한다"를 "확인 후 진행할 수 있다"로, "KeyHue는 입력 소스 목록을 바꾸지 않는다"를 "제거할 때 자기 항목만 TIS로 끈다"로 이 결정이 대체한다.

## 검증

- 카탈로그에 없는 설정 항목은 사용자 모드가 아님(순수 함수). 오류창의 그래도 제거가 진행 중인 작업에 묻히지 않고 새 제거를 시작함(수명 주기 테스트, 이전 순서에서는 실패).
- 가짜 런타임: 모드가 남으면 거부, 확인 후 제거는 검증·종료·비활성화 뒤 파일 삭제, 파일이 이미 없어도 확인 후 제거는 자기 항목을 끔, 일반 제거도 부모를 끔, 안내 창의 버튼 세 개.
- 실제(macOS 26.6.2, 위 재현): 부모 비활성화 반영, 모드 요청 무시, 번들이 없으면 TIS 카탈로그에서 빠짐을 확인했다. 남은 설정 항목은 전체 디스크 접근 권한이 있는 터미널의 `defaults delete com.apple.inputsources AppleEnabledThirdPartyInputSources`로만 지울 수 있었다.
- 수동(남은 일): 다른 Mac과 macOS 버전에서 시스템 설정의 모드 삭제가 반영되지 않는 경우를 다시 재현한다.
