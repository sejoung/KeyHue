# 0051. 입력기는 KeyHue에 내장하고, 앱에서 설치·업데이트·제거한다

상태: Accepted (활성화 대기 안내·개발 호환 스크립트는 [0052](0052-input-method-activation-and-single-app-scripts.md)로 갱신, 설치 시 활성화·제거 시 비활성화는 [0055](0055-users-add-input-sources-manually.md)로 대체, 영문 한 글자 조합은 [0081](0081-commit-english-letters-as-typed.md)로 대체; 실제 앱 호환성 검증 대기)
날짜: 2026-10-02

## 배경

입력기 단독 설치는 KeyHue의 기본 소스 해석·앱별 복원·한/영 모드 유지와 연결하는 과정이 번거롭다. 사용자는 별도 입력기 빌드와 설치 대신 KeyHue에서 입력기 사용을 선택하고 싶어 한다. 별도 버전·ZIP은 연동하는 구성 요소를 서로 다른 상태로 만들기도 한다. 영문 단어 전체에 이어지는 조합 밑줄도 일반 입력을 방해한다.

## 결정

- **사용자가 빌드·다운로드하는 앱은 `KeyHue.app` 하나다.** 입력기 서비스는 `Contents/Helpers/KeyHueInputMethodSpike.app`에 내장한다. macOS가 실행하는 IMK 프로세스와 세션 코어는 유지한다. KeyHue 종료 상태에서도 이미 선택한 입력기의 기본 입력은 동작하고, 모드 유지·자동 복원은 KeyHue 실행 중에 제공한다. 입력 문자열을 프로세스 간 공유하지 않는다.
- 서비스는 KeyHue와 같은 `VERSION`·빌드 번호·아키텍처·서명 identity를 사용한다. 서비스부터 서명하고 외부 앱을 마지막에 서명한다. ZIP·업데이트 안내도 KeyHue 하나로 통합한다. 별도 입력기 빌드·패키징·공증은 공개 진입점으로 제공하지 않는다. 공통 메타데이터와 내부 SwiftPM 타깃은 계속 재사용한다.
- 기능은 **기본 OFF·실험적**이다. 앱 시작·일반 업데이트만으로 입력기를 설치하거나 교체하지 않는다. 설정/메뉴에서 사용·설치·업데이트를 선택하면 연동을 잠시 끄고 ABC로 전환한 뒤 설치한다. 준비되면 연동과 한/영 모드 유지를 켜고 한글 모드를 선택한다. 모드 유지에 필요한 입력 모니터링 설명·요청을 제공하고, 미허용 상태를 설정에 표시한다.
- 설치 위치는 `~/Library/Input Methods/KeyHueInputMethodSpike.app`이다. 내장 원본을 이동하지 않고 복사한다. 기존 등록과 호환되도록 번들 ID·모드 ID·연결 이름·실행 파일·설치 이름을 유지한다. 표시 이름은 KeyHue 입력기다. 전역 설치·관리자 권한·다른 입력기 파일·Apple ABC 삭제를 사용하지 않는다.
- 설치·업데이트는 소유 메타데이터·서명과 임시 사본을 검증하고, 선택 상태를 재확인하며 해당 입력기만 정상 종료한다. 이전 설치본을 보관하고 교체한 뒤 최종 검증·등록·활성화한다. 실패 시 이전 파일과 활성화 상태를 복구한다. 복구 실패 시 백업은 남긴다. 강제 종료·시스템 캐시 삭제를 하지 않는다. 작업 중 KeyHue의 자동 복원을 중단한다.
- 등록은 `TISRegisterInputSource`, 활성화는 부모 → 한글 → 영문 순서다. 두 모드가 아직 노출되지 않으면 설치를 유지하고 재로그인 후 사용 옵션을 다시 켜도록 안내한다. 실제 캐시/재로그인 동작은 지원 OS에서 수동 확인한다.
- **입력기 제거**는 연동 OFF·ABC 전환 후 해당 서비스의 정상 종료·소유/서명·선택 상태를 확인한다. 자신의 모드와 부모만 비활성화하고 정확한 설치 번들만 삭제한다. KeyHue 앱·내장 원본·설정·다른 소스는 보존한다. 실패 시 기존 활성화 상태를 복구한다. 앱까지 삭제할 때는 입력기부터 제거한다.
- 설치본과 내장 서비스의 버전·실행 파일·서명 리소스가 다르면 업데이트 버튼을 표시한다. 같은 버전 개발 재빌드도 교체할 수 있다. 업데이트는 명시적으로 선택할 때만 수행한다.
- **영문도 현재 한 글자만 marked text로 유지한다.** 다음 문자는 이전 글자를 확정한 뒤 자신만 조합 표시한다. 공백·기호·확정 요청은 남은 조합을 확정하고 경계를 한 번 전달한다. Backspace는 조합 글자를 지우고 조합이 없으면 앱의 일반 삭제에 맡긴다. 단어 전체 밑줄 메뉴·정책을 제거한다. 자동 고침용 단어 추적·범위 교체·되돌리기는 미구현이며 후속 ADR과 실제 앱 검증을 거친다.

## 이전 결정에 미치는 범위

- 0045의 별도 배포물·독립 초기 설정 소유, 0046의 별도 버전·ZIP·영문 단어 조합 비교, 0047의 별도 빌드 후 직접 모드 추가 흐름을 대체한다. 프로세스/모듈 경계·개인정보·단계별 검증은 유지한다.
- 0049의 연동·모드 유지 선택은 유지한다. 최초 사용 흐름은 두 옵션을 함께 준비하며 이후 모드 유지를 별도로 끌 수 있다. 사용 OFF는 파일 제거와 다르다. 원래 기본 소스 설정을 보존하는 계약도 유지한다.
- 0048의 한글 현재 음절·아이콘, 0050의 키 직전 실제 모드 동기화는 유지한다. 패키징 통합으로 실제 전환·앱 호환성이 검증됐다고 판단하지 않는다.
- `scripts/install.sh`는 KeyHue 설치용이다. 기존 `scripts/install.sh input-method-spike`는 개발 호환 진입점으로 남기되 통합 앱을 빌드하고 내장 사본을 사용한다. 사용자 안내는 앱의 설치/제거를 기준으로 한다.

## 검증과 결과

임시 폴더·가짜 OS 어댑터로 첫 설치, 기존 설치 업데이트, 같은 버전 재빌드, 등록/최종 검증 실패 복구, 활성 입력기 재선택, 종료 실패, 외부 번들·심볼릭 링크 거부, 제거와 원본 보존을 검사한다. UI는 설치 성공 전에 설정을 직접 켜지 않는지 확인한다. 세션 테스트는 한 글자 조합·삭제·여러 단어 원문 보존·경계 한 번·실제 모드 동기화를 확인한다.

CI와 릴리즈는 통합 앱 하나를 검사하며 내장 입력기 누락·버전/빌드 불일치·아이콘/메타데이터·두 실행 파일의 universal 아키텍처·중첩 서명·IMK self-check를 확인한다. 릴리즈 서명 테스트는 부모와 서비스의 인증서가 같은지 검사한다. Developer ID 공증은 기존 선택 경로를 유지하고 안쪽 서비스와 바깥 앱을 staple한다. 실제 Developer ID 공증 성공은 개발 서명 검사로 대신하지 않는다.

실제 설치·등록·제거·재로그인, TextEdit/Notes/웹/Electron/Terminal의 밑줄·확정·Backspace·전환 직후 첫 글자·권한 미허용 동작은 수동 검증으로 남는다. 자동 테스트는 사용자 시스템 입력 소스를 변경하지 않는다.

## 보완 (2026-10-03): 내장 원본과 설치 위치가 겹치는 경우

- 링크를 따라간 경로로 비교해 내장 원본과 설치 위치가 같거나 한쪽이 다른 쪽 안에 있으면 설치·제거 모두 `invalidBundle`로 거부한다. 이전에는 설치만, 그것도 일부 방향만 막아 업데이트가 서명된 앱 안에 쓰거나 제거가 내장 원본을 지울 수 있었다.
- 테스트: `installRefusesWhenThePayloadIsTheInstallLocationOrInsideIt`, `installNeverWritesInsideThePackagedPayload`, `uninstallNeverDeletesThePackagedPayload`.
