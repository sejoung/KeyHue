# 0052. 설치 성공과 입력 소스 활성화를 구분하고 단일 앱 스크립트만 유지한다

상태: Accepted (macOS 26 자기 멤버십 보완·부모/모드 완료 조건은 [0053](0053-verify-input-modes-and-repair-owned-source-membership.md)으로 갱신)
날짜: 2026-10-02

## 배경과 관찰

입력기를 제거한 뒤 다시 설치하면 설치 완료·재로그인 안내가 반복됐다. macOS 26.6.2의 실제 조회에서 부모와 영문은 활성, 한글은 비활성이었다. `TISEnableInputSource`는 성공을 반환했지만 한글의 enabled 속성은 바뀌지 않았다. 기다리거나 부모를 다시 활성화하는 것만으로 해결되지 않았다. 사용자는 시스템 설정의 입력 소스 추가 화면에서 한글·영문을 직접 추가할 수 있다고 확인했으며 이후 별도 프로세스 조회에서는 두 모드가 모두 활성 상태였다. 이를 자동 활성화 성공의 증거로 해석하지 않는다.

기존 앱은 비활성 상태를 재로그인 필수로 안내했고 사용 요청을 꺼서, 직접 추가한 뒤에도 다시 사용 옵션을 켜야 했다. 0051 이후에도 남아 있던 별도 구성 요소 인자·설치 헬퍼는 입력 소스를 앱이 관리한다는 결정과 맞지 않는다.

## 결정

- 파일 설치·등록 성공과 입력 소스 활성화를 구분한다. 활성화는 부모 → 한글 → 영문 순서이며 각 단계에서 카탈로그와 소스 핸들을 다시 얻는다. 부모가 활성화되기 전에 자식 모드가 보이지 않는다고 중단하지 않는다. API 반환값만으로 완료하지 않고 최종 enabled 속성과 실제 두 모드 가용성을 확인한다.
- 파일 설치가 성공했으나 모드가 비활성이면 설치본과 사용·모드 유지 요청을 보존한다. 설정/메뉴·설치 완료 안내에서 키보드 설정을 열 수 있게 하고, **텍스트 입력 › 편집 › +에서 KeyHue 한글·영문 추가**를 안내한다. 두 모드가 가용해지면 기존 알림 기반 연동 정책이 적용된다. 요청은 저장되므로 앱을 다시 실행해도 옵션을 다시 켤 필요는 없다. 두 모드가 없을 때는 기존 기본 소스 정책을 적용한다.
- 비활성 상태만으로 재로그인을 필수로 안내하지 않는다. 추가 화면에도 입력기가 없거나 캐시 항목이 남는 경우 재로그인을 수동 복구 수단으로 안내한다. 정상 종료 실패 오류의 재로그인 안내는 유지한다.
- 설치 후보와 복구 백업은 macOS가 감시하는 `~/Library/Input Methods` 밖의 임시 폴더에 둔다. 검증된 최종 서비스만 설치 위치에 둔다. 실패 복구와 백업 보존 계약은 유지한다.
- 등록·활성화 상태 코드와 자신의 활성 소스 ID만 진단 로그에 남긴다. 입력 내용은 기록하지 않는다. 비공개 입력 소스 환경 설정 직접 수정·시스템 캐시 삭제·시스템 프로세스 종료는 설치 기능에 넣지 않는다.
- 공개 스크립트는 KeyHue 하나만 처리한다. `scripts/app-config.sh`에서 공유 버전·제품·내장 서비스·서명 메타데이터를 가져온다. `components.sh`, 별도 입력기 등록 헬퍼·구성 요소 테스트를 제거하고 단일 앱 설치/번들 테스트로 대체한다. `utility`·`input-method-spike` 대상 인자는 빌드 전에 거부한다.
- 빌드 과정에서 부모 안에 서비스를 직접 구성·서명한다. 독립 입력기 앱/ZIP을 만들거나 재귀 빌드하지 않는다. `install.sh`는 내장 번들의 ID·공통 버전/빌드·중첩 서명을 검사하고 KeyHue만 설치·실행한다. 입력기 설치·활성화·제거는 앱에서 수행한다. `--no-build`는 유지한다. 내부 SwiftPM 실행 타깃과 호환용 번들/모드 ID는 유지한다.

## 검증과 이전 결정

0051의 재로그인 후 재설정 안내와 개발 호환 설치 진입점을 대체한다. 실제 API가 성공해도 모드가 비활성인 경우, 부모 활성화 후 자식 노출·핸들 갱신, 직접 추가 후 옵션 재조작 없이 가용성 반영, 제거 후 재설치, 입력기 감시 폴더 밖의 staging, 단일 ZIP·내장 누락/버전/서명·구성 요소 인자 거부·앱 설치 실패 복원을 자동 검사한다. 테스트는 임시 파일과 가짜 카탈로그/OS를 사용하며 사용자 입력 소스를 변경하지 않는다.

2026-10-02 전체 검증(`.artifacts/verify/20261002-163601/`): Swift 398개, 스크립트 51개, 사이트 16개와 ShellCheck·통합 번들·IMK self-check 통과.

이번 사용자 환경의 직접 추가 가능·최종 활성 상태는 확인했지만 모든 지원 OS의 자동 활성화나 실제 편집 앱 호환성을 보장하지 않는다. TextEdit/Notes/웹/Electron/Terminal의 입력·전환·밑줄·삭제와 재설치 경로는 계속 수동 검증한다.
