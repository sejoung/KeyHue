# 0088. 검증 시간을 줄인다: 스크립트 테스트 병렬화, 실행 파일 재사용, 단계 겹치기

- 상태: Accepted
- 날짜: 2026-10-12
- 관련: [0022](0022-testing-strategy.md), [0080](0080-swift-lint-file-length-dead-code-and-cycles.md)

## 맥락

`scripts/verify.sh`는 release.sh와 CI가 쓰는 전체 검증이다. 로컬에서 182초가 걸렸다(2026-10-12, 소스 한 파일 변경 후). 단계별로는 스크립트 테스트 105초, `swift test` 26초, 번들 25초, swift-lint 17초였다.

측정해 보니 원인은 대부분 계산이 아니었다.

- **새 실행 파일의 첫 실행.** macOS는 새로 만든 실행 파일을 처음 실행할 때 0.2초쯤 검사한다. 내용이 같은 복사본도 새 파일이면 검사하고, 이미 실행한 파일의 하드 링크·심볼릭 링크는 0.01초였다. 이 검사는 시스템 전체에서 차례로 처리돼, 동시에 10개를 실행하면 마지막 것은 1.6초를 기다렸다. 스크립트 테스트는 테스트마다 가짜 명령(`defaults`, `codesign` 등)을 만들고 저장소 스크립트를 복사해 실행했다.
- **고정 대기.** uninstall 테스트 하나가 로그인 항목 확인의 고정 5초 시간 제한을 기다려 9초 걸렸다.
- **바뀌지 않은 아이콘 생성.** `build-app.sh`가 빌드마다 `swift` 해석기로 아이콘 스크립트 4개를 실행해 7초를 썼다.
- **설정 저장.** `SettingsStore`가 저장할 때마다 바뀌지 않은 키까지 25개 남짓을 모두 쓰거나 지웠다. 쓰기마다 cfprefsd를 거쳐 1ms쯤 걸리고, 앱 테스트는 저장소를 수백 번 만들었다. 설정 창 메뉴 일치 테스트 하나가 6.8초였다. 앱에서도 슬라이더를 끄는 동안 같은 일이 일어난다.

## 결정

- **스크립트 테스트를 동시에 돌린다.** `Tests/scripts/run.sh`는 테스트 하나를 격리된 임시 폴더에서 돌리던 방식을 그대로 두고 `xargs -P`로 CPU 수만큼 동시에 실행한다. 결과는 파일 순서대로 출력한다. 결과를 남기지 못한 테스트는 실패로 본다. `KEYHUE_TEST_JOBS=1`이면 하나씩 돈다.
- **같은 내용의 실행 파일은 한 벌만 둔다.** `make_executable`이 실행 권한을 주고, 실행기의 캐시(`STUB_CACHE`)에 내용별로 한 벌을 두어 하드 링크한다. 캐시 파일은 읽기 전용이라 링크에 덮어쓰면 테스트가 실패한다(다른 테스트의 가짜 명령을 바꾸지 않는다). 내용을 바꿀 때는 `write_executable`을 쓴다. 서명하는 실행 파일(`make_packaged_app`)은 서명이 파일을 바꾸므로 공유하지 않는다.
- **앱 단계 시간 제한을 조절할 수 있게 한다.** uninstall.sh의 `KEYHUE_PREPARE_TIMEOUT`을 `KEYHUE_APP_STEP_TIMEOUT`으로 바꾸고 로그인 항목 확인에도 쓴다. 기본값(5초, 10초)은 그대로다.
- **아이콘은 원본이 바뀔 때만 만든다.** `docs/icon.png`와 아이콘 스크립트 세 개의 SHA-256을 `build/work/app/icons.sha256`에 남기고, 같으면 이전 결과를 쓴다. 다시 만들 때는 네 스크립트를 동시에 돌린다.
- **설정은 저장된 값과 다른 키만 쓴다.** 기본값과 같아진 키는 저장돼 있을 때만 지우고, 레거시 키도 있을 때만 지운다. 저장되는 결과는 같다.
- **verify 단계를 겹친다.** build → swift test는 차례로 돈 뒤, lint·swift-lint(+code-check)·스크립트·사이트 테스트를 번들 빌드와 동시에 돌린다. swift-lint는 `.build/lint`, code-check는 `Tools/CodeCheck/.build`를 써서 번들의 `.build`와 겹치지 않는다. 둘은 같은 빌드 폴더를 쓰므로 차례로 돈다. 단계마다 걸린 시간을 출력한다.
- CI는 Homebrew 자동 업데이트를 끄고 SwiftLint·Periphery를 설치한다.

### 하지 않는 것

- **swift test와 다른 단계를 겹치지 않는다.** 앱 테스트에는 시간 제한을 확인하는 테스트(작업 프로세스가 1초 안에 끝나는지)가 있다. 스크립트 테스트가 첫 실행 검사를 줄 세우면 이 테스트가 만든 실행 파일도 그 줄에서 기다려, 결과가 부하에 따라 달라진다.
- Periphery 인덱스를 평소 빌드(`.build`)와 합치지 않는다(0080 유지). 대신 다른 단계와 동시에 돈다.
- CI 빌드 캐시(swift-syntax)는 이번에 넣지 않는다. 툴체인이 바뀔 때 캐시를 맞게 버리는지 로컬에서 확인할 수 없다.

## 검증

같은 Mac(10코어)에서 `KEYHUE_REQUIRE_SWIFT_LINT=1 scripts/verify.sh`를 쟀다. 두 경우 모두 `SettingsStore.swift`가 바뀐 상태라 다시 컴파일했다.

| | 이전 | 이후 |
| --- | --- | --- |
| 전체 | 182초 | 52초 (소스 변경이 없으면 42초) |
| 스크립트 테스트 142개 | 105초 | 21~26초 (하나씩 돌리면 60초) |
| 번들(바뀐 소스 없음) | 11초 | 3.5초 |
| 앱 테스트 317개 | 19초 | 10초 |

- 스크립트 142개, Swift(Core 645·App 317·IMK 227), code-check, 사이트 테스트 모두 통과했다.
- 저장하는 키 수를 세는 테스트를 더했다: 저장소를 만들 때 쓰지 않고, 바뀐 키 하나만 쓰고, 기본값으로 돌아가면 그 키만 지운다.
- 하나씩 실행(`KEYHUE_TEST_JOBS=1`)도 통과한다.
