# 0058. 외부 모드 요청은 대기 고침을 취소하고 기본 입력은 실제 편집기로 검사한다

상태: Accepted (전용 클라이언트 전환·TextEdit 입력 메뉴 경로 검증, 외부 전환 조합 보존은 0059로 보완)

날짜: 2026-10-03

## 배경

[ADR 0057](0057-automatic-correction-observation-and-input-priority.md)의 관찰은 실제 TIS 모드를 확인하지만, 사용자가 고침 대기 중 KeyHue 한글 모드를 선택하면 `setValue` callback이 TIS 갱신보다 먼저 도착할 수 있었다. 이전 영문 snapshot만 보고 관찰을 계속하면 사용자 모드 선택 뒤 단어도 고치게 됐다. 전용 Cocoa 클라이언트 결과만으로 일반 편집기 호환성을 판단할 수도 없다.

## 결정

- 고침 코어는 텍스트 확인 이후의 모드 대기 단계에서만 현재 작업의 예상 모드를 노출한다. 컨트롤러는 TIS 동기화 전에 요청 callback을 고침 어댑터에 전달한다. 대기 중인 자기 요청과 같은 모드 callback만 보존하고 나머지는 후보·관찰·되돌리기 이력을 무효화한다. 이전 TIS 값으로 요청의 출처를 추정하지 않는다.
- 이미 보낸 자기 요청과 같은 모드에 대한 수동 요청은 callback 인자만으로 구분할 수 없다. 모든 외부 모드 왕복이나 늦은 callback의 출처를 식별한다는 계약으로 확대하지 않는다. 실제 모드·클라이언트·범위 확인을 계속 요구하며 일반 앱 고침은 허용하지 않는다.
- 전용 Cocoa 검사에는 실제 두 `NSTextView` 사이 이동, 대기 중 필드 이동, 고침 후 필드 왕복과 Backspace, 대기 중 ABC·KeyHue 한글 직접 선택을 추가한다. 직접 `keyDown`을 호출하는 검사는 필드 활성화가 전달될 차례를 준 뒤 새 필드의 키를 보낸다. 이동 직후 같은 실행 차례에 호출한 키가 이전 context에 도착하는 것을 제품의 이력 유지 문제로 해석하지 않는다.
- 현재 선택/조합 위치의 `insertText`는 SDK 계약에 따라 replacement range의 location·length 모두 `NSNotFound`를 사용한다. 이것만으로 일반 앱의 전환 문제가 해결됐다고 판단하지 않는다.
- 일반 앱의 첫 대상은 TextEdit의 새 `.txt`·`.rtf` 문서다. Launch Services로 테스트 파일만 열고, 각 키 직전에 전면 앱 PID와 고유한 `AXFocusedWindow` 제목을 확인한다. Swift helper가 HID 경로에 키를 보내고 AppleScript는 해당 문서의 결과만 읽는다. `System Events key code` 결과만으로 실제 IMK 키 처리를 검증하지 않는다.
- 기본 검사는 실제 입력 메뉴로 ABC·KeyHue 두 모드를 선택한다. 별도 worker의 TIS 선택은 `KEYHUE_TEST_TEXTEDIT_MODE_SWITCH=worker`로 구분한다. 두 경로의 결과를 합쳐 앱 전체가 지원된다고 판단하지 않는다. 문서로 돌아오면 내용 보존을 먼저 검사하고 커서를 끝에 명시적으로 둔다. 마지막 글자가 보인다는 사실만으로 marked text 종료를 추정하지 않는다.
- runner는 입력 소스 설정을 편집하지 않는다. KeyHue 유틸리티를 잠시 종료하고 원래 선택·유틸리티 실행 상태를 복원하며 전후 KeyHue configured IDs를 비교한다. 생성한 문서만 저장 없이 닫는다. 자료는 `.artifacts/input-method-textedit/`에 남긴다. 문서별·창 왕복 검사는 120초, 두 문서 전체는 300초 watchdog을 사용하며 일반 CI에 포함하지 않는다.

## 검증과 한계

전용 Cocoa 전체 검사는 `.artifacts/input-method-e2e/20261003-164621/`에서 통과했다. 필드 이동 취소·되돌리기 이력 폐기와 두 외부 소스 선택, 기존 자동 고침·되돌리기·빠른 다음 키, 실제 서비스 업데이트·반복 설치를 확인했다. 자기 모드 요청이 시작되기 전에는 예상 모드가 없고 요청 callback 동안만 해당 모드를 예상하는 순수 회귀 테스트를 추가했다.

TextEdit 1.20에서는 실제 입력 메뉴 경로의 문서별 기본 입력과 창 왕복을 검증했다. 외부 worker 경로는 최종 설치본의 `.artifacts/input-method-textedit/20261003-172249/`에서 실패했다. 원래 문서에 보이던 `안`이 첫 영문 키에서 사라져 최종 `a `가 됐다. 키 직전 조회 source ID는 Latin이었다. 선택 조회 성공은 해당 문서 context의 조합 종료나 키 처리 준비 완료를 보장하지 않는다. 입력 메뉴 경로의 통과로 이 실패를 덮지 않으며, 유틸리티 연동·전환 단축키의 실제 문서 context 검사는 남긴다. 세부 근거는 [호환성 기록](../INPUT_METHOD_COMPATIBILITY.md)에 있다.

서비스 업데이트 직후 한 실행에서는 첫 글자가 조합되지 않았고 서버는 이후 기동 로그를 남겼다. 기동 후 재실행의 통과를 콜드 스타트 완료나 첫 키 준비 상태 보장의 근거로 사용하지 않는다. 후속 업데이트 검사는 포커스를 잃어 키 전송을 중단한 실행도 있었다. 실패 원인과 통과 근거를 구분한다.

전체 자동 검증 `.artifacts/verify/20261003-164927/` 통과: Swift 845개(Core 524·App 242·실험 Core 79), 스크립트 115개, 사이트 34개, lint, 앱·서비스 빌드/서명·self-check. 이후 변경된 GUI runner는 실제 실행과 별도 ShellCheck로 검사한다.

일반 앱의 IMK 범위 조회·자동 교체·모드 거부 복구 능력, Notes·웹·Electron·Terminal·보안 필드, 빠른 외부 모드 왕복, 응답하지 않는 RPC·성능 기준, 판정기·제품 고침 옵션은 남아 있다.

후속 [ADR 0059](0059-finalize-composition-on-input-source-change.md)는 위 외부 TIS 이탈 시의 조합 유실을 수정하고 같은 조건의 이전/수정 코드로 비교했다. 여기의 빌드 73 실패는 당시 기록이며, 진입·콜드 스타트와 일반 앱 호환성의 미완료 상태는 유지한다. 최신 runner는 같은 창의 미확정 조합 사례를 추가해 문서 종류별 180초·창 검사 120초·전체 300초 한도를 사용한다.
