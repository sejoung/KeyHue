# 0056. 확정 단어 교체와 되돌리기는 격리된 IMK 클라이언트에서 먼저 실험한다

상태: Accepted (격리된 Cocoa 고침·되돌리기 사례 통과, F13 관찰은 0057로 대체, 제품 1단계 완료는 별도 판정)  
날짜: 2026-10-03

## 배경

기본 한글·영문 입력은 현재 글자만 조합하고 앞 글자는 확정한다. Space에서 고치려면 클라이언트가 이미 확정한 단어를 문서 상대 범위로 교체해야 한다. 기존 언어 판정기의 정확도와 이 편집 경로의 안전성은 별개의 문제다. 실제 앱 결과는 [호환성 표](../INPUT_METHOD_COMPATIBILITY.md)에 기록한다.

## 결정

아래 F13 확인 장치는 초기 실험 계약이다. 이후 [ADR 0057](0057-automatic-correction-observation-and-input-priority.md)에서 이를 자동 관찰·기한·다음 입력 우선 처리로 대체했다. 식별·범위·실험 앱 제한은 유지한다.

- `CorrectionProbe`는 단계별 범위 교체 실험이다. 각 편집 요청은 동기적으로 보내고 이후 이벤트에서 결과를 확인한다. IMK 콜백은 기존처럼 메인 스레드에서만 처리하며 작업을 비동기로 재전송하지 않는다. 즉시 응답하는 가짜 클라이언트용 동기 경로도 순수 테스트에서 비교한다.
- IMK 어댑터는 전용 테스트 앱 ID `io.github.sejoung.keyhue.testclient.correction-probe`에만 허용한다. 일반 앱에는 고침 경로를 열지 않는다. `KEYHUE_TEST_CORRECTION_PROBE=1`로 만든 host 클라이언트와 명시적인 `dkssud` 사례만 사용한다. 판정 모델·제품 설정·지원 앱 허용 정책은 아직 연결하지 않는다.
- 한 글자 조합을 유지하면서 최대 64개의 영문 키와 시작 위치를 세션 메모리에 추적한다. 시작은 문서 맨 앞이나 공백/줄바꿈/Tab 뒤에서만 허용한다. IMK가 현재 영문 marked text와 정확히 같은 한 글자 선택을 보고하면 조합 끝 커서로 해석한다. 일반 선택 영역을 고침에 허용하는 규칙은 아니다. 숫자·기호·삭제·이동·단축키는 후보를 무효화한다.
- Space에서는 추적한 후보를 보관하고 기본 입력 경로가 남은 조합과 공백을 한 번에 확정한다. 다음 관찰에서 세션·클라이언트 ID, 영문 모드, 빈 선택 영역, 정확한 원문과 공백, 조합 종료를 확인한 뒤 단어와 공백 범위를 한 번의 `insertText(_:replacementRange:)`로 교체 요청한다.
- 실제 IMK에서는 편집 요청을 보낸 키 callback 안의 getter가 변경 전 조합 상태를 반환했다. **텍스트 교체 요청 → 다음 이벤트의 새 snapshot으로 텍스트·빈 선택 영역·조합 종료 확인 → `selectMode(_:)` 요청 → 다시 새 snapshot으로 모드 확인**의 단계로 나눈다. 원문과 결과 교체, 공백, 모드 전환을 원자적 처리로 가정하지 않는다.
- 전용 host 앱은 Space 뒤 F13 관찰 이벤트를 세 번, Backspace 뒤 두 번 보낸다. Space 뒤 첫 관찰은 원문과 공백을 확인하고 교체를 요청한다. 이어지는 두 관찰은 텍스트를 확인해 모드를 요청하고 모드 적용을 확인한다. 이벤트는 정확한 테스트 bundle ID에서만 소비되며 사용자 단축키가 아니다. 이 관찰 장치를 제품 자동 고침의 구현으로 표시하지 않는다. 일반 앱용 완료 알림/상태 재조회·기한·다음 키 경합 계약은 별도 설계한다.
- 범위는 UTF-16 기준이다. 반환 문자열 길이와 내용이 일치해야 한다. 읽는 것은 해당 단어/결과와 시작 경계 한 글자뿐이며 문서 전체 길이·내용은 요청하지 않는다. 클라이언트 ID나 범위를 확인할 수 없으면 고치지 않는다.
- 편집 소유권은 컨트롤러 세션 UUID와 IMK 클라이언트 객체의 정체성으로 비교한다. `uniqueClientIdentifierString()`은 SDK `HIToolbox.framework/Headers/IMKInputSession.h`에 `globallyUniqueString`의 wrapper로 명시돼 있으며 호출마다 같은 ID를 반환한다고 가정하지 않는다. 조합 범위를 보고한 클라이언트를 유지해 객체 주소 재사용도 막는다.
- 실제 Cocoa 클라이언트가 조합을 확정하면 앱 쪽은 길이 0을 반환해도 IMK 쪽 `markedRange()`는 `{NSNotFound, NSNotFound}`를 반환했다. 이 실험은 **동일한 유지 중인 클라이언트가 유효한 조합 범위를 보고한 이력이 있고, 자기 Space 확정 후 원문·빈 선택 영역을 확인할 수 있을 때** 이 값을 활성 조합 없음으로 해석한다. 새 클라이언트나 잘못된 범위는 교체를 거부한다. 임의의 앱에서 조회 실패와 비활성 조합을 구분하는 일반 지원 계약으로 확대하지 않는다.
- 사전 조건을 만족하지 않으면 기본 입력만 유지한다. 이미 확정한 Space는 교체 거부 시 다시 추가하지 않는다. 경계 확정 전 API를 대상으로 하는 순수 테스트에서는 거부된 교체 뒤 원문과 Space를 한 번 확정하는 경로도 검사한다. 교체가 됐으나 모드 요청이 반영되지 않았고 자기 결과 범위가 유지되면 원문과 공백 하나로 복구한다. 복구도 다음 snapshot으로 확인한다. 외부 편집·다른 세션·다른 모드가 개입하면 추측해서 덮어쓰지 않으며 실험을 실패로 기록한다.
- 즉시 Backspace는 확인된 고친 단어와 공백을 원문으로 교체한다. 다음 관찰에서 원문을 확인하고 영문 모드를 요청하며 이어서 영문 모드를 확인한다. 되돌리기 모드 요청 실패 시 검증된 자기 범위에 한해서 고친 결과로 복구한다. 다음 Space에서는 거부한 고침을 반복하지 않는다. 추가 입력·선택/커서 이동·마우스는 이력과 대기 작업을 폐기한다.
- 요청한 모드 변경의 활성화·확정·모드 callback은 대기 상태를 바로 지우지 않고 다음 관찰에서 동일 클라이언트·범위·원문·모드를 검증한다. 외부 모드/필드 변화와의 경쟁은 제품 단계 전에 별도 검사한다.
- 실제 검사에서는 유틸리티의 자동 연결이 ABC 대조군을 바꾸지 않도록 KeyHue 유틸리티를 잠시 종료한다. 입력기는 유지하며 모든 종료 경로에서 원래 소스를 복원하고 원래 실행 중이었다면 유틸리티를 다시 연다. 포커스가 없거나 검사 중 잃으면 실패로 종료한다. 입력 소스 목록이 달라지지 않았는지도 확인한다.
- 원문·후보·키·되돌리기 상태는 메모리에만 둔다. 전용 테스트 앱의 서버 로그에는 이벤트 분류·순번, 후보 길이, 선택/조합 범위 길이와 결과·모드·세션 ID를 기록한다. 글자·키 코드·문서 내용은 기록하지 않는다.

## 검증과 한계

순수 테스트는 고침/되돌리기/재고침 억제, 이모지·결합 문자 앞 UTF-16 범위, 교체 거부, 모드 요청 실패와 복구, 커서·선택·원문·세션 불일치, 외부 편집·재진입을 검사한다. 실제 IMK 교체와 모드 요청은 opt-in Cocoa 테스트에서 따로 수행한다.

2026-10-03 초기 실제 검사는 원문과 영문 모드로 남아 실패했다. 후속 계측 `.artifacts/input-method-e2e/20261003-120559/`에서는 6타 후보와 Space 전달이 정상임을 확인했다. 첫 관찰에서 매번 새로 생성한 클라이언트 ID를 비교해 중단했고, IMK 비활성 범위도 활성 조합으로 해석하고 있었다. 위 식별/범위 계약을 적용한 `.artifacts/input-method-e2e/20261003-120941/`에서는 기본 입력, 실제 범위 교체·공백·한글 모드, 즉시 원문·영문 복원, 재고침 억제, 이모지·결합 문자·가족 이모지 앞 UTF-16 범위, 이동 후 이력 무효화와 일반 영어/식별자 보존이 통과했다. 일반 키는 모두 `NSTextView.keyDown`으로 한 번 전달했고 F13 관찰만 명시적으로 input context에 전달했다. 이는 전용 클라이언트·명시적인 사례에 대한 결과다.

같은 callback에서 새 상태를 확인할 수 없다는 결과를 반영해 실험용 확인 이벤트를 분리했다. 새 snapshot에서도 원문·범위·모드가 확인되지 않으면 실패다. 관찰 이벤트 없이 사용자가 다음 키를 치거나 포커스를 바꾸는 경우, callback을 받지 못한 외부 모드 왕복, 앱 자체 편집과 대기 작업의 기한은 아직 제품 계약으로 해결하지 않았다. 입력기는 이 한계를 가진 테스트 앱에서만 실험한다.

이번 결정은 1단계 제품 자동 고침 구현 완료를 뜻하지 않는다. 기본 입력 호환성 표, 검증된 교체/되돌리기 결과, 실패 복구와 성능 기준, 판정 임계값, 설정 전달, 보안 필드와 지원 앱 정책이 갖춰져야 사용자 옵션을 추가한다.
