# 0055. 입력 소스는 사용자가 시스템 설정에서 추가한다

상태: Accepted  
날짜: 2026-10-03

## 배경

ADR 0052·0053은 설치 뒤 KeyHue가 부모 → 한글 → 영문 순서로 활성화하고, macOS 26에서는 `com.apple.inputsources`의 `AppleEnabledThirdPartyInputSources`에 자기 항목을 직접 보완했다. macOS 26.6.2에서 `/Applications`에 설치한 KeyHue로 확인한 결과:

- 두 모드에 대한 `TISEnableInputSource`는 0을 반환하지만 enabled 속성과 설정 목록이 바뀌지 않았다. 부모 활성화만 반영됐다.
- KeyHue의 설정 쓰기는 cfprefsd가 거부했다(`requires user-preference-write or file-write-data sandbox access`). 같은 시점에 KeyHue의 `kTCCServiceSystemPolicyAllFiles` 검사가 거부됐다. 전체 디스크 접근 권한이 있는 터미널 프로세스는 같은 쓰기에 성공했다. 개발 중 자동 보완이 통과한 것은 이 차이로 보인다.
- 거부된 값은 쓰기를 시도한 프로세스의 CFPreferences 캐시에 남아 같은 프로세스의 재조회 결과를 믿을 수 없었다.
- 거부를 실패로 처리하자 등록까지 롤백돼 사용자가 수동으로 추가할 수도 없었다.

자동 추가를 유지하려면 키보드 유틸리티에 전체 디스크 접근 권한을 요구해야 하고, OS 버전마다 문서화되지 않은 설정 형식과 캐시 동작에 의존해야 한다.

## 결정

- **KeyHue는 입력 소스 목록을 바꾸지 않는다.** 설치·업데이트는 ABC 전환, 서비스 복사·서명 검증, 정상 종료, `TISRegisterInputSource` 등록까지만 한다. 부모·모드 활성화(`TISEnableInputSource`)와 `com.apple.inputsources` 쓰기를 제거한다.
- 사용자가 시스템 설정 › 키보드 › 텍스트 입력 › 편집 › +에서 한국어의 KeyHue 두벌식과 영어의 KeyHue 영문을 추가한다. 설치 완료 안내는 실제 표시 이름과 언어 위치를 알려 준다. 두 모드가 이미 추가돼 있으면 바로 연동하고 한글 모드를 선택한다. 사용 요청은 저장되므로 나중에 추가해도 옵션을 다시 켤 필요가 없다.
- 준비 상태 판정(ADR 0054)은 유지한다. macOS 26의 설정 항목은 실제 상태를 알기 위해 **읽기만** 한다.
- 제거는 사용자가 두 모드를 먼저 지워야 진행한다. 모드가 남아 있으면 파일이 이미 없어도 시스템 설정에서 제거하라는 오류를 보여주고 아무것도 바꾸지 않는다. 그 뒤 서비스를 종료하고 검증된 설치본만 삭제한다. 사용자가 볼 수 없는 부모 항목은 제거를 막지 않는다.
- 등록 이후 macOS 26에서 KeyHue만 재시작하는 동작(ADR 0053)은 유지한다. 이미 등록된 같은 설치본의 재요청은 no-op이며 카탈로그에 등록이 빠졌을 때만 다시 등록한다.

ADR 0052의 활성화 순서·확인, ADR 0053의 자기 멤버십 보완·고아 항목 정리·제거 시 비활성화, ADR 0054의 "부모부터 순서대로 활성화" 항목을 이 결정으로 대체한다.

## 검증

- 가짜 런타임: 설치·업데이트가 등록만 하고 입력 소스를 바꾸지 않음, 사용자가 이미 추가한 모드면 준비 완료, 같은 설치본 재요청 no-op, 등록 누락 시 한 번만 재등록, 모드가 남은 제거 거부(파일 없음 포함), 부모 항목만 남은 경우 제거, 기존 설치 교체·롤백·외부 번들 거부.
- macOS 26 설정 항목 읽기: 자기 항목만 해석, 알 수 없는 형식 거부, 미지원 OS 미조회, 시스템 설정 변경 후 무효화.
- 실제 수명 주기(opt-in): 두 번 설치/제거해도 `AppleEnabledThirdPartyInputSources` 전체가 그대로인지 확인.
- 수동: 시스템 설정에서 두 모드를 추가한 뒤 재시작 없이 연동 시작, 영문 모드가 영어 아래에 보이는지 확인.
