# 0077. 방금 허용한 키 보내기 권한은 새 프로세스로 바로 쓴다

상태: Accepted (구현·자동 검증, 이 Mac에서 처음 설치 시나리오 5단계로 확인)

날짜: 2026-10-06

관련: [0049](0049-opt-in-input-method-integration.md), [0071](0071-route-through-the-leaving-mode-and-wait-for-modifier-release.md), [0073](0073-utility-posts-terminal-keys-for-the-input-method.md), [0075](0075-check-accessibility-only-for-features-that-use-it.md)

## 배경

처음 설치 시나리오(ADR 0074, 빌드 101, 2026-10-06 14:03~14:07)의 5단계에서 세 가지 문제가 나왔다. 5단계는 터미널에서 ⌥↩ → KeyHue 손쉬운 사용 요청 → 허용이다.

**1. 허용해도 고쳐지지 않았다.**

- 14:06:02에 KeyHue의 손쉬운 사용·이벤트 전송이 허용됐다(TCC auth 2).
- 그런데 실행 중인 KeyHue는 14:06:10·14:06:20·14:07:02에도 `noPermission`으로 답했다.
- macOS는 이벤트 전송 허용 여부를 프로세스마다 처음 답한 대로 기억한다. 그래서 다시 실행해야 적용된다. 입력 모니터링과 달리 다시 시작하라는 안내도 없다.

**2. 권한 없음이 앱 실패로 쌓였다.**

- 세 번째에 Ghostty를 "고치지 않는 앱"에 넣으라는 제안이 나왔고, 그 뒤로는 안내가 사라졌다(`notice=suggestExclusion`, 다음 `quiet`).
- 권한 안내 문구는 나왔지만, 한 번 제안한 뒤로는 조용해지는 규칙에 걸렸다.

**3. 라우팅이 스스로 꺼졌다.**

- 14:05:15에 ABC를 라우팅하며 떠나는 모드와 목표를 연달아 선택했다(ADR 0071).
- TIS가 바로 다음 순간 아직 첫 선택(한글)을 알려 주었고, 이를 "선택 실패 또는 즉시 덮어쓰기"로 판단해 사용자의 ABC 연결 옵션을 껐다.

## 결정

- **새 프로세스로 키 보내기:** 유틸리티가 이벤트 전송 권한이 없다고 판단하면, 같은 실행 파일의 짧은 작업 모드(`--keyhue-post-backspaces <pid> <개수>`)로 다시 해 본다.
  - 새 프로세스는 권한을 새로 확인하므로 방금 허용한 권한이 바로 적용된다. 허용됐으면 그 프로세스가 같은 Backspace를 보내고 0으로 끝난다. 아니면 77(EX_NOPERM)로 끝난다.
  - 그래도 권한이 없을 때만 macOS에 한 번 요청한다(ADR 0075).
  - 작업 모드는 보낸 뒤 0.1초 기다렸다가 끝난다. 처음 구현은 보내자마자 끝나서 마지막 키가 사라졌다(14:25, 입력기가 3개 중 2개만 받음, `asd` → `aㅁㄴㅇ`).
- **권한 없음은 앱 실패로 키우지 않는다:** `keyPermission`은 "고치지 못한 앱" 목록에 남긴다([허용…] 버튼을 위해). 하지만 몇 번이든 매번 허용 안내를 보이고, 제외 제안이나 조용히 하기로 넘어가지 않는다.
- **라우팅 성공 판단:** 라우팅은 목표 선택 호출이 성공하면 성공으로 본다. 직후 TIS가 아직 이전 소스를 알려도 실패로 보지 않는다. 시스템이 ABC로 되돌리는 덮어쓰기는 기존 보호(목표·떠나는 모드 직후 0.2초 안의 ABC)로 막는다.

## 결과

- 터미널에서 처음 ⌥↩ → 허용 → 바로 다시 ⌥↩로 고쳐진다. KeyHue를 다시 시작할 필요가 없다. 다시 시작하기 전까지는 고칠 때마다 작업 프로세스 하나(수십 ms)가 더 든다.
- 권한을 주기 전까지 터미널 고침을 몇 번 눌러도 허용할 곳이 계속 안내된다.
- 두 번 선택하는 라우팅이 TIS 지연 때문에 사용자의 옵션을 끄지 않는다.

## 검증

- 단위 테스트:
  - `WorkerCommandTests`: 작업 모드 인자, 개수 범위
  - `CorrectionFeedbackTests`: 권한 없음 5번도 제안 없이 안내
  - `InputMethodRoutingTests`: 선택 직후 TIS가 이전 소스를 알려도 라우팅 유지
- `scripts/verify.sh` 통과.
- 실제 확인(14:27~14:28):
  - KeyHue의 손쉬운 사용·이벤트 전송만 초기화한 뒤 다시 실행했다.
  - 터미널 ⌥↩가 `noPermission`이었다 → 허용 → 다시 시작하지 않고 ⌥↩ 두 번(영문 `dkssud`, 한글 모드 `asd`) 모두 "posted from a new process"였다.
  - 입력기가 Backspace를 모두 받았고(`keys delivered`), 사용자가 정확히 바뀐 것을 확인했다.
