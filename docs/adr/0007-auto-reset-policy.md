# 0007. ABC 자동 전환 정책: 기본 OFF, 지연 전환 + 1회 검증

- 상태: Accepted — 전환 대상(ABC)은 [0013](0013-per-input-source-colors.md)의 "기본 입력 소스"로 대체. 타이밍(지연 + 1회 검증)은 유효. 앱 전환 토글은 [0029](0029-switch-behavior-per-situation.md)의 선택지로 대체
- 날짜: 2026-09-29

## 맥락
앱 전환/ESC/텍스트 focus 해제 시 ABC로 되돌리는 기능은 사용자 상태를 자동으로 바꾼다. 명세는 "쉽게 끌 수 있어야 한다", "앱 시작 시 불필요한 권한을 요구하지 않는다"를 요구한다.

구현 중 실측에서 다음 경쟁 상태를 발견했다: 앱 활성화 알림 직후 바로 `TISSelectInputSource`를 호출하면, 시스템(TSM)이 새 앱에 **기존 Source를 다시 적용**하면서 10–30ms 사이 `English → Korean → English` 깜빡임이 생기고, 드물게는 전환이 덮어써져 Korean으로 남았다.

## 결정
- **기본값은 모두 OFF.** 메뉴 예시의 체크 표시는 켰을 때의 모습으로 보고, 첫 실행은 표시 기능만 동작한다.
- 판단은 `ResetPolicy`(순수 함수)가 한다.
  - 이미 English 계열이면 아무것도 하지 않는다(ABC가 아닌 U.S. 등도 유지).
  - ESC는 key code 53, autorepeat 제외.
  - 앱별 기억(Phase 2)이 켜져 있고 기록이 있으면 **기억한 Source 복원이 ABC 전환보다 우선**한다.
- 전환 대상(`ABCSourcePicker`): 활성화된 키보드 Source 중 `com.apple.keylayout.ABC` → `com.apple.keylayout.US` → 임의의 English keylayout → 임의의 English 순. 없으면 로그만 남기고 아무것도 하지 않는다.
- 실행 타이밍:
  - 앱 전환은 **0.1초 뒤** 전환한다(TSM 재적용이 끝난 후).
  - 실행 직전 현재 Source를 다시 확인해 이미 목표면 건너뛴다(대기 중 사용자가 직접 바꾼 경우).
  - 0.25초 뒤 한 번 검증하고, 덮어써졌다면 **1회만** 재시도한다.
  - 모두 1회성 `asyncAfter`이며 반복 타이머가 아니다.
- KeyHue 자신(메뉴, 권한 안내 alert)의 활성화는 앱 전환으로 취급하지 않는다.

## 결과
- 실측: Finder ↔ Chrome 6회 연속 전환에서 깜빡임 없이 모두 ABC로 전환되었다.
- 앱 전환 후 ABC 반영까지 약 0.1초 지연이 생긴다. 체감상 즉시에 가깝고, 깜빡임/실패보다 낫다고 판단했다.

## 검토한 대안
- **즉시 전환**: 깜빡임과 간헐적 실패.
- **알림 debounce로 깜빡임만 숨기기**: 모든 상태 표시가 늦어지고, 전환이 덮어써지는 문제는 해결하지 못한다.
