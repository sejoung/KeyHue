# 0047. 로컬 설치 명령에 IMK 실험 대상을 추가하고, 선택 상태 확인 후 교체·등록 요청한다

> 배포·버전·사용자 설치 흐름은 [ADR 0051](0051-single-app-distribution-and-managed-input-method.md)로 대체했다. 아래는 당시 결정이며 프로세스 경계·개인정보·단계별 검증 등 유지 범위는 0051을 따른다.

- 상태: Accepted (ADR 0046의 설치 부분을 갱신)
- 날짜: 2026-10-02

## 맥락
[ADR 0046](0046-shared-component-build-and-imk-spike.md)에서 빌드·검증·패키징을 공유하고 IMK 설치는 수동 실험으로 남겼다. 사용자는 개발 중 반복 테스트를 쉽게 할 수 있도록 기존 `install.sh`에 입력기 설치도 추가하자고 요청했다.

유틸리티는 종료 후 앱을 교체하고 다시 실행할 수 있다. IME는 선택 중인 조합과 시스템의 입력 소스 등록이 있어 같은 수명 주기를 그대로 적용할 수 없다. 자동 고침·기본 입력기 개발 전이라도 명시적인 개발 설치 명령은 상태 확인·실패 복구를 갖춰 제공할 수 있다.

## 결정
- `scripts/install.sh [utility | input-method-spike] [--no-build]`를 제공한다. 인자 없는 명령과 기존 `--no-build`는 계속 유틸리티용이다. 빌드 타깃·앱 이름·번들 ID는 `components.sh`의 정의를 따른다.
- IMK 실험의 기본 설치 위치는 `~/Library/Input Methods/KeyHueInputMethodSpike.app`이다. 사용자 입력기 폴더는 없으면 만든다. sudo·전역 설치·기본 입력 소스 설정은 하지 않는다.
- `scripts/input-method-install.swift`를 TIS 어댑터로 둔다. 선택된 입력 소스 ID·번들 ID로 실험 입력기가 사용 중인지 확인하고, 사용 중이거나 확인 불가능하면 중단한다. 자동으로 모드를 바꾸지 않고 조합을 끝낸 뒤 ABC로 전환하라고 안내한다.
- IME 상태를 시작 전·기존 프로세스 종료 전·파일 교체 전에 확인한다. 비활성 실험 프로세스에만 정확한 실행 파일 패턴으로 TERM을 보내고 짧게 기다린다. 종료되지 않으면 교체하지 않는다. SIGKILL·유틸리티 종료·임의의 다른 입력기 종료는 하지 않는다.
- 원본의 서명·ID·실행 파일을 검사한다. 임시 폴더에 복사·서명 검사를 끝낸 뒤 교체하며, 최종 서명 검사까지 이전 설치본을 보관한다. 교체/최종 검사 실패 시 이전 앱을 복원한다. 원본과 대상 경로가 겹치거나 IME 대상에 다른 앱이 있으면 거부한다.
- 설치 성공 후 `TISRegisterInputSource`로 입력 소스 카탈로그 등록을 요청한다. 입력 소스 활성화·선택은 사용자가 시스템 설정에서 한다. IMK 서버를 `open`으로 직접 실행하는 대신 시스템 설정을 연다.
- 등록 요청 실패는 파일 설치와 구분해 보고한다. 검증된 설치 파일은 유지하고 등록 미완료로 실패를 반환한다. 사용자는 시스템 설정 확인·재로그인 후 재시도할 수 있다. 등록 요청 성공을 실제 앱 입력 호환성 성공으로 해석하지 않는다.
- 설치 테스트는 임시 폴더의 서명된 가짜 앱과 가짜 TIS/프로세스/설정 도구를 쓴다. 실제 입력 소스를 등록·전환하지 않는다. 헬퍼는 전체 검증에서 Swift 6으로 컴파일한다.

## 결과
- 개발자는 `scripts/install.sh input-method-spike` 한 번으로 빌드·파일 설치·등록 요청·설정 열기를 수행할 수 있다. 반복 설치는 ABC로 전환 후 같은 명령을 사용한다.
- 유틸리티의 설치 편의와 IME의 별도 수명 주기를 한 진입점에서 제공한다. 각 구성 요소의 종료·등록·실행 정책은 구분한다.
- 입력 소스 선택과 파일 교체를 OS 전체의 원자적 트랜잭션으로 보장하는 것은 아니다. 설치 중 실험 입력기를 다시 선택하지 않으며, 등록 캐시·재로그인·실제 입력 호환성은 T단계에서 관찰한다.
- 명시적인 로컬 개발 설치이며 정식 업데이트 확인이나 자동 설치·공개 배포를 추가하지 않는다.

## 검증
- 설치 테스트: 유틸리티 기존 동작, IME 최초 설치·등록 요청·설정 열기, 비활성 프로세스 종료, 선택/재선택 중단, 종료 실패 중단, 다른 구성 요소 거부, 복사 실패 보존, 최종 검사 실패 복원, 등록 실패 보고, 원본/대상 중첩 거부.
- Apple SDK `HIToolbox.framework/Headers/TextInputSources.h`의 `TISRegisterInputSource` 계약에 따라 등록과 활성화/선택을 구분했다. API는 사용자/시스템의 Input Methods 폴더에 설치된 입력기 번들 등록을 지원한다.
- 현재 실제 입력 소스 조회는 확인했다. 실제 IME 파일 설치·등록·앱 호환성은 [실험 기록](../INPUT_METHOD_SPIKE.md)의 후속 검증 항목이다.
