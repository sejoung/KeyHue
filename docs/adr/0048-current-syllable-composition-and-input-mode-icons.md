# 0048. 한글은 마지막 글자만 조합하고 입력 소스 메뉴에는 투명한 가/A 아이콘을 쓴다

> 영문 단어 조합 비교와 표시 이름은 [ADR 0051](0051-single-app-distribution-and-managed-input-method.md)로 갱신했다. 한글 현재 음절·아이콘 결정은 유지한다.

- 상태: Accepted (ADR 0046의 한글 조합 실험 정책을 갱신)
- 날짜: 2026-10-02

## 맥락
[ADR 0046](0046-shared-component-build-and-imk-spike.md)의 IMK 기술 검증 번들은 편집 API 관찰을 위해 한글 단어 전체를 marked text로 유지했다. 사용자는 실제 모드 전환·입력 후 밑줄이 계속 이어지는 불편과 입력 소스 아이콘이 흰 네모로 보이는 문제를 보고했다.

메뉴 아이콘은 배경이 있는 AppIcon.icns를 두 모드에 공통으로 지정하고 있었다. 조합 표시와 입력 소스 구분은 기본 입력 경험에 해당하므로, 고침 기능을 추가하기 전에 수정한다.

## 결정
- 한글은 조합 결과의 마지막 글자만 marked text로 유지한다. 새 글자가 생기면 앞부분을 확정하고 마지막 글자에 필요한 원래 키만 남긴다. 기존 `Dubeolsik`의 조합/키 변환을 재사용하고 두벌식 표를 복제하지 않는다.
- 받침 이동·겹받침 분리 후의 앞부분을 `insertText`로 현재 조합 대신 확정한 다음, 새 마지막 글자를 `setMarkedText`로 전달한다. 어댑터의 기존 순차 액션 경로를 유지한다.
- 조합 중 Backspace는 현재 글자에서 키 한 타를 취소한다. 조합이 없어지면 다음 Backspace를 앱에 맡긴다. 이미 확정한 앞 글자를 입력기가 다시 조합하거나 삭제하지 않는다.
- 경계·모드 전환·클라이언트 확정 요청은 남은 조합만 한 번 확정한다. 영문 기본 즉시 확정과 단어 marked text 비교 옵션은 유지하고, 64타 상한은 영문 비교 옵션에 적용한다.
- 앱 아이콘은 기존 KeyHue 아이콘을 유지한다. 입력 소스 메뉴에는 배경이 투명한 `가`(한글)/`A`(영문) 이미지를 따로 지정한다. 16pt TIFF에 1x/2x 표현을 넣고 검은 template 이미지와 선택 상태용 흰 alternate 이미지를 생성한다.
- 후속 사용자 피드백에 따라 입력 소스 추가 화면의 식별도 구성한다. `tsInputMethodIconFileKey`에는 컬러 카멜레온 PNG를, 모드별 `tsInputModePaletteIconFileKey`에는 32pt의 `가`/`A` 배지를 지정한다. 설정용 배지는 배경이 있는 일반 이미지로 만들어 메뉴용 template 이미지와 구분하며 1x/2x 표현을 넣는다. 실제 설정 UI가 반영하는 모습은 재설치 후 확인한다.
- 입력기의 부모 소스 ID·`CFBundleName`·`CFBundleDisplayName`을 `InfoPlist.strings`로 한국어/영어 번역한다. 한국어 이름은 `KeyHue 실험 입력기`다. 기술 검증 타깃·실행 파일·번들/모드 ID는 그대로 유지한다.
- 공통 번들 빌드에서 메뉴 아이콘을 생성·복사하고 서명한다. 번들 검사는 모드별 파일 참조와 존재를 검사해 앱 아이콘으로 되돌아가거나 파일이 누락되는 회귀를 잡는다.

## 결과
- 긴 단어를 입력해도 조합 영역이 한 글자에 머문다. 밑줄의 실제 모양은 클라이언트가 정하므로 앱별로 확인한다.
- 삭제의 경계가 확정된 앞 글자와 조합 중인 글자로 나뉜다. 단어 전체를 다시 조합하는 예전 실험의 삭제 동작을 제공하지 않는다.
- 입력기 소유 조합을 단어 전체로 늘리지 않는다. 영문 자동 고침의 버퍼/교체 정책은 별도 실험이며 이번 수정으로 확정하지 않는다.
- 설치된 앱에는 재설치가 필요하다. 아이콘 캐시가 남으면 실제 파일과 TIS 등록 경로를 먼저 확인한다. 둘이 정상인데 메뉴 표시만 오래된 경우 현재 사용자의 `TextInputMenuAgent`만 재시작해 확인할 수 있다. 설치 스크립트가 시스템 프로세스를 자동 종료하지는 않는다. 계속 남으면 실험 모드 재추가·재로그인으로 확인한다. 시스템 캐시를 일괄 삭제하지 않는다.

## 검증
- 순수 세션 테스트: 마지막 글자 조합, 받침 이동, 겹받침 분리, 겹모음/Shift 키 취소, 경계·모드 전환의 단일 확정, 앱에 맡기는 삭제.
- 클라이언트 편집을 모사한 결정적 입력 표본으로 확정 문자열이 기존 일괄 조합과 일치하고 marked text가 한 글자인지 검사한다.
- 번들 테스트: 메뉴/설정 아이콘 누락과 잘못된 파일 참조, 입력기·모드 표시 이름 번역 누락을 거부한다.
- 실제 앱에서 밑줄·Backspace·선택 덮어쓰기, 입력 소스 메뉴의 라이트/다크·선택 상태·캐시 갱신을 별도로 확인한다. 자동 검사를 실제 IMK 호환성 확인으로 표시하지 않는다.
- 재설치 뒤 TIS는 새 TIFF를 가리키지만 메뉴바는 흰 네모를 유지한 환경에서, 입력 메뉴 표시 프로세스만 재시작한 뒤 사용자가 `가` 표시를 확인했다. 실행 중인 실험 입력기 PID는 유지됐다. 영문 아이콘·라이트/다크 전환까지 확인한 것으로 확대 해석하지 않는다.
- 메타데이터 근거: [Apple IMKServer 문서](https://developer.apple.com/documentation/inputmethodkit/imkserver/init%28name%3Abundleidentifier%3A%29?language=objc)의 입력기 아이콘 키와 로컬 Apple SDK `HIToolbox.framework/Headers/TextServices.h`의 메뉴/alternate 아이콘 키 계약을 따른다.
