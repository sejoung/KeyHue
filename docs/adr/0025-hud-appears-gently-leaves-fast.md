# 0025. HUD는 부드럽게 나타나고 바로 사라지며, 타이핑하면 즉시 숨는다

- 상태: Accepted (ADR 0024의 표시 타이밍을 대체, 나타나는 방식과 유지 시간은 0032로 갱신)
- 날짜: 2026-09-29

## 맥락
ADR 0024에서 HUD를 "즉시 나타남 → 0.35초 → 0.12초 페이드 아웃"으로 줄였다. 그래도 사용자는 이렇게 말했다.

> 나타나는 것은 천천히 나와도 사라지는 것은 빠르게 사라지면 좋겠다. 보고 변경되었다고 치면 딜레이가 걸리는 느낌이다.

HUD는 입력을 막지 않지만(클릭·포커스를 받지 않는 패널), **확인하고 타이핑을 시작했는데 화면에 남아 있으면** 반응이 느린 것처럼 느껴진다. 나타나는 쪽은 알아채기만 하면 되므로 부드러워도 된다.

## 결정
- 타이밍을 뒤집는다: **0.15초 페이드 인(easeOut) → 0.3초 유지 → 0.05초 페이드 아웃.**
- 떠 있는 동안 다시 전환되면 페이드 인 없이 색만 바꾸고 유지 시간을 다시 센다.
- 늦게 끝난 페이드 아웃이 새로 띄운 HUD를 숨기지 않도록, 표시마다 번호(generation)를 매겨 확인한다.
- **타이핑하면 즉시 숨긴다**(`hideNow()`).
  - ESC 전환용 listen-only 키 감지(ADR 0008)가 켜져 있을 때 모든 keyDown에서 호출한다.
  - 어떤 키인지는 보지 않는다. "입력 내용을 기록하지 않는다"는 원칙은 그대로다.
  - ESC 전환이 꺼져 있으면(입력 모니터링 권한 없음) 이 기능은 동작하지 않고, 위의 짧은 타이밍만 적용된다. 이 목적만으로 새 권한을 요구하지 않는다.
- 웹사이트 데모 HUD도 같은 타이밍(150ms 페이드 인, 450ms 뒤 50ms 페이드 아웃)과 "타이핑하면 숨김"을 따른다.

## 결과
- 통합 테스트
  - 페이드 아웃이 0.06초 이하이고 페이드 인보다 짧은지
  - 전체가 0.55초 이하인지
  - `hideNow()`로 즉시 숨는지
  - 숨긴 직후 다시 띄운 HUD가 이전 페이드 아웃에 가려지지 않는지
- 실측(화면의 HUD 창 존재 구간)은 docs/TESTING.md의 방식으로 확인한다.
