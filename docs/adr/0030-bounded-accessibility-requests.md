# 0030. 손쉬운 사용 요청은 짧게 끊고, 켜진 옵션에 필요한 것만 관찰한다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락
성능을 점검했다.
- 가만히 있을 때는 CPU 0.0%, 메모리 13 MB(최대 16 MB)였다.
- 위험은 손쉬운 사용(AX) 쪽에 있었다. AX 조회는 대상 앱과 동기 IPC로 주고받고, KeyHue는 이를 메인 스레드에서 한다.
  - 대상 앱이 멈춰 있으면(무지개 공) 응답이 올 때까지 KeyHue 메인 스레드가 막힌다. 그동안 색 막대·HUD·메뉴바 갱신과 ESC 감지(같은 메인 스레드)가 멈춘다.
  - 실측(직접 띄운 테스트 앱을 SIGSTOP): 시스템 기본값으로는 요청 한 번에 약 1.5초를 기다렸다. 앱에 붙을 때는 관찰자 등록과 속성 조회가 여러 번 이어져 합치면 수 초가 된다.
- 창 옵션만 켜도 "포커스 변경" 알림을 구독했고, 알림마다 텍스트 필드 판단용으로 역할·세부 역할·편집 가능 여부를 조회했다(3번). 이 조회는 텍스트 필드 옵션에만 필요하다. 포커스 변경 알림은 브라우저·Electron 앱에서 자주 온다.

## 결정
- **AX 요청 대기 시간을 0.25초로 줄인다.**
  - `AXUIElementSetMessagingTimeout`을 시스템 전체 요소에 걸어 이 프로세스의 기본값으로 만들고, 붙는 앱 요소에도 건다.
  - 시간을 넘기면 그 판단은 건너뛴다(텍스트 필드 아님, 창 모름으로 처리). 실측: 0.27초에 끊긴다.
- **켜진 옵션에 필요한 것만 관찰한다**(`AccessibilityUse`, Core).
  - 텍스트 필드 이탈: 포커스 변경 알림 구독, 붙을 때 포커스 요소 조회
  - 창 옵션(그대로 두기가 아닐 때): 메인 창 변경 알림 구독, 붙을 때 메인 창 조회
  - 필요한 것이 없으면 붙지 않는다. 옵션이 바뀌면 같은 앱이라도 다시 붙는다.
- 앱 전환 때 활성 화면을 찾는 창 목록 조회(`CGWindowListCopyWindowInfo`)는 그대로 둔다. 실측으로 창 23개에서 약 1.2 ms였다.

## 결과
- 멈춘 앱으로 전환해도 KeyHue가 막히는 시간이 요청당 약 1.5초에서 약 0.27초로 줄었다.
- 창 옵션만 켜면 포커스 변경 알림과 그에 따른 조회가 없어졌다.
- 테스트
  - Core: 옵션별 `AccessibilityUse`
  - 통합: 옵션별 구독 알림·초기 조회 속성, 필요한 것이 없으면 붙지 않음, 대기 시간 설정
  - 로컬 성능: `Tests/perf/ax-timeout.sh`. 테스트 앱을 정지시켜 기본값과 KeyHue 설정의 대기 시간을 비교하고, 0.5초를 넘으면 실패한다.
- 대상 앱이 잠깐 느린 것만으로도 0.25초를 넘으면 그 한 번의 판단을 놓칠 수 있다. 창 전환은 다음 알림에서 다시 기준을 잡고, 텍스트 필드는 실험적 기능이라 감수한다.
