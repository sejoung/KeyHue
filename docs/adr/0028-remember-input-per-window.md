# 0028. 창마다 입력 소스를 기억한다 (AX 창 동일성, 앱 실행 중에만)

- 상태: Accepted (어떻게 고르는지는 0029)
- 날짜: 2026-09-29

## 맥락
창 전환 시 초기화(ADR 0027)를 만든 뒤, "터미널 창 하나는 한글, 다른 창은 영문"처럼 **창마다** 입력 소스를 따로 쓰고 싶다는 요청이 있었다.
- 앱별 기억(ADR 0007)은 Bundle ID 단위라 같은 앱의 창을 구분하지 못한다.
- 창 전환 감지(ADR 0027)가 이미 활성 앱의 메인 창을 AX 요소로 알고 있다.
- 창 제목은 읽지 않는다는 원칙(개인정보)을 지킨다. 그러면 창을 가리킬 수 있는 것은 AX 창 요소의 동일성(CFEqual/CFHash)뿐이다. 이 동일성은 앱(또는 KeyHue)을 다시 실행하면 이어지지 않는다.

## 결정
- **저장하지 않는다.** `WindowInputMemory`(Core, 제네릭)는 메모리에만 있고 KeyHue가 끝나면 사라진다. 닫힌 창의 기록이 쌓이지 않도록 최근 100개 창만 둔다(LRU).
- 창은 `AXWindowID`(CFEqual로 비교, CFHash로 해시)로 구분하고, 코디네이터는 `AnyHashable`로 받아 AX에 의존하지 않는다.
- **기록 시점**
  - 입력 소스가 바뀔 때마다 지금 메인 창 몫으로 기록한다(KeyHue가 되살린 경우도 포함).
  - 창을 떠날 때, 앱을 떠날 때 그 순간의 입력 소스를 떠나는 창 몫으로 기록한다. 한 번도 바꾸지 않은 창도 돌아오면 그대로다.
  - 앱을 떠날 때의 창은 새 앱에 다시 붙기 전에, 돌아온 앱의 앞 창은 다시 붙은 뒤에 읽는다.
- 전환 시점과 검증은 앱·창 전환과 같다(0.1초 뒤 전환, 0.25초 뒤 한 번 검증).
- "기억한 입력 소스 지우기"는 앱별·창별 기억을 모두 지운다.
- 언제 기록하고 되살릴지(옵션 구조, 우선순위)는 ADR 0029에서 정한다.

## 결과
- 단위 테스트: 기록·덮어쓰기·LRU·지우기, 떠날 때 기록, 0.1초 대기, 창별 복원 흐름.
- 통합 테스트: `AXWindowID`의 해시가 CFEqual과 일치(사전 키).
- macOS의 "문서 입력 소스 자동 전환"과 함께 켜면 둘이 같은 일을 하므로 하나만 쓰기를 권한다. 알림 순서에 따라 새 창의 입력 소스가 떠난 창 몫으로 기록될 수 있다.
- **아직 실제 앱에서 확인하지 않은 것**: 터미널·iTerm·VS Code 등에서 창·탭별로 되살아나는지. 사용자가 권한을 허용한 뒤 확인한다(`docs/TESTING.md`).
