# 0019. 다운로드 페이지와 사용 설명서는 site/를 GitHub Pages로 배포하고, 스크린샷은 앱이 직접 렌더링한다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락
GitHub Releases 페이지는 일반 사용자가 "최신 버전 받기"와 "서명 없는 앱 여는 법"을 찾기 어렵다. 설정 항목이 늘어 사용 설명서도 필요하다. 설명서에는 화면 이미지가 있어야 하는데, 이 개발 환경에는 화면 기록 권한이 없어 실제 화면을 캡처할 수 없다. 또 UI가 바뀔 때마다 영어·한국어 이미지를 손으로 다시 찍는 방식은 유지되지 않는다.

## 결정
### 사이트
- `site/`의 정적 HTML/CSS/JS를 `.github/workflows/pages.yml`이 GitHub Pages로 배포한다(main push, `site/**` 변경 시). 저장소 설정 › Pages › Source를 "GitHub Actions"로 한 번 켜야 한다.
- 페이지: `index.html`(영어), `ko.html`(한국어), `manual.html`, `manual-ko.html`. 빌드 도구나 프레임워크 없이 정적 파일만 쓴다.
- **최신 버전 다운로드**
  - 기본 링크는 `releases/latest/download/KeyHue.zip`이다. 이를 위해 Release workflow가 버전 없는 고정 이름 `KeyHue.zip`을 함께 올린다.
  - JS가 GitHub API로 최신 릴리즈의 버전과 날짜를 표시하고 실제 asset 링크로 바꾼다. 릴리즈가 없으면(404) 소스 빌드 안내로 바꾸고, API가 실패하면 고정 링크를 그대로 둔다.
- **디자인**: 페이지가 KeyHue처럼 동작한다. 하단에 고정 색 막대가 있고, 데모 입력칸에 친 글자의 문자 체계(한글/가나/한자/키릴/라틴)와 Caps Lock에 따라 막대·메뉴바 카멜레온·HUD 색이 바뀐다. 브라우저는 macOS 입력 소스를 읽을 수 없으므로 이것이 짐작이라는 점을 페이지에 밝힌다.
  - 색은 앱의 기본 팔레트를 그대로 쓰고, 바탕은 아이콘의 남색과 차가운 흰색이다(다크 모드 지원).
  - 글꼴은 Bricolage Grotesque(제목)와 Pretendard(본문, 한글·라틴)다.
- 메뉴바 메뉴처럼 렌더링할 수 없는 화면은 이미지 대신 표로 설명한다.

### 스크린샷
- 앱에 `KeyHue --render-screenshots <dir>` 모드를 둔다(`DocScreenshots`).
  - 임시 UserDefaults와 예시 입력 소스(ABC, 한국어, 히라가나)로 **실제 SwiftUI 설정 창**을 화면 밖 창에서 렌더링해 PNG로 저장한다.
  - 사용자 설정과 화면 기록 권한과 무관하다.
- `scripts/screenshots.sh`가 이 모드와 아이콘 생성 스크립트를 실행해 `site/assets/`(설정 창 3탭 × en/ko, 웹 아이콘, favicon, 메뉴바 마스크)를 갱신한다. 생성된 이미지는 커밋한다(Pages 배포에 macOS 빌드가 필요 없도록).

## 결과
- 사용자는 한 페이지에서 최신 버전을 받고 첫 실행 허용 방법을 본다. 설명서 이미지는 명령 한 줄로 두 언어 모두 최신으로 유지된다.
- 스크린샷을 만들다가 설정 창 설명 문구가 한 줄로 잘리던 버그를 찾아 고쳤다(`fixedSize`).
- 화면 밖 창은 활성 창이 아니라서 토글이 회색(비활성 스타일)으로 그려진다. 켜짐/꺼짐 위치는 보이므로 받아들였다.
- 앱 바이너리에 문서용 렌더링 코드가 조금 포함된다. 인자를 줄 때만 동작하고, 입력·권한과 관계가 없다.
- 확인: headless Chrome으로 index/ko/manual-ko 페이지 렌더링을 확인했고, 다운로드 버튼이 실제 GitHub 최신 릴리즈(v0.1.1)를 읽는 것을 확인했다. Pages 배포 자체는 저장소 설정 후 첫 push에서 확인해야 한다.
