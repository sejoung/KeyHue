# 0072. 터미널 단어는 같은 세션의 재활성화에서 지우지 않고, 잠금 화면에서는 세션 복구를 하지 않는다

상태: Accepted (구현·자동 검증 통과. Ghostty 실제 검사 남음)

날짜: 2026-10-06

관련: [0062](0062-repair-input-method-session-with-previous-source-shortcut.md), [0068](0068-fix-words-with-a-shortcut.md), [0071](0071-route-through-the-leaving-mode-and-wait-for-modifier-release.md)

## 배경

사용자 보고: Claude Code(Ghostty 안)에서 ⌥↩가 고침 대신 줄바꿈으로만 들어간다. Claude Code가 ⌥를 먼저 가져가는 것 같다.

**키 순서:** Ghostty는 키를 입력기에 먼저 주고(`interpretKeyEvents`), 입력기가 처리하지 않은 키만 프로그램에 보낸다. Claude Code는 Ghostty가 보낸 바이트(`ESC CR`)만 받으므로 입력기보다 먼저 ⌥↩를 가져갈 수 없다. 입력기가 ⌥↩를 받으면 결과와 상관없이(고침·고칠 단어 없음·보안 입력) 로그를 남긴다. 따라서 줄바꿈이 됐다면 그 ⌥↩는 입력기를 거치지 않은 것이다. 해당 창의 입력기 세션이 닫혀 있었던 경우다(ADR 0061·0070).

**재현 (2026-10-06 11:28, 빌드 97):**

- 사용자가 이 Claude Code 입력창에서 한글·영문으로 각각 `dkssud` ⌥↩를 눌렀다. 두 경우 모두 고쳐졌고 줄바꿈은 없었다.
- 그 직전 첫 ⌥↩(11:28:50.835)는 "고칠 단어가 없습니다"였다. 0071에서 넣은 진단 로그는 `cleared=activation keys=0`였다.
- Ghostty는 사용자가 치는 동안 **같은 세션**을 비활성화했다가 1ms 안에 다시 활성화했다(11:28:48.821, 11:28:49.850). 유틸리티 로그에는 그 시각에 아무 일도 없었다. Ghostty 자체 동작이다.
- 입력기는 활성화·비활성화마다 터미널 단어를 비웠다(ADR 0068). 그래서 앞에서 친 글자가 사라졌다.

**잠금 화면:** 같은 날 11:12:48 화면을 잠그자 다음 순서로 일이 일어났다.

- 자동 전환이 잠금 화면에 영문을 선택했다.
- 잠금 화면이 ABC로 되돌렸다.
- 세션 복구가 확인을 받지 못해 잠금 화면에서 ⌘Space를 두 번 눌렀다(11:12:49.183).
- 0071의 라우팅 제외 덕분에 라우팅 옵션은 꺼지지 않았다. 복구는 별도 경로라 이 제외의 영향을 받지 않았다.

## 결정

- **단어 유지:** 터미널 단어(`TypedWord`)와 바로 되돌리기 기록은 입력기 세션의 활성화·비활성화에서 지우지 않는다. 고침 어댑터는 세션(컨트롤러)마다 하나라서, 다시 활성화된 세션은 같은 터미널 화면이다. 단어는 다음 경우에만 비운다:
  - 클릭
  - Return·Tab·방향키, ⌘⌃⌥와 함께 누른 키
  - 고침 설정 변경
  - 보안 입력
  - 고치던 중 앞 앱·클라이언트가 바뀜
- **기다리는 고침:** 수정키 떼기를 기다리는 고침은 시도할 때마다 세션 활성·클라이언트·앞 앱을 확인한다(기존 동작). 그래서 재활성화만으로 취소하지 않는다.
- **잠금 화면 복구 없음:** 앞 앱이 로그인 창이면 세션 복구 대상으로 보지 않는다(`SystemSessionRepair.currentContext`가 nil). 잠금 화면에서 키를 보내지 않는다.

## 결과

- 터미널에서 친 단어가 Ghostty의 세션 재활성화로 사라지지 않는다.
- 앱을 바꿨다 돌아와도 그 터미널의 마지막 단어를 고칠 수 있다. 다른 앱에 있는 동안 프로그램이 입력 줄을 다시 그렸다면 지울 글자 수가 맞지 않을 수 있다. 셸과 Claude Code의 입력 줄은 출력으로 바뀌지 않으므로 받아들인다.
- ⌥↩는 Claude Code의 줄바꿈 키이기도 하다. 입력기가 받지 못하면 줄바꿈이 된다. 입력기 세션이 닫히는 경우를 줄이는 것(0070·0071)이 근본 대응이다. 받지 못했을 때도 무해한 키를 원하면 고침 단축키를 Claude Code가 쓰지 않는 조합으로 바꾼다(설정 → 입력기 → 고침 단축키).

## 검증과 한계

- `scripts/verify.sh` 통과.
- IMK 어댑터의 활성화 처리는 단위 테스트 대상이 아니다. Ghostty 실제 검사(`KEYHUE_TEST_GHOSTTY_CORRECTION=1`)로 회귀를 확인한다.
- Ghostty가 같은 세션을 다시 활성화하는 조건은 확인하지 못했다. 검사 도구로 그 상황을 재현하지는 않는다.
- 진단 로그의 `cleared=`는 이제 `click`·`boundary key`·`settings`·`secure input`·`context` 중 하나다.
