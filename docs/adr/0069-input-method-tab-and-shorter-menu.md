# 0069. 입력기는 설정의 별도 탭에서 상태 한 줄과 할 일 하나로 보이고, 메뉴는 다시 자주 쓰는 것만 둔다

- 상태: Accepted (구현·단위 테스트·설정 창 렌더링 확인)
- 날짜: 2026-10-05
- 관련: [0038](0038-ux-cleanup.md), [0051](0051-single-app-distribution-and-managed-input-method.md), [0055](0055-users-add-input-sources-manually.md), [0064](0064-correction-modes-off-manual-automatic.md), [0068](0068-fix-words-with-a-shortcut.md)

## 맥락

입력기와 단어 고침을 더하면서 설정 창과 메뉴가 다시 길어졌다. 사용자는 "옵션이 너무 많고 번잡하다, 설명이 많고 스크롤이 있는지 모르겠다"고 했다. 실제 화면을 렌더링해 확인한 문제는 다음과 같다.

1. **자동 전환 탭에 성격이 다른 기능이 몰렸다.**
   - 들어 있던 것: 앱·창 전환, ESC, 텍스트 필드, 입력기 설치·연동, 단어 고침, 한/영 경고.
   - 입력기와 단어 고침은 "자동 전환"이 아니다.
   - 설명 단락이 10개쯤이었고, 입력기 절에만 4개였다.
2. **설명이 내부 동작을 풀어 썼다.** 예: "기억한 ABC는 KeyHue 영문으로 읽고…".
3. **입력기 조작이 다섯 개였다.** "입력기 사용" 토글, 설치 버튼, 모드 유지 토글, "연동 끄고 ABC로 전환", 제거. 토글을 켜는 것과 설치 버튼은 같은 동작이었다.
4. **메뉴에 입력기 항목 7개가 펼쳐져 있었다.** ADR 0038의 "자주 쓰는 것만"에서 벗어났다.
5. **스크롤이 보이지 않았다.** 창은 540×640으로 고정이고, macOS는 스크롤 막대를 스크롤할 때만 보인다. 절이 화면 끝에서 끊기면 아래에 더 있는지 알 수 없었다.
6. **"실험적"이 제목·헤더·설명에 반복됐다.**

## 결정

### 설정 창: 다섯 탭
- 탭은 일반 · 모양 · 입력 소스 · 자동 전환 · **입력기**다. 탭 막대 너비는 500으로 늘린다.
- 자동 전환 탭에는 앱·창 전환, ESC, 텍스트 필드만 남긴다. 한 화면에 들어간다.
- 입력기 탭은 위에서 아래로 "KeyHue 입력기 → 단어 고침 → 한국어 입력(한/영 경고)" 순서다.
  - 한/영 경고는 입력기 없이도 쓰는 기능이다. 그래도 "한/영을 잘못 친 경우"를 다루므로 단어 고침 옆에 둔다.

### 입력기: 상태 한 줄과 할 일 하나
- `InputMethodMenuState`가 설치·설정·입력 소스로부터 상태(`Phase`)와 다음에 할 일(`NextStep`)을 정한다. 설정 창과 메뉴가 같은 값을 쓴다.

| 상태 | 보이는 문구 | 할 일 |
|---|---|---|
| 이 KeyHue에 입력기가 없음 | 이 KeyHue에는 들어 있지 않음 | 없음 |
| 설치 안 됨(파일이 지워진 경우 포함) | 설치 안 됨 | 설치 및 사용… |
| 설치됨, 연동 꺼짐 | 설치됨 · 꺼짐 | 입력기 사용… |
| 새 버전 있음 | 새 버전 있음 | 업데이트 및 사용… |
| 두 모드가 아직 없음 | 시스템 설정에서 두 모드를 추가하세요 | 입력 소스 설정 열기 |
| 사용 중 | 사용 중 | 없음 |

- 드물게 쓰는 동작은 **관리** 메뉴에 둔다: 한/영 모드 유지, 연동 끄고 ABC로 전환, 입력기 제거.
  - 파일 없이 모드만 남았어도 제거할 수 있게 관리 메뉴를 보인다.
- "입력기 사용" 토글은 없앤다. 켜기는 설치와 같았고 끄기는 "연동 끄고 ABC로 전환"과 같았다(`setInputMethodEnabled` 제거).
- 작업 중에는 상태 대신 진행 표시를 보이고, 할 일과 관리 메뉴를 막는다.

### 설명은 한 줄, 자세한 내용은 ⓘ
- 절마다 한 줄 요약만 보인다. 기존의 긴 설명은 ⓘ 버튼의 팝오버로 옮긴다. 번역은 그대로 쓴다.
- "되돌린 고침 기록" 설명은 그 토글의 도움말로 옮긴다. 전에는 수동 모드에서도 보였다.
- 단어 고침을 쓸 수 없을 때(입력기 미사용)는 "KeyHue 입력기를 사용하는 동안 바꿀 수 있습니다"를 보인다.

### "실험적"은 배지 하나
- 제목 옆의 작은 배지로 한 번만 보인다. 토글 이름의 "(실험적)"은 뺀다.

### 스크롤
- 모든 탭의 Form에 `.scrollIndicators(.visible)`를 단다. 내용이 창보다 길면 스크롤 막대가 늘 보인다.
- 탭마다 창 높이를 바꾸는 방식은 하지 않았다. 탭을 나눈 뒤에는 기본 상태에서 모든 탭이 한 화면에 들어간다. 단어 고침의 목록을 펼치면 길어질 수 있는데, 그때는 스크롤 막대가 보인다.

### 메뉴: 다시 자주 쓰는 것만
- 남기는 것: 현재 입력, 상태 바 표시, 앱을 바꿀 때 ▸, 같은 앱에서 창을 바꿀 때 ▸(권한·감지 실패 안내), ESC, **KeyHue 입력기 ▸**, 설정…, 업데이트, KeyHue 정보, 종료.
- KeyHue 입력기 하위 메뉴에는 다음이 들어간다. 상위 항목의 체크는 사용 중(✓), 두 모드를 기다리는 중(–)을 보인다.
  - 상태 한 줄
  - 할 일
  - 한/영 모드 유지(권한 안내)
  - 연동 끄고 ABC로 전환
  - 입력기 제거
  - 입력기 설정…: 설정 창의 입력기 탭을 연다(`showInputMethodSettings`).
- 설정 창으로만 옮기는 것: 전환 HUD(모양), 텍스트 필드(자동 전환), 기본 입력 소스(입력 소스), 기억한 입력 소스 지우기(자동 전환), 로그 파일 보기(일반).
- `StatusMenuState`는 그대로 둔다. 메뉴에서 뺀 항목의 값(HUD, 텍스트 필드, 기억 지우기)은 이제 메뉴가 쓰지 않는다.

## 결과
- 자동 전환 탭은 한 화면에 들어간다. 입력기 탭은 입력기·단어 고침·경고를 한곳에서 보인다.
- 입력기 조작은 "할 일 하나 + 관리 메뉴"가 된다.
- 메뉴 항목은 입력기 7개, HUD, 텍스트 필드(권한 포함), 기본 입력 소스, 기억 지우기, 로그 파일만큼 줄어든다.
- 메뉴에서 빠진 HUD·텍스트 필드·기본 입력 소스를 메뉴에서 바꾸던 사용자는 설정 창을 열어야 한다.
- 고침 실패 알림의 안내 문구는 "설정 → 입력기"를 가리킨다.

## 검사
- `InputMethodMenuStateTests`: 설치·설정·입력 소스 조합마다 상태 하나와 할 일 하나, 파일이 지워진 경우, 관리 메뉴에 들어가는 동작, 작업 중 막힘, 상태·할 일 문구가 서로 다름.
- `SettingsMenuConsistencyTests`: 설정 창과 메뉴가 같은 상태 값을 쓴다(기존).
- `SettingsModelTests`: 두 모드를 기다리는 상태에서 할 일이 입력 소스 설정 열기이고, 두 모드를 추가하면 사용 중이 된다. 새 버전이 있으면 할 일이 업데이트이고 설치 동작을 부른다.
- 번역 키 검사(`LocalizationTests`): 새 키는 세 언어에 있고 쓰지 않는 키는 지웠다.
- 설정 창 렌더링(`scripts/screenshots.sh`)으로 다섯 탭을 영어·한국어로 확인했다.
