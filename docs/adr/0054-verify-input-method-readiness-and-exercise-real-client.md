# 0054. 입력기 준비 상태를 실제 카탈로그와 클라이언트로 검증한다

상태: Accepted (부모부터 순서대로 활성화하는 항목은 [0055](0055-users-add-input-sources-manually.md)로 대체)  
날짜: 2026-10-02

## 배경

설치 안내는 성공했지만 시스템 설정 목록과 실제 입력 결과가 맞지 않는 문제가 반복됐다. 앞선 수명 주기 시험은 두 mode가 enabled인지 확인했을 뿐, 설치 UI의 실제 목록과 편집 앱의 텍스트 입력까지 확인하지 않았다. mode-enabled 입력기에서 부모와 자식 mode는 별도 상태를 가진다. 부모가 비활성이면 mode도 실제로 사용할 수 없지만, 기존 검사는 두 mode의 enabled 표시만 보고 설치 완료로 오인했다.

설치 버튼을 반복했을 때 이미 현재 버전으로 설치된 서비스에도 등록 API를 다시 호출했다. macOS의 새 입력기 알림을 반복할 수 있는 경로였다.

## 결정

- 준비 완료는 fresh TIS 카탈로그에서 부모 입력기가 enabled이고, 한글·영문 mode가 각각 하나씩 enabled 및 selectable이며 실제 native enabled 목록에도 포함될 때만 인정한다. 설정 멤버십만 있거나 enabled만 표시된 상태는 pending이다.
- 부모부터 순서대로 활성화하고 각 API 호출 뒤 카탈로그를 다시 읽는다. 부모 또는 요청한 mode가 실제 활성화되지 않으면 그 상태를 기록하고 설치 성공 안내를 띄우지 않는다.
- 설치 파일과 앱 payload가 같고 catalog가 준비됐다면 설치/사용 재요청은 no-op이다. 재등록·재복사·재시작을 반복하지 않는다. catalog에서 부모 등록이 빠졌을 때만 등록을 다시 시도한다. 첫 설치와 업데이트가 성공했을 때만 KeyHue를 재시작한다.
- read-only System Settings 검사를 추가해 실제 입력 소스 편집 목록에서 두 mode가 보이는지 확인한다. 별도 Cocoa 텍스트 클라이언트로 IMK 입력·한영 왕복·Backspace·조합 범위를 검사한다. host 검사는 사용자 입력 소스와 임시 창에 영향을 주므로 기본 CI에서 실행하지 않는다. macOS 잠금이나 foreground가 없는 경우 테스트를 통과 처리하지 않는다.
- 작업 UUID와 파일·등록·활성화 결과, native·설정 catalog 차이, IMK 세션과 모드 callback을 기록한다. 글자와 키 코드는 기록하지 않는다. 짧은 진단 프로세스는 2초 안에 끝나야 하며 종료 코드와 JSON을 확인한다.

이 결정은 ADR 0053의 두 mode enabled 여부만으로 판정하던 완료 조건을 parent와 실제 selectable 상태 확인으로 대체한다. macOS 26 자기 멤버십 보완과 다른 입력기 항목 보존은 유지한다.

## 검증

- 준비 상태 독립 조합 128개, 누락·중복·외부 ID.
- 설치 업데이트·반복 재사용 no-op·활성화/제거 실패·중복 작업 잠금·외부 번들 및 링크 거부.
- 잘못된 JSON, 누락 파일, 비정상 종료, 응답 시간 초과인 진단 프로세스.
- 실제 설치 서비스 업데이트 후 두 mode 준비 상태와 재사용 no-op.
- System Settings 편집 목록에서 KeyHue 두 mode 표시 확인.
- Cocoa 클라이언트에서 ABC·시스템 두벌식·KeyHue 한글/영문, 왕복 전환, 여러 단어, 받침 이동, Backspace와 한 글자 marked range 검사. 시작 입력 소스 복원 확인.
