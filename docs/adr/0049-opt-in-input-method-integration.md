# 0049. 입력기 연동은 저장된 기본값을 보존하고, 두 모드 유지는 별도 실험 옵션으로 둔다

- 상태: Accepted (유틸리티 구현, 실제 전환·빠른 입력 호환성은 수동 검증 대기)
- 날짜: 2026-10-02
- 관련: [0037](0037-dont-undo-manual-switches.md), [0045](0045-experimental-input-method-component.md), [0047](0047-component-aware-local-install.md)

## 맥락

실험 입력기는 영문과 두벌식 모드를 각각 macOS 입력 소스로 제공한다. 시스템 ABC도 남아 있어 ⌘Space 전환 순서에 끼어들 수 있고, 기존 KeyHue의 자동 기본값·앱/창 복원은 ABC를 선택할 수 있다. 사용자가 입력 소스 순서를 조정하거나 전환 키를 KeyHue에 알려 주는 방식은 반복 설정을 요구한다.

[Apple의 입력 소스 설정 설명](https://support.apple.com/en-tj/guide/mac-help/mchl84525d76/mac)에서 Caps Lock은 마지막 Latin 소스와 비Latin 소스 사이의 전환이고, 문서별 입력 소스 복원은 별도 설정이다. 모든 경로를 동일한 키 조합으로 간주하지 않는다. 시스템 단축키·입력 소스 목록을 수정하지 않고 실제 TIS 선택 변경을 관찰한다.

## 결정

1. 유틸리티에 `integrateInputMethod`를 추가한다. 기본은 OFF다. 현재는 spike의 명시적인 Hangul/Latin ID 두 개만 인식하며, 두 모드가 모두 **활성·선택 가능**할 때 연동한다. 미래 정식 입력기는 ID 계약을 별도로 추가한다.
2. 연동 중 자동 기본값과 명시적인 ABC 기본값을 KeyHue 영문으로 해석한다. 저장된 `defaultSourceID`는 덮어쓰지 않는다. U.S., 독일어, 일본어 등 다른 명시적인 기본값을 유지한다. 앱·창 기억의 ABC도 읽는 시점에만 KeyHue 영문으로 해석한다. 실제 사용 이후에는 기존 기억 정책대로 실제 입력 소스 ID를 기록한다. (2026-10-03 보완) 시스템 두벌식도 같은 방식으로 짝을 이룬다. 연동 중에는 기억·기본값의 시스템 두벌식을 KeyHue 두벌식으로 읽는다. 연동이 꺼지거나 KeyHue 모드가 빠지면 기억된 KeyHue 두벌식·영문을 시스템 두벌식·ABC로 읽는다. 해당 시스템 소스가 없으면 기존 대체 규칙을 따른다. 다른 한국어 배열(세벌식 등)과 그 밖의 입력 소스는 바꾸지 않는다. 연동 전에 기억한 시스템 두벌식이 첫 실행에서 그대로 복원되던 문제를 막는다. 저장된 기본값이 KeyHue 모드인 경우도 같은 규칙으로 읽는다. KeyHue 모드 선택이 실패해 저장된 기본값으로 한 번 대체할 때는 KeyHue 모드를 후보에서 빼고, 시스템 후보가 없으면 바꾸지 않는다.
3. 앱 전환, 창 전환, ESC, 텍스트 필드 이탈에 같은 정책을 적용하고 메뉴·설정에도 실제 기본 대상 이름을 보여 준다. 실행 직전에 켜진 소스를 다시 확인한다. 한 모드라도 없어지면 기존 정책을 사용한다. KeyHue 모드의 TIS 선택 호출이 실패하면 저장된 기본 정책으로 한 번 대체하고, 실패한 모드로 재시도하지 않는다. IMK 프로세스 시작·클라이언트 입력 성공은 TIS 반환값만으로 보증하지 않는다.
4. 별도 `routeInputMethodPair`도 기본 OFF다. 연동이 켜져 있을 때만 작동하는 **실험 옵션**이다. KeyHue 한글 → ABC는 KeyHue 영문으로, KeyHue 영문 → ABC는 KeyHue 한글로 연결한다. 다른 언어·입력 소스에서 ABC로 오는 경우와 두 KeyHue 모드 사이의 직접 전환은 그대로 둔다. 시스템의 순환 목록 자체를 두 항목으로 바꾸지는 않는다.
5. ABC를 입력 메뉴에서 직접 선택해도 같은 규칙이 적용된다. 사용자가 이 점을 UI에서 알 수 있게 하고, 메뉴와 설정에 **연동 끄고 ABC로 전환**을 제공한다. 이 동작은 먼저 연동을 OFF로 저장하고 예약·검증 작업을 취소한 뒤 ABC를 직접 선택한다. 실패하면 연동은 꺼진 채로 유지하고 사용 가능한 시스템 소스를 선택하도록 알린다. 저장된 두 모드 유지 선호는 남기되, 연동 OFF 동안 작동하지 않는다.
6. 입력 소스 선택 알림과 목록 변경·새로 읽기를 구분한다. 초기 실행, 앱·창·필드·Space 변경, 모드 목록 변경, KeyHue 자동 전환은 새 기준을 세우고 대기 중인 연결을 취소한다. 실제 앞 앱과 앱 모니터의 PID가 일치할 때만 연결한다. 연결은 다음 main queue 차례에 현재 TIS·활성 모드를 다시 확인하고 한 번만 실행한다. 중복 알림은 무시한다.
7. 두 모드 유지에는 **입력 모니터링 권한**이 필요하다. 기존 listen-only 이벤트 탭으로 입력 시작 여부와 메뉴 클릭만 관찰한다. 어떤 전환 키인지 설정받거나 문자열을 읽거나 키를 차단·재전송하지 않는다. 타이핑이 시작되면 연결을 취소하고 현재 TIS로 기준을 갱신해 늦은 알림이 단어 중간에 모드를 바꾸지 않게 한다. 연동 중 기존 자동 전환 대기도 키 입력으로 취소한다. 권한이 없거나 탭이 동작하지 않으면 두 모드 연결은 실행하지 않는다. 기본 연동 정책은 이 권한 없이도 동작한다.
8. 연결 직후 200ms 내 상호작용 없이 ABC로 되돌아오면 시스템 덮어쓰기로 간주해 두 모드 유지 옵션만 OFF로 저장한다. 선택 실패도 동일하게 중단한다. 새 키/메뉴 상호작용 또는 보호 시간 경과 후의 정상 전환과 구분한다. 상태·성공 여부만 로그에 남기며 입력 문자는 남기지 않는다.

## 한계와 기존 결정의 적용

ADR 0037의 수동 선택 우선 원칙은 기본 연동과 실험 옵션 OFF에서 유지한다. 두 모드 유지 ON은 사용자가 명시적으로 선택한 제한적 예외이며, KeyHue 모드에서 ABC를 선택하는 전환만 다시 연결한다. 다른 언어 선택과 복구 명령을 덮어쓰지 않는다.

입력 소스 알림은 OS 선택 **이후**에 도착한다. 첫 키가 ABC에 들어간 뒤 연결을 취소할 수 있으므로, 매우 빠른 입력이 의도한 언어로 입력된다고 보증하지 않는다. 입력을 삭제·재전송해 이 차이를 숨기지 않는다. 알림·키 이벤트 순서가 어긋나는 환경에서 반복적인 잘못된 모드나 입력 유실·중복이 생기면 이 옵션을 끄고 기본 연동만 사용한다. 실제 앱 호환성과 최소 지원 OS 결과가 확보되기 전에는 정식 배포 지원 기능으로 표시하지 않는다.

입력기는 유틸리티가 없어도 독립적으로 작동하며 내부에서 전환 키를 가로채지 않는다. 입력기 고침·되돌리기 단계와 현재 별도 아티팩트·릴리즈 정책은 그대로 따른다.

## 검증

- 순수 테스트: 기본값 보존, 명시적인 다른 입력 소스, 앱·창 기억, ESC·필드·앱·창 공통 대상, 모드 삭제/비활성화, 실행 직전 변경, 실패 후 대체·재시도 상한, 복구·입력 시작의 예약 취소.
- 연결 테스트: 두 방향 ABC 전환, 직접 모드/다른 언어 유지, 중복·늦은 알림, 알림 전/후 빠른 키 입력, 새 선택·앱 문맥 변경, 권한 상실·모드 삭제, 즉시 덮어쓰기·선택 실패의 중단.
- UI/설정 테스트: 두 옵션의 독립 저장, 권한 안내 경로, 모드 이용 가능 여부, 저장된 기본값과 표시 대상의 차이, ABC 복구 액션 연결, EN/KO/JA 번역 일치.
- 자동 테스트는 가짜 입력 소스와 시간으로 실행하며 실제 시스템 선택을 바꾸지 않는다. ⌘Space/⌃Space/Caps Lock/Fn/입력 메뉴의 실제 결과, OS 문서 복원과의 경쟁, 첫 키·조합·복구는 [수동 안내](../../Resources/InputMethodSpike/README.md)의 표를 따른다.
