# 0053. 두 모드 가용성을 확인하고 macOS 26의 자기 입력 소스 항목을 복구한다

상태: Accepted (macOS 26 호환 처리, 실제 편집 앱 검증 대기)
날짜: 2026-10-02

## 배경과 실제 재현

0052 수정 이후 첫 설치·전환은 성공했지만 같은 KeyHue 실행 중 제거·재설치하면 다시 두 모드 추가 안내가 표시됐다. 제거 후에는 설치 파일과 새로운 TIS 카탈로그에서 서비스가 없어도 시스템 설정의 현재 입력 소스 목록에 한글 항목이 남았다.

macOS 26.6.2에서 부모·한글·영문을 각각 새 프로세스로 활성화/비활성화해도 API는 성공을 반환하면서 `com.apple.inputsources`의 `AppleEnabledThirdPartyInputSources`에 한글 항목을 남겼다. 부모 활성 속성이 false여도 두 모드는 selectable/enabled일 수 있었다. 기존 검증은 부모까지 enabled여야 준비 완료로 판단했고, Info.plist의 두 모드 기본 활성 값이 true여서 명시 설정이 없는 모드가 다시 활성으로 조회됐다.

임시 번들 실험에서 기본 활성 값을 false로 바꾸고 자신의 설정 항목만 추가/제거했을 때 새 프로세스의 두 모드는 모두 enabled=1 → enabled=0으로 바뀌었다. 다른 입력 소스 항목은 보존됐다. 같은 프로세스의 TIS 참조는 여전히 이전 상태를 반환했고 선택 API는 -50을 반환할 수 있었다. 단순 재조회·순서 변경·대기만으로 해결됐다고 판단하지 않는다.

## 결정

- 완료 조건은 **한글·영문 두 selectable 모드의 가용성**이다. 비선택 부모의 enabled 속성은 준비 완료 조건에서 제외한다. 부모 → 모드 활성화 시도는 유지한다.
- 두 모드의 `tsInputModeDefaultStateKey`는 false로 둔다. 사용을 명시적으로 선택할 때 활성화하고, 설정에서 제거한 모드는 기본 활성 값으로 되살리지 않는다. 번들 검사에서 이를 요구한다.
- 공식 TIS 등록·활성화·비활성화 API를 먼저 사용한다. 관찰한 **macOS 26에만** 별도 멤버십 설정을 보완한다. CFPreferences의 `com.apple.inputsources` 도메인, `AppleEnabledThirdPartyInputSources` 한 키만 다룬다. 이는 공개 API 위의 문서화되지 않은 설정 형식이며 모든 지원 OS의 계약으로 일반화하지 않는다.
- 자기 번들 ID와 알려진 부모/한글/영문 ID가 정확히 일치하는 항목만 추가/제거한다. 다른 입력 소스·키·도메인·순서를 보존한다. 알 수 없는 자기 모드/형식은 쓰기 전에 거부한다. 동기화·재조회 검증에 실패하면 이전 설정을 복구하고 작업을 실패로 처리한다. 전체 설정 파일 교체·전역 캐시 삭제·시스템 프로세스 종료는 하지 않는다.
- 활성 소스 조회는 이 OS에서 자신의 멤버십과 설치된 selectable 카탈로그를 함께 확인한다. 외부 입력 소스는 기존 TIS 활성 속성을 따른다. 입력 소스 알림이 오면 멤버십 캐시를 무효화해 직접 추가/삭제를 다시 읽는다. 키마다 디스크나 별도 프로세스를 조회하지 않는다.
- 등록·제거 후 기존 프로세스는 현재 선택도 오래된 값으로 읽을 수 있다. macOS 26에서 성공한 설치/제거 뒤 **KeyHue만 자동 재시작**한다. 설정을 저장하고 동일 실행 파일의 내부 대기 모드가 이전 KeyHue 종료 후 설치본을 다시 연다. 준비된 설치의 한글 선택은 재실행한 앱에서 수행한다. macOS 재로그인·시스템 프로세스 종료는 하지 않는다.
- 작업 전 ABC 복귀와 제거/교체의 선택 상태 확인은 같은 실행 파일의 짧은 내부 프로세스로 공개 TIS API를 수행·조회한다. 선택 대상은 실제 selectable 소스 ID로 검증하고, AppDelegate·일반 UI를 시작하거나 입력 버퍼를 공유하지 않는다. 내부 상태 조회는 새 프로세스의 실제 enabled 모드/현재 소스를 반환한다. 일반 입력·전환 경로는 재시작 후 네이티브 API를 사용하며 키마다 프로세스를 만들지 않는다. 별도 배포 앱/설치 스크립트는 없다.
- 제거는 자기 멤버십이 실제로 없어졌는지 확인한 후 파일을 삭제한다. 파일이 이미 없어도 남은 자기 설정 항목을 정리한다. 이 상태에서는 설정/메뉴의 제거 액션을 숨기지 않는다. 파일 삭제만 성공했다고 전체 제거 완료를 기록하지 않는다.

## 검증과 이전 결정

0052의 비공개 설정 직접 변경 금지 중 **관찰한 macOS 26 형식의 자기 입력 소스 항목 보완**만 이 결정으로 대체한다. 설치 트랜잭션·다른 입력 소스 보존·입력 내용 비수집·단일 앱 배포는 유지한다.

회귀 검사는 부모 비활성+두 모드 활성, 고아 한글 항목 정리, API 성공 후 비활성 상태, 다른 항목/추가 메타데이터 보존, 알 수 없는 형식/OS의 쓰기 거부, 쓰기/읽기 검증 실패 복구, 기본 활성 금지, 선택 후 실제 상태 확인을 포함한다. 실제 사용자 위치의 수명 주기 검사는 별도 명시 옵션으로만 실행한다. 일반 `verify.sh`·CI는 사용자 입력 소스를 바꾸지 않는다.

TextEdit/Notes/웹/Electron/Terminal의 실제 입력과 아주 빠른 모드 전환은 계속 수동 검증한다. macOS 27 이후에는 설정 형식을 검증하기 전 이 호환 처리를 켜지 않는다.
