# 입력기 실제 앱 호환성 기록

순수 로직 테스트와 실제 앱 검증을 구분한다. 전체 자동 검증이 통과해도 아래 앱 호환성은 별도로 확인한다. 실험 계약은 [ADR 0056](adr/0056-isolated-correction-and-undo-probe.md), [ADR 0057](adr/0057-automatic-correction-observation-and-input-priority.md), [ADR 0058](adr/0058-external-mode-callbacks-and-native-editor-acceptance.md), [ADR 0059](adr/0059-finalize-composition-on-input-source-change.md), 실행 절차는 [TESTING](TESTING.md#실험-입력기-연동-검증)을 따른다.

### 확인한 문제와 수정

기존 host 검사는 `handleEvent`가 거부하면 `keyDown`도 호출해 같은 이벤트가 다시 IMK에 전달될 수 있었다. 이전 `.artifacts/input-method-e2e/20261003-110817/`의 통과 기록은 이 제약을 가진 초기 증거다. 한 번 전달하도록 바꾼 `.artifacts/input-method-e2e/20261003-114448/`에서는 KeyHue 한글의 첫 Space가 빠졌다. 남은 조합과 공백을 하나의 `insertText`로 확정하고 Space를 소비하도록 수정했으며, 이후 기본 검사와 순수 회귀 테스트가 통과했다.

초기 고침 실행 `114949`·`115752`에서는 원문과 영문 모드로 남아 실패했다. `120559` 진단 실행에서 6타 추적과 Space 전달이 정상임을 확인했다. `uniqueClientIdentifierString()`을 안정된 클라이언트 ID로 사용해 첫 관찰 때 다르다고 판정하고 있었고, 확정 뒤 IMK가 반환하는 `{NSNotFound, NSNotFound}`를 활성 조합으로 해석하고 있었다. 세션 UUID와 유지 중인 클라이언트 객체로 소유권을 비교하고, 같은 클라이언트가 유효한 조합 범위를 보고한 이력이 있는 격리 실험에서만 비활성 범위를 해석하도록 수정했다. 원문·빈 선택·모드·UTF-16 범위 확인은 유지한다. `120941`에서 전체 acceptance가 통과했다. 상세 계약은 [ADR 0056](adr/0056-isolated-correction-and-undo-probe.md)을 따른다.

초기 ABC 선택 실패·포커스 상실·잠금 화면 중단도 있었다. 활성 창이 없거나 검사 중 포커스를 잃으면 키를 보내지 않고 실패로 종료한다. 실패 실행도 원래 입력 소스를 복원한다. 유틸리티 자동 연결의 간섭을 피하려고 runner가 유틸리티를 잠시 종료하지만, 초기 선택 실패 원인 전체를 이것으로 단정하지 않는다.

자동 관찰 도입 후 조회 중 자연 Backspace가 재진입하면서 이전 관찰과 새 되돌리기가 경합했다. 조회 전후·효과 직전 세대 검사와 중단 처리를 보완했다. 반복 burst 검사는 남은 marked text를 취소하는 테스트 초기화에서 정체돼, 정상 Space로 확정한 뒤 새 문서를 시작하도록 고쳤다. 초기 타임아웃의 actor 문맥 오류도 수정했고 별도 60초 watchdog과 단계별 로그를 추가했다. 이 정체를 입력기 RPC 교착으로 단정하지 않는다. 수정한 `134316` 실행에서 모든 사례가 통과했다.

TextEdit 한글 입력이 서버 callback에 도착하는 것도 로그에서 확인했다. 영문 결과 보존·Latin source ID 확인을 영문 한 글자 marked text나 모든 영문 키의 IMK callback 확인과 동일시하지 않는다. 문서 왕복 때 마지막 글자가 보이는 것만으로 조합 종료를 보장하지 않는다. 이 검사는 자동 완성·영문 밑줄·모든 기호/단축키·교체 능력의 완료 증거가 아니다. TextEdit 고침은 전용 앱 제한 때문에 실행되지 않는다.

위 빌드 73에서는 외부 worker 선택과 실제 메뉴 선택의 결과 차이가 미해결이었다. 아래 빌드 74의 후속 검사로 확인된 이탈 시 조합 유실을 수정했다. TIS 선택 조회 성공만으로 활성 문서의 입력 context가 준비됐다고 판단할 수 없다. 유틸리티 자동 연동·시스템 전환 단축키의 실제 문서 경로를 추가 확인해야 한다. `commitComposition` sender fallback, 다른 이벤트 인터페이스, Latin script 메타데이터 변경을 시험했지만 worker 실패를 해결하지 못해 최종 코드에는 포함하지 않았다. 원인을 해당 항목으로 단정하지 않는다.

초기 `System Events key code` 실행의 문자열 통과는 실제 IMK 전달을 충분히 확인하지 못한 근거라 위 결과에 합치지 않았다. 실제 메뉴 전체 검사 `170845`는 일반 텍스트 11개·RTF 일부가 통과한 뒤 120초 watchdog으로 종료됐다. 이후 종류별 검사로 분리했고 두 종류 전체 runner의 한도는 300초로 조정했다. 준비 전 AX 창 조회·메뉴 번역 차이·포커스 상실도 실패로 기록했다. 업데이트 직후 첫 조합 누락과 이후 서버 기동을 관찰한 실행도 있어 콜드 스타트 준비 보장은 남아 있다.
