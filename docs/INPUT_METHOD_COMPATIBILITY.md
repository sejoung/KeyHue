# 입력기 실제 앱 호환성 기록

순수 로직 테스트와 실제 앱 검증을 구분한다. 전체 자동 검증이 통과해도 아래 앱 호환성은 별도로 확인한다. 실험 계약은 [ADR 0056](adr/0056-isolated-correction-and-undo-probe.md)과 [ADR 0057](adr/0057-automatic-correction-observation-and-input-priority.md), 실행 절차는 [TESTING](TESTING.md#실험-입력기-연동-검증)을 따른다.

## 2026-10-03 실제 Cocoa 검사

환경: macOS 26.6.2 (25G83), arm64, Swift 6.4 / macOS 27 SDK. 최신 실제 검사 설치본은 0.2.5·빌드 72다. 아래 최신 근거는 `.artifacts/input-method-e2e/20261003-134316/`다. KeyHue 유틸리티를 잠시 종료하고 별도 `NSTextView` 창에 직접 작성한 테스트 문구만 전달했다. 서버 callback은 관찰한 실행에서 메인 스레드였다.

최신 검사는 기본·고침의 키를 모두 `NSTextView.keyDown`으로 한 번 전달하며 F13을 보내지 않는다. 입력기가 메인 큐에서 자동으로 편집·모드 적용을 확인한다. 전용 테스트 클라이언트의 명시적인 사례에 대한 결과다. 실제 범위 교체 거부는 검사했지만 실제 모드 거부 후 복구와 필드/포커스 이동·외부 모드 왕복은 아직 미확인이다. 150ms 관찰 기한은 동기 IMK RPC 자체의 시간 제한이나 제품 성능 보장이 아니다.

### 확인한 문제와 수정

기존 host 검사는 `handleEvent`가 거부하면 `keyDown`도 호출해 같은 이벤트가 다시 IMK에 전달될 수 있었다. 이전 `.artifacts/input-method-e2e/20261003-110817/`의 통과 기록은 이 제약을 가진 초기 증거다. 한 번 전달하도록 바꾼 `.artifacts/input-method-e2e/20261003-114448/`에서는 KeyHue 한글의 첫 Space가 빠졌다. 남은 조합과 공백을 하나의 `insertText`로 확정하고 Space를 소비하도록 수정했으며, 이후 기본 검사와 순수 회귀 테스트가 통과했다.

초기 고침 실행 `114949`·`115752`에서는 원문과 영문 모드로 남아 실패했다. `120559` 진단 실행에서 6타 추적과 Space 전달이 정상임을 확인했다. `uniqueClientIdentifierString()`을 안정된 클라이언트 ID로 사용해 첫 관찰 때 다르다고 판정하고 있었고, 확정 뒤 IMK가 반환하는 `{NSNotFound, NSNotFound}`를 활성 조합으로 해석하고 있었다. 세션 UUID와 유지 중인 클라이언트 객체로 소유권을 비교하고, 같은 클라이언트가 유효한 조합 범위를 보고한 이력이 있는 격리 실험에서만 비활성 범위를 해석하도록 수정했다. 원문·빈 선택·모드·UTF-16 범위 확인은 유지한다. `120941`에서 전체 acceptance가 통과했다. 상세 계약은 [ADR 0056](adr/0056-isolated-correction-and-undo-probe.md)을 따른다.

초기 ABC 선택 실패·포커스 상실·잠금 화면 중단도 있었다. 활성 창이 없거나 검사 중 포커스를 잃으면 키를 보내지 않고 실패로 종료한다. 실패 실행도 원래 입력 소스를 복원한다. 유틸리티 자동 연결의 간섭을 피하려고 runner가 유틸리티를 잠시 종료하지만, 초기 선택 실패 원인 전체를 이것으로 단정하지 않는다.

자동 관찰 도입 후 조회 중 자연 Backspace가 재진입하면서 이전 관찰과 새 되돌리기가 경합했다. 조회 전후·효과 직전 세대 검사와 중단 처리를 보완했다. 반복 burst 검사는 남은 marked text를 취소하는 테스트 초기화에서 정체돼, 정상 Space로 확정한 뒤 새 문서를 시작하도록 고쳤다. 초기 타임아웃의 actor 문맥 오류도 수정했고 별도 60초 watchdog과 단계별 로그를 추가했다. 이 정체를 입력기 RPC 교착으로 단정하지 않는다. 수정한 `134316` 실행에서 모든 사례가 통과했다.

## 다음 완료 조건

격리된 클라이언트의 후보 추적·교체·모드 전환·되돌리기·자동 확인·빠른 다음 입력과 외부 편집 취소 사례는 완료했다. 제품 옵션 전에 다음 항목이 남아 있다.

1. 실제 필드/포커스 이동·외부 모드 변경의 경합과 모드 거부 후 복구를 검사한다.
2. 앱별 기본 입력과 클라이언트 능력 판별, RPC 지연·실패 계약과 성능 기준을 확인한다.
3. 판정기 임계값, 설정 전달, 지원 앱·보안 필드 정책을 연결한 뒤 제품 고침 옵션을 제공한다.
